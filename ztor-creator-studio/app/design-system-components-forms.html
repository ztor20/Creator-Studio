First consumer: the bookyay gate's "Imported" rows — one bookyay event maps to exactly one ztor event, so an already-imported one still has to be listed (you search to find out whether you already created it; filtering it out would answer "Nothing matches that", which is the wrong message) but cannot be picked again.

4.11 Form section

🟠 organism

Purpose

用途

No-card section skeleton for create / wizard flows. Each section = title + grey sub + top divider + generous padding; fields inside reuse the Field system + Input / Select / Segmented atoms. Label and hint presentation is scoped to .form-section, while field rhythm stays on the base Field system, so other .field usages (Settings, e-shop) are untouched.

建立／wizard 流程的無卡片區段骨架。每段＝標題＋灰副標＋上分隔線＋寬鬆留白；段內欄位沿用 Field system 與 Input／Select／Segmented。label／描述呈現只作用在 .form-section 內，欄位節奏維持基礎 Field system，不影響其他地方的 .field（Settings、e-shop）。

4.205 Listing controls

🟠 organism

Purpose

用途

Whether fans can buy a thing, whether they can find it, and whether they can buy it right now are three separate questions. Spec §7.14 (D241) made them three independent switches — listed, shown in shop, on sale — and this component is the three rows they live in. Before D241 the same card was called "Listing settings" and one word ("上架") carried both "is it published" and "can you browse to it"; the two are now split.

「有沒有上架」「在網站上找不找得到」「能不能購買和結帳」是三件不同的事。規格 §7.14（D241）把它們定成三個互相獨立的開關——上架、顯示於商店、開賣——本元件就是那三列的骨架。D241 之前這張卡叫「上架設定」，「上架」一個詞同時背了「發布了沒」與「在網站上找不找得到」，現在拆開。

Show in shop sits outside the second layer (2026-09-04 · D247). .lctl__derived holds the schedule of listing — when it goes up, when it comes down. Whether people can find it is a different question that only arises once it is listed, so it gets its own bordered row (control-row, or control-group where hiding has to reveal a private link). It disappears together with the second layer when nothing is listed.

Two sections, two layers each (2026-09-04 · D245). The three switches are independent in the spec, but for a creator they are two decisions taken at two different moments: “does this appear in the shop, and when” is now; “when can people check out” comes after. So the block is split into Listing and Sale, and each section keeps exactly one main decision on the first layer with everything it implies tucked into .lctl__derived below it. On a create page “Don’t list” means draft — the second layer and the whole Sale section disappear. On a detail page the second layer stays put when unlisted: the private link is greyed out rather than removed, because it still exists, it just does not work right now.

It owns the rows, not the controls. Title + one line of explanation, where the control sits, when the schedule fields open, and the distance between the three rows — that is all. The controls themselves are reused as-is: Switch, Radio list (--collapsible), Field + Input, Link field. Which control the listing row uses is the page's call: create flows keep the collapsible three-way (don't list / list now / schedule — at creation time "whether" and "when" are one decision), detail pages use a switch (the thing already exists; all that is left is on or off).

它擁有列，不擁有控制。標題＋一行說明的排法、控制擺在哪、排程欄何時展開、三列之間的距離——就這些。控制本身原樣重用：Switch、Radio list（--collapsible）、Field＋Input、Link field。上架列用哪一種由頁面決定：建立頁沿用收合式三選一（不上架／立刻上架／定時上架——建立時「要不要」與「什麼時候」是同一個決定），細節頁改用開關（東西已經存在，只剩開著還是關著）。
