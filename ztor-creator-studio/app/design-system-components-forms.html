4.11 Form section

🟠 organism

Purpose

用途

No-card section skeleton for create / wizard flows. Each section = title + grey sub + top divider + generous padding; fields inside reuse the Field system + Input / Select / Segmented atoms. Label and hint presentation is scoped to .form-section, while field rhythm stays on the base Field system, so other .field usages (Settings, e-shop) are untouched.

建立／wizard 流程的無卡片區段骨架。每段＝標題＋灰副標＋上分隔線＋寬鬆留白；段內欄位沿用 Field system 與 Input／Select／Segmented。label／描述呈現只作用在 .form-section 內，欄位節奏維持基礎 Field system，不影響其他地方的 .field（Settings、e-shop）。

Why cards, not dividers (2026-09-23, Q125 revised — user feedback: “the divider isn’t clear enough”, “still too tight”)

為什麼是卡片、不是分隔線 （2026-09-23，Q125 修訂——使用者回饋：「用分隔線好像不是很明確」「間距還是太小」）

The first pass separated the blocks with 32px of space plus a 1px hairline. The site’s existing answer to “where does one block end” is not a line but a card — .settings-section is literally “cards spread apart by the container’s gap” — so the dialog follows the same one. Recipe: L2 nesting layer (--layer-2-surface + a --layer-2-line inset ring, no backdrop-filter — the card sits on the glass dialog, and a nested blur only samples its own parent), --radius-xl, padding --sp-20, and border: 0, which also retires the .form-section + .form-section hairline inside this scope. Padding is --sp-20 rather than the page-level --card-pad (24): it equals the card-to-card gap, so one ruler measures the whole stack, and a 620px dialog cannot spare 8 more px of width. Content-to-content between two cards therefore reads 20 + 20 + 20 = 60px.

上一輪是「32px 留白＋1px 淡分隔線」。站上對「一個區塊到哪裡結束」的既有答案不是線而是卡片——.settings-section 就是「把卡片用容器的 gap 排開」，彈窗照同一套走。配方：L2 巢狀層（--layer-2-surface 加一圈 --layer-2-line 內陰影，不挂 backdrop-filter——卡坐在玻璃彈窗上，巢狀層再模糊只取樣得到母層自己）、--radius-xl、內距 --sp-20，以及 border: 0——它同時把 .form-section + .form-section 那條髮絲線在這個作用域收掉。內距選 --sp-20 而不是頁面級的 --card-pad（24）：它與卡間 gap 同值，一把尺量到底；620px 的彈窗也不能再貢獻 8px 寬度。兩張卡的內容對內容因此是 20＋20＋20＝60px。

Its row separators and row padding stay — those are the internal structure of one formula, not a division into blocks. Consumers outside a card (create-bundle, bundle-detail, the bundle editor’s pricing block) are unaffected.
