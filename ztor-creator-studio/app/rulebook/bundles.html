組合包與票務商品

創作者把商品與活動門票打包成組合包來賣，賣出一套就從每個成員自己的量扣，組合包不另外進貨。至少含一張門票的組合包在活動裡叫「票務商品」，上架與開賣預設跟著活動走，並有自己的購買條件。

組合包的成員

組合包是一條販售管道（Channel，一條能賣東西的路），由商品成員與門票成員組成；組合包本身不在庫存池裡，賣出一套就從每個成員自己的量扣。成員怎麼組，見組合包的組成規則；哪些商品與門票不能加入，見可以加入的成員；含門票的組合包，見票務商品。

商品成員

  • 庫存池裡的商品
  • 每套用量＝每套放幾件，預設 1
  • 單一規格的商品沒得挑規格
  • 多規格的商品由粉絲下單時任選，沒貨的規格不能選
  • 賣出一套，從池扣「每套用量」件

門票成員

  • 某一場活動的門票，記三件事：
    • 所屬活動
    • 允許的門票，至少勾 1 項、可多勾
    • 張數 n，預設 1
  • 允許的門票可以同時有票種與獨立票；獨立票是不掛票種、只屬於一個場次的門票，見步驟 4 票種與票務
  • 粉絲購買時從允許的門票挑一項，拿到該項 n 張
  • 只勾一項，等於固定那一項
  • 門票也進庫存池：票種門票與獨立票各以自己的張數為一份庫存，單張購買與各組合包從同一份張數賣，見活動規則的門票的庫存
  • 賣出一套，從粉絲選到的那一項扣 n 張

門票在建立活動時隨活動產生，相當於一種商品；門票成員可以列多種門票讓粉絲任選一種，跟多規格商品讓粉絲選規格是同一套邏輯。

組合包的組成規則

組合包至少要有 1 個成員，成員只能是商品或門票。

  • 同一件商品 × N 件，或只含一種票 × n 張的純套票，都是合法的組合包
  • 成員彼此平等，沒有主體
  • 商品與門票可以放在同一個組合包
  • 組合包不能當另一個組合包的成員
  • 一個組合包只放一場活動的門票，不做跨活動混搭
  • 加入成員時，已加入一場活動的門票後，其他活動的門票不能選，畫面說明要換活動得先移除已加入的門票
  • 同一場活動在同一個組合包只有一筆門票成員
  • 門票的組法只有四種：
    • 多種票中任選 1 張
    • 多種票中任選 n 張
    • 任選 1 張再加商品
    • 任選 n 張再加商品
  • 同一套裡的 n 張票一律是同一項門票
  • 「每場各一組」的組合包，允許的門票只列該場次的獨立票
  • 一組通用所有場次時，允許清單可以含任一場次的獨立票；粉絲挑到獨立票，拿到的是它所屬場次的票
  • 同時內含兩種票、各自張數的組法（例如家庭套票）不提供

可以加入的成員

創作者從自己的商品與活動挑成員；下列商品與門票不能加入。

  • 已下架或已封存的商品不能加入
  • 數位影視類與數位音樂類只由項目發售，不能當成員，共 7 個數位次分類：
    • 電影
    • 短片
    • 影集
    • MV
    • 紀錄片
    • 數位單曲
    • 數位專輯
  • 實體音樂照常可以當成員
  • 活動已封存或已結束的門票不能加入
  • 草稿活動不列在建立組合包的候選清單
  • 草稿活動的票務商品，只能在該活動建立流程的「票務商品」步驟一起建，見從活動建立票務商品

票務商品

至少含一筆門票成員的組合包，在活動裡叫「票務商品（Ticket bundle）」；這是入口的叫法，物件就是組合包。

  • 同一份資料出現在兩個地方：電子商店的組合包清單，以及活動詳情的「票務商品」分頁
  • 票務商品跟一般組合包共用定價、庫存、三個開關、封存與下架連動
  • 票務商品的上架與開賣跟著活動，見票務商品的上架與開賣時間
  • 票務商品有自己的購買條件，見票務商品的購買條件
  • 活動開賣前移除場次、一併刪除該場的門票時，含這些門票的組合包保留：被刪的門票在粉絲端的組合包選項裡隱藏、不能選，在建立組合流程與組合商品細節頁顯示為停用，見移除場次與門票
  • 某一個門票成員允許的門票全部被刪時，組合包不能賣，狀態標「無法販售（Unavailable）」，取代原本的「即將開賣」或「販售中」；組合包保留，組合商品細節頁頁首與電子商店清單都用這個狀態
  • 電子商店清單把組合包與拍賣也叫「商品」
  • 本頁的「商品成員」只指庫存池裡那件有庫存的東西

依據：主規格 §7.14「庫存池與商品」「門票的庫存池與單售鎖定」、§7.12；5.1.5.4 §4 F2；5.1.5.9 §2.3；5.1.6.1 F7「移除場次」、F20、F22「這張票怎麼建」；D251、D254、D284、D292、D293、D294、D295、D296、D352、D380、D382、D391、D433、D465。

組合包與成員商品的設定關係

每件一般商品與每張活動門票，都像倉庫裡的一份庫存，帶著自己的價格、庫存、上架等屬性；組合包是把這些庫存拿出來組在一起。組合包的每一項屬性只有兩種來源：沿用單品，或組合包自己設；有幾項先沿用單品，創作者設定變更之後才變成組合包自己設。兩種關係各是什麼，見兩種關係；每一項設定屬於哪一種、各自怎麼設，見逐項對照。

但書：什麼時候不能改

上表寫「可以改」的組合包設定，遇到下列情況會被鎖住。

  • 賣出任一套之後：成員內容鎖定，只剩組合折扣、販售上限、購買條件與限購、停售，以及另設的上架、下架、開賣、停售時間能改，見售出後鎖定成員內容
  • 還沒賣出時：組合包上架中，或已下架但還有結帳中的訂單，成員內容不能改，見組合包修改成員的條件

組合包的庫存與鎖定套數

組合包沒有自己的庫存，賣出一套從各成員自己的量扣；創作者可以用鎖定套數把量留給組合包。此刻能賣幾套，見組合包可售量；把量留給組合包，見鎖定套數；設成限量時鎖定怎麼跟著走，見限量與鎖定；含活動門票的組合包要停賣，見把票務商品的庫存設為 0；單售還沒開賣時組合包怎麼扣量，見共用庫存的影響；用數字試，見試算分配。

  • 共用庫存、鎖定量、沒有被鎖定的庫存量、保留等通用規則，見電子商店販售流程的庫存規則

組合包可售量

組合包可售量是這個組合包此刻最多還能賣幾套。

  • 有鎖定套數時，可售量＝鎖定套數 N − 這個組合包保留中的套數
  • 不鎖定時，可售量＝每個成員能湊出的套數取最小，各成員的算法見最多能鎖幾套
  • 限量的組合包一定有鎖定，可售量＝限量 − 已售套數 − 保留中的套數，見限量與鎖定

鎖定套數

鎖定套數讓創作者把 N 套留給組合包，只有這個組合包能賣這 N 套。N 最多能填多少，見最多能鎖幾套；多規格商品與多項門票怎麼分，見逐規格或逐項門票分配。

  • 組合包的鎖定單位是「套」，只填一個鎖定套數 N
  • 不限量時自己填：空白或 0＝不鎖定，各成員與其他販售管道共用沒有被鎖定的庫存量
  • 限量時不能自己填，鎖定跟著限量走，見限量與鎖定
  • 鎖定套數是還沒賣掉的配額：粉絲下單時，這幾套記成這個組合包的保留、鎖定套數不變；付款成功後鎖定套數減掉這幾套，門票成員的鎖定跟著減 n 張；付款到期或失敗，保留的套數回到可賣
  • 各成員的鎖定量由 N 算出，不逐個填：
    • 單一規格商品：N × 每套用量，唯讀
    • 門票成員：N × n 張，從允許的門票扣
  • 被鎖的門票張數，單張門票與其他組合包都拿不到
  • 同一張門票的單售鎖定加各組合包鎖定的總和，不得大於「張數 − 已售 − 未鎖定格的保留」；單售門票也能鎖定，見步驟 4 的價格與數量
  • bookyay 匯入的門票也一樣，張數就是帶入的時段人數上限；所以同一場所有販售管道鎖的張數加起來，不會超過這場帶入的票數
  • bookyay 調低人數上限時，ztor 的門票張數同步調低，包含這張門票的組合包照上面的公式重算上限；已鎖定的量怎麼調，見頁尾尚待確認
  • 商品細節頁看到的「鎖給組合」是各組合包套數算出來的量，唯讀
  • 操作紀錄每次改動記一筆「鎖定套數 前 → 後」，明細列各成員算出來的量前 → 後
  • 只改分配也記一筆

最多能鎖幾套

  • N 的上限＝每個成員能湊出的套數取最小
  • 商品成員：沒有被鎖定的庫存量 ÷ 每套用量，無條件捨去
  • 門票成員：每個允許項目的剩餘張數 ÷ n、各自無條件捨去，再加總；剩餘張數＝張數 − 已售 − 單售鎖定 − 其他組合包已鎖的張數 − 未鎖定格的保留；獨立票的剩餘就是它自己的剩餘張數
  • 超過上限時表單擋下，並寫出是哪個成員壓住上限
  • 補貨後上限放寬，已鎖的 N 不會自動變

逐規格或逐項門票分配

  • 多規格商品可以選填逐規格分配：指定哪些選項組合各鎖幾件
  • 每格不得大於該選項組合當下沒有被鎖定的量，合計不得大於 N × 每套用量
  • 門票成員允許多項門票時，同樣可以選填逐項分配
  • 每格不得大於該項門票當下剩餘張數，合計不得大於 N × n
  • 允許少分配：沒指定的餘量只限定總數，不落在任何一個規格或門票上
  • 少分配的餘量從該成員未鎖定的整體量裡扣，單售與其他組合包都拿不到

限量與鎖定

組合包設成限量時，自動把成員庫存鎖給這個組合包，對外賣幾套與對內留幾套一起決定。

鎖定跟著限量走，不能另外設

調高限量多出的套數從成員沒有被鎖定的庫存量再鎖

  • 鎖定是對內預留，只算還沒賣掉的套數，粉絲看不到
  • 數位商品沒有庫存，不鎖，只受限量約束；實體商品與門票照樣鎖

  • T 恤鎖給這個組合包 30 件；數位單曲不鎖
  • 把限量調到 60 套：T 恤要再鎖 10 件，T 恤沒有被鎖定的庫存只剩 4 件時擋下，寫出還缺 6 套
  • 改回不限量：30 件全部退回 T 恤沒有被鎖定的庫存

  • 是營運動作，不必下架
  • 含 bookyay 門票、由創作者自建的組合包也可以設

活動是票務商品開關的上限

票務商品的上架、顯示、開賣只能在活動允許的範圍內收窄，不能比活動寬。

  • 活動未上架、已下架、已封存或已結束時，票務商品不能上架
  • 活動已結束或已封存後，先前隨活動下架的組合包也不能重新上架，見組合包重新上架時帶著成員上架
  • 活動隱藏時，含其門票的組合包在電子商店的清單與搜尋都找不到，組合包自己的顯示開關也不能切成顯示
  • 活動隱藏期間，粉絲仍可以經組合包自己的非公開連結購買，比照隱藏的組合包
  • 組合包原本的顯示值保留，活動切回顯示後，照組合包自己的開關
  • 開賣與停售的限制，見另設自己的時間
  • 完整的上限規則見活動設定是門票與票務商品的上限

  • 活動開賣中，票務商品可以自己先停售、隱藏或下架
  • 要讓票務商品完全停賣，用停售或下架
  • 隱藏的組合包只是不在商店陳列，開賣中仍可經非公開連結購買
  • 活動發布後，最後一組仍在販售的組合包也可以隱藏，見不擋的情形
  • 活動下架時，含其門票的上架中組合包一同下架，見組合包的下架連動與刪除
  • 活動重新上架時，組合包不會自動上架，重新上架前會彈窗問要不要同時上架，見組合包重新上架時帶著成員上架

成員下架或活動下架時，含該成員的上架中組合包會一起下架。組合包重新上架時，也會帶著已下架的成員一起上架。哪些下架會連動，見誰下架會帶著組合包一起下架；重新上架怎麼帶成員，見組合包重新上架時帶著成員上架；活動發布後哪些要先下架才能改，見組合包在活動發布後的修改；什麼時候能改成員，見組合包修改成員的條件；賣出後哪些內容不能改，見售出後鎖定成員內容；怎麼刪除，見刪除組合包。

單售商品下架、活動下架時，含該商品或該活動門票的上架中組合包一同下架。

  • 單售商品下架時，若還在任何上架中組合包裡，確認內容列出這些組合包名稱
  • 確認：這些組合包一同下架，單售下架成立
  • 取消：都不下架
  • 單售定時下架到期的自動下架同樣連動，並通知創作者
  • 創作者主動下架活動時，確認內容列出這些組合包
  • 活動因排程或結束自動轉為不可售時，組合包一併自動下架並通知創作者
  • 已下架或已封存的組合包不受影響
  • 成員資格不因下架而移除
  • 組合包因成員下架而一同下架時，組合商品細節頁要看得出原因與是哪一個成員

組合包重新上架時帶著成員上架

上架中的組合包，成員一律在上架中；組合包從已下架重新上架，會連帶重新上架這個組合包所有已下架的成員。

  • 所屬活動已結束或已封存時，含這場活動門票的組合包不能重新上架：按上架時擋下，並就地說明原因是活動已結束或已封存；跟活動結束時組合包自動下架一致
  • 連帶上架前先確認並列出這些成員，確認才執行
  • 成員中有已封存的：擋下並列出，提示創作者先把這些成員個別解除封存（回到已下架）
  • 成員解除封存、單售自己重新上架或解除封存，都不連動組合包
  • 組合包解除封存只影響自己：回到已下架，不連動任何成員
  • 曾因成員下架而被連動下架的組合包，解除封存後仍是已下架
  • 重新上架後是「上架＋顯示沿用＋未開賣」：組合包與被連帶的成員都要各自再設開賣

組合包修改成員的條件

還沒賣出任何一套的組合包，要同時符合兩條才能修改成員：組合包已下架，而且沒有結帳中的訂單。只含商品的組合包與票務商品都適用。

  • 修改成員包括：新增、移除、替換成員，改每套用量，門票成員改允許的門票與張數 n
  • 組合包已下架：下架只擋新訂單，不會取消已經在結帳中的訂單
  • 沒有結帳中的訂單：粉絲下單後到付款前，這筆訂單的量先保留給他（見保留）；付款計時結束前，訂單會付款成功，或逾時、付款失敗而釋放；這個組合包保留中的量歸零才能改成員
  • 只含商品的組合包，上架中照樣能改其他欄位，只有成員內容要先下架
  • 賣出任何一套之後成員內容鎖定，下架也不解鎖，見售出後鎖定成員內容
  • 上架中時，成員區唯讀並說明要先下架；已下架但還有結帳中的訂單時，成員區唯讀並提示「還有 N 筆訂單結帳中，結清後才能修改成員」

範例（數字皆為假設）：組合包是「A 票 ×1＋衣服 ×1」，上架中、還沒賣出，創作者想改成「B 票 ×1＋衣服 ×1」。

  • 先下架組合包；這時還有 2 筆訂單在結帳中，成員區仍不能改
  • 這 2 筆訂單付款或逾時之後，才能把 A 票換成 B 票，存好再自己上架
  • 如果其中 1 筆付款成功，這個組合包就算賣出 1 套，成員內容從此鎖定，要換內容就建新組

售出後鎖定成員內容

組合包賣出任何一套之後，成員內容就鎖定；所有組合包都適用，包含創作者在 ztor 自建的。

  • 鎖定的內容：成員清單、門票成員的允許的門票與張數 n、各成員數量
  • 還能改的只有：
    • 售價（組合折扣）
    • 販售上限
    • 購買條件與限購：只影響之後的購買，商品組合包與票務商品都可以改
    • 停售
    • 組合包另設的上架、下架、開賣、停售時間：只影響之後的購買，仍要落在活動允許的範圍內，見另設自己的時間；上架中也可以直接改
  • 票務商品上架中時，售價、販售上限、購買條件與限購要先下架才能改，見組合包在活動發布後的修改；停售隨時可做
  • 尚未售出時，門票成員的允許的門票與張數 n 可以在組合商品細節頁改，條件見組合包修改成員的條件
  • 要換內容就建新組、停售舊組
  • 頁面要說明鎖定的理由
  • 撤銷只能整組：撤銷一套，組內門票全部失效、商品一起取消；不能只撤銷其中一部分成員
  • 撤銷後，量退回這一套賣出時的那個鎖定，見撤銷後退回原本賣出的那個鎖定
  • 含門票的組合包，由 Admin 在訂單詳情撤銷這個組合包品項，見門票與組合包在哪裡撤銷
  • 含 bookyay 匯入活動門票的組合包同樣在 ztor 撤銷，撤銷的同時到 bookyay 撤銷這幾張門票；全部撤成功才算撤銷，任何一張沒撤成功整筆都不撤，見撤銷之後
  • 組合包裡有任何一件商品已領取，或任何一張門票已掃碼入場，就不能撤銷
  • 撤銷不寄 email 給買家

刪除組合包

零成交、且已下架或已封存的組合包可以刪除，見電子商店販售流程。

  • 刪除組合包不影響成員的狀態
  • 鎖給這個組合包的量，退回成員沒有被鎖定的庫存量，成員的總量不變
  • 刪除組合包不寫操作紀錄
  • 單售商品仍是任何組合包的成員時（不論組合包上架中、已下架或已封存），刪除商品會被擋下並列出這些組合包
  • 要先自己把商品從組合包移除，刪除商品不會自動把它從組合包移除
  • 草稿活動被刪除時，創作者自己建、含該活動門票的草稿組合包一起刪除
  • 刪除草稿活動的確認內容，列出會一起刪除的組合包名稱
  • 活動發布後不能被刪空或停空：停售、下架、封存或刪除最後一組仍在販售的組合包，若會讓活動也沒有還在的門票（隱藏的也算），就擋下並就地提示「至少要有 1 張門票或 1 組仍在販售的組合包」，見發布後擋下的動作
  • 活動的門票全部隱藏時，門票仍算還在，這些動作不擋
