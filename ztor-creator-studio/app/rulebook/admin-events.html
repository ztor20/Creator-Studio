活動匯入管理

Admin（平台營運）在這頁替 bookyay 自動匯入的每場活動對應創作者，並替還沒設定門票與票務商品的活動繼續設定；從匯入到結案的整條旅程，見活動用戶旅程圖。

1bookyay 活動的對應與補完

創作者活動管理是 Admin 處理 bookyay 活動的唯一入口：bookyay 選給 ztor 的活動自動匯入，匯入時不分創作者，Admin 逐場對應創作者後再補完設定。

待對應創作者→待設定→草稿→已發布
  • 活動票券的撤銷由 Admin 在 bookyay 後台執行，ztor 唯讀，見活動總覽的撤銷票券

已匯入活動清單

已匯入活動清單讓 Admin 看見 bookyay 匯入了哪些活動、各自對應給誰、設到哪一步。

  • 清單以活動為主，列出從 bookyay 匯入 ztor 的全部活動，不依創作者分組
  • 每筆至少顯示活動名稱、日期、場地與對應的創作者
  • 每筆狀態四選一，草稿與已發布跟創作者端看到的一致：
    • 待對應創作者：已匯入、還沒對應創作者
    • 待設定：已對應創作者、還沒存過
    • 草稿：已存、還沒發布
    • 已發布：完成設定並發布
  • 待對應創作者、以及還沒存過的待設定活動，創作者端看不到，也不計數
  • Admin 第一次儲存後，狀態轉為草稿，活動成為創作者的草稿，之後照一般草稿走
  • 已發布的活動不能改對應，也沒有任何操作

篩選與搜尋

  • 依狀態篩選清單
  • 可用活動名稱、創作者名稱或主辦方名稱搜尋
  • 從 Creator 詳情點「已匯入 M 場」進來時，只列已對應給這位創作者的活動

對應創作者

對應創作者決定一場 bookyay 活動屬於哪位創作者，是設定的第一步。

  • 每場匯入的活動由 Admin 搜尋 ztor 創作者後選定一位，一場活動對應一位創作者
  • 畫面顯示 bookyay 帶來的主辦方名稱，只當參考：唯讀，不帶入活動資料
  • 還沒對應創作者的活動不能進入設定，也就不能發布
  • 對應後，狀態轉為待設定；Admin 第一次儲存前，創作者端看不到這場活動
  • 找不到創作者時，Admin 先到 Creator 管理建立創作者，建好後再回來對應

解除對應

  • 待設定與草稿的活動，Admin 可以解除對應，活動回到待對應創作者，再重新對應給另一位創作者
  • 草稿的活動，解除對應時草稿一併刪除，Admin 要先在確認視窗確認草稿內容會清掉
  • 待設定的活動直接解除
  • 已發布的活動不能改對應
  • 創作者在活動清單刪除匯入活動的草稿，結果相同：活動回到待對應創作者，Admin 再重新對應

繼續設定

  • 「繼續設定」出現在待設定與草稿的活動
  • 按下後帶著這場的 bookyay 資料進建立活動流程，不經第一步的帶入詢問
  • 欄位怎麼帶、哪些鎖定，照從 bookyay 帶入活動
  • Admin 第一次儲存後，活動出現在創作者活動清單的草稿分頁，這筆狀態轉為草稿；活動發布後轉為已發布

自動匯入與更新檢查

這一區讓 Admin 知道活動怎麼來、清單有多新，必要時立刻再檢查一次 bookyay。

  • bookyay 選給 ztor 的活動自動匯入這頁，Admin 不需要另外執行匯入
  • 匯入當下，活動不屬於任何創作者，等 Admin 對應
  • 持續自動檢查 bookyay 有沒有更新，對象是整份匯入清單
  • 畫面顯示「最後檢查時間」，不論這次有沒有搬進新活動都會更新
  • Admin 可以按「重新檢查」，立刻再檢查一次 bookyay，完成後清單依結果重整
  • bookyay 端刪除或隱藏活動時（外部平台觸發），ztor 端的活動轉為下架、資料保留
  • bookyay 把活動改回草稿時，ztor 同步下架；bookyay 再次發布時，ztor 同步重新上架，先前一起下架的票務商品不會自動上架
  • 一場匯入的活動都沒有時，清單顯示空狀態，最後檢查時間與重新檢查仍然顯示
