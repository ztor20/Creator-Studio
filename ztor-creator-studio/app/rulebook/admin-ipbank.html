Admin IP Bank

Admin 在 Admin IP Bank 記錄每部影片（Film）的 IP 由哪些權利人（Owner）持有，以及每位權利人分到多少收入比例。分到的金額怎麼算，見IP Bank Reporting。

概述

  • 一筆資料是「一部影片的一個 IP 給一位權利人」
  • 同一部影片可以有好幾筆，每筆只連結一位權利人
  • Admin 不用先選定創作者就能進這頁
  • 這頁只管全平台影片的分潤分配，創作者自己的 IP、上架與授權在我的 IP

Admin 進 Admin IP Bank 後，從清單決定要建一筆新的、調整既有的，還是去看分潤數字。

清單

清單讓 Admin 檢視與維護每一筆「影片 × IP × 權利人」的分配。一列是一筆，欄位如下；每一列能做的事，見列操作。

欄位內容
影片（Film）這一筆屬於哪部影片，顯示名稱與辨識資訊
IP 名稱（IP title）權利人在這部影片持有的 IP
類型（Type）IP 類型，選項見建立 IP Entry 的 IP 資料
權利人（Owner）已有 Ztor 帳號的使用者，或受邀的 email
狀態（Status）已連結（Linked）或已邀請（Invited (Pending)），見權利人的連結狀態
分潤比例（Share）這位權利人在這部影片分到的收入比例，見分潤比例怎麼檢查

列操作

每一列的操作收在「⋯」選單裡，依權利人的連結狀態只提供一種。

功能或欄位出現條件與必填規則

存檔時重新檢查這部影片的分潤比例合計，見分潤比例怎麼檢查
已連結的資料不能移除

分潤比例怎麼檢查

同一部影片所有權利人的分潤比例加起來不能超過 100%，沒分出去的部分歸平台。

規則內容
單筆的範圍見建立 IP Entry 的分潤配置
同一部影片的合計不能超過 100%
已配置比例（Allocated share）這部影片已經分給權利人的比例合計，建立與編輯時都顯示
剩餘比例（Remaining share）這部影片還能分配的比例，建立與編輯時都顯示
平台剩餘（Platform remainder）沒有分配出去的比例歸平台
超過 100% 時不能存檔，畫面指出超出多少

範例（數字皆為假設）：影片 A 已有兩位權利人，各 30% 與 30%。

  • 已配置 60%，剩餘 40%，平台剩餘目前是 40%
  • 再加一位填 50%：合計 110%，不能存檔，畫面指出超出 10%
  • 改填 40%：合計 100%，可以存檔，平台剩餘變成 0%

依據：5.1.0.1 F3.2；5.1.0.1.1 F3；D129、D131。

權利人的連結狀態

權利人有兩種連結狀態，由建立時選了誰決定，Admin 不能手動改：已邀請 → 已連結。狀態用詞的全站定義見狀態語言。

狀態什麼時候進入Admin 能做分潤報表上
已邀請（Invited (Pending)）建立時填了還沒註冊的有效 email，存檔後進入，同時建立邀請移除應計金額照常累積
認領帳號前不能提款
已連結（Linked）建立時選了既有的 Ztor 帳號，存檔後進入
受邀的人接受邀請、認領帳號（claim）後，從已邀請自動轉入		編輯顯示已提款與可用金額
  • 怎麼找權利人、怎麼發出邀請，見建立 IP Entry 的權利人連結
  • 報表上各金額怎麼算、已邀請時怎麼顯示，見分潤金額怎麼算

依據：5.1.0.1 F3.1、F3.3；5.1.0.1.1 F2；主規格 §7.2、§7.3；D129、D131、D132。
