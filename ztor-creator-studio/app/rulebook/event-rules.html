活動規則

創作者與 Admin 照這頁的規則判斷一場活動走到哪個階段、什麼時候買得到、門票能賣多少、能做哪些動作，以及票務商品怎麼跟著變，其他活動頁提到這些規則時會連回這裡。從匯入或建立到結案的整條旅程，見活動用戶旅程圖。

活動的階段

一場活動從草稿單向走到結束，同時只落在一個階段。每個階段下創作者與 Admin 能做什麼，見各階段誰能做什麼；已下架、完售等標籤的各種樣子，見活動標籤與進度的各種樣子；一場活動算在哪個階段，見階段怎麼判定。

草稿→已排程→售票中→進行中→已結束 下架與封存不是階段，草稿以外的任何階段都可能下架，已下架的活動才能封存，見上架與下架、封存與解除封存

階段怎麼判定

  • 一場活動取已經走到最遠的那一個階段，例如活動當天現場仍在售票，算進行中
  • 已發布、等待定時上架的活動算已排程
  • 進行中與已結束的時間點，依活動所在地的時區判定（不是創作者或粉絲的時區）：
    • 有填開始時間：開始時間到了進入進行中；沒填開始時間：活動當日 00:00 進入進行中
    • 有填結束時間：結束時間到了進入已結束；沒填結束時間：活動日的次日 00:00 進入已結束
    • 只有單日活動可以不填；開跨日活動時開始與結束時間必填，見步驟 3 每一場的時間
  • 一場活動可以有多個場次，所有場次共用一份場地；每一站換場地的巡迴，改成每站各建一場活動，見步驟 3 場次

什麼時候買得到

單張門票與票務商品預設用活動的售票期間販售，也可以各自設時間。

  • 單張門票加了限時購買條件時，照限時購買的期間販售
  • 票務商品跟隨開賣時，就是活動的售票期間；另設時用另設的值，見組合包與票務商品
  • 活動的時間改了，跟隨中的票務商品立刻跟著改

活動設定是門票與票務商品的上限

建立活動時一起建立的單張門票與票務商品，上架、開賣、顯示都以活動的設定為上限，只能比活動窄，不能比活動寬。

設定活動怎麼限制單張門票與票務商品
上架活動未上架、已下架、已封存或已結束時，票務商品不能上架
活動下架時票務商品怎麼跟著變，見票務商品怎麼跟著活動變動
開賣單張門票的限時購買、票務商品的開賣與停售，都不能晚於活動停售
活動停售後就不能再買
單張門票的兩種限時折扣不在此限，期間在上架區間內即可，可以晚於活動停售；折扣只在這張門票可購買的時間內生效
顯示活動隱藏時，含本活動門票的組合包在電子商店的清單與搜尋都找不到，見組合包的上架、顯示、開賣開關
單張門票的顯示開關不受影響：經活動連結進入的活動頁，照常列出顯示中的門票
活動隱藏期間，含本活動門票的組合包可以經組合包自己的非公開連結購買
  • 唯一的例外是提前販售（早鳥），見早鳥與預售
  • 單張門票與票務商品自己收窄（例如先停售、隱藏或下架）不回寫活動；關掉組合包不影響活動本身與單張門票的販售

早鳥與預售

早於正式開賣就能買的時間叫其他售票時間，也就是預售；預售一開始，活動就進入售票中。建立活動第 6 步「開賣設定」下方唯讀列出。

  • 單張門票的限時購買早於正式開賣，就是早鳥的一種
  • 票務商品另設的開賣早於正式開賣，也算其他售票時間
  • 每張門票可以各自設不同的早鳥時間
  • 預售屬於售票中，所以已排程的活動不會有成交

門票的庫存

門票跟商品用同一套庫存規則：每張門票的張數是一份庫存，活動頁的單張購買與每個含這張門票的組合包各是一條販售管道。共用、鎖定、保留與撤銷退回的通用規則，見電子商店販售流程的庫存怎麼分配：共用與鎖定；本節只寫門票自己的部分：留張數給單張購買，見鎖給單售；各部分還能賣幾張，見門票的數量怎麼算；張數與鎖定能調到多少，見張數與鎖定的上下限；讓一張門票不能再單張購買，見門票的庫存設為 0；其餘情形，見bookyay、刪除與封存。

鎖給單售

創作者可以替一張門票留一部分張數給活動頁的單張購買，叫鎖給單售；留下的張數只有單張購買能賣，組合包拿不到。

  • 建立活動時，在步驟 4 的單張門票設，見單張門票
  • 票務組合包在步驟 5 設自己的鎖定套數，從這張門票還沒鎖走的張數取，見鎖定套數
  • 兩邊都不設時，單張購買與票務組合包共用這張門票的張數
  • 設了鎖給單售時，單張購買只賣鎖給單售的張數，賣完就售罄，不會去賣沒鎖定的部分
  • 活動發布後，在活動詳情的票務分頁改；鎖給單售屬庫存，活動上架中也不必下架，見單張門票彈窗
  • 門票只有限量：沒有限量與不限量之分，也沒有補貨流程與可調低的庫存門檻

門票的數量怎麼算

一張門票的張數分成好幾格：鎖給單售、每個組合包的鎖定、沒有被鎖定的部分（未鎖定）；每一格的可賣＝這一格的配額 − 這一格的保留（粉絲已下單、還沒付款而先扣住的量，見保留）。

  • 未鎖定＝張數 − 已售 − 鎖給單售 − 各組合包的鎖定
  • 未鎖定的可賣＝未鎖定 − 未鎖定這一格的保留
  • 沒設鎖給單售時，單張購買賣的是未鎖定的可賣，與沒設鎖定的組合包共用
  • 保留中＝各格的保留加總
  • 售出進度＝（已售＋保留中）÷ 張數，達 80% 與 95% 時在活動詳情警示

  • 鎖給單售加各組合包的鎖定，總和不能大於「張數 − 已售 − 未鎖定這一格的保留」，表單直接擋下

門票的庫存設為 0

活動發布後，創作者可以把一張門票的庫存設為 0，這張門票就不能再單張購買；已售出的票照常有效。按鈕在活動詳情的票種列表與單張門票彈窗，不必進編輯模式、不必下架。

  • 門票的庫存＝單張購買此刻能賣的張數：設了鎖給單售時是鎖給單售的可賣，沒設時是未鎖定的可賣
  • 設為 0 時，鎖給單售縮成只剩它的保留
  • 張數改成剛好等於「已售＋各組合包的鎖定＋鎖給單售剩下的保留＋未鎖定這一格的保留」，單張購買與未鎖定的可賣都是 0
  • 之後鎖給單售或未鎖定這兩格的保留到期釋回時，釋回的量從那一格與張數同時扣掉，可賣維持 0
  • 保留付款成功時照常轉成已售
  • 組合包鎖定裡的保留釋回時，回到那個組合包的鎖定，張數不扣，因為組合包沒有被設為 0
  • 要恢復單張購買，把張數調高
  • 照上方範例：設為 0 後，鎖給單售剩 5，張數改成 10＋40＋5＋3＝58
  • bookyay 匯入的門票不能設，要停賣用提前停售時間、下架或隱藏這張門票，見停止販售的三種做法

bookyay、刪除與封存

  • bookyay 匯入的門票也能鎖給單售，只是 ztor 內部的分配，不改 bookyay 的張數
  • 門票被刪除時，它的鎖給單售一併消失
  • 活動封存時，各格鎖定的數字保留、唯讀
  • 單張購買的可賣歸零就是售罄，即使還有保留中的量；整場什麼時候算完售，見完售
  • 撤銷票券後，張數退回原本賣出的那個鎖定，見撤銷票券

依據：主規格 §7.14「保留」「調低與移除鎖定」「門票的庫存池與單售鎖定」「組合包：鎖定套數」「活動完售與停止販售」；5.1.6.1 F20、F22「鎖給單售」；5.1.6.2 §3、F9；5.1.6.3 §2.6；D435、D447、D465（含補充二）。

活動的動作與效果

每個動作各寫能用的階段、條件與效果，依序是：

  • 發布後還能改什麼：發布後的修改
  • 草稿怎麼刪：刪除草稿
  • 場次與門票能不能刪：移除場次與門票
  • 活動找不找得到：上架與下架
  • 活動歸檔：封存與解除封存
  • 活動在不在公開清單：顯示、隱藏與非公開連結
  • 賣完了：完售
  • 三種停止販售做法的差別：停止販售的三種做法
  • 票券怎麼作廢：撤銷票券

刪除草稿

草稿可以刪除；發布過的活動不能刪除，也沒有取消，只能下架、再封存，見封存與解除封存。

  • 刪除草稿系列的母列，整個系列連同底下的場次一起刪除
  • 草稿系列的子場也可以單獨刪除，同樣要確認
  • 一起刪除的組合包，見下方票務商品怎麼跟著活動變動

移除場次與門票

開賣前可以移除場次與門票；活動進入售票中之後（售票中、進行中），場次和門票（含未售出的）都不能刪除，只能隱藏。

  • 草稿與已排程的活動可以移除場次，至少留一場
  • 該場已有門票時，移除前跳出確認，列出會一併刪除的門票；確認後場次與這些門票一起刪除
    • 該場的門票包括票種在這一場組合出的門票，以及指定這一場的獨立票
  • 該場沒有任何門票時直接移除，不跳確認
  • 一併刪除門票後，已排程的活動會沒有還在的門票（隱藏的也算）、也沒有仍在販售的組合包時，擋下這次移除，見發布後擋下的動作
  • 被刪的門票列在組合包的允許門票清單時，組合包保留；那些門票在粉絲端的組合包選項裡隱藏、不能選，在創作者介面的組合包畫面顯示為停用
  • 某一個門票成員允許的門票全部被刪時，組合包不能賣，狀態標「無法販售（Unavailable）」，取代原本的「即將開賣」或「販售中」，見票務商品
  • bookyay 匯入的活動不能增刪場次，帶入的門票也不能刪除

上架與下架

上架是階段以外的另一回事。

  • 草稿以外的四個階段，創作者與 Admin 都能下架與重新上架活動；下架與重新上架都不改變階段
  • 下架一律先確認；已有成交時，確認視窗說明已售出的票照常有效
  • 定時下架打開時，到了下架時間自動下架；定時下架關閉時不會自動下架
  • 已下架的活動留在原本的階段，另加「已下架」徽章
  • 下架後，活動頁仍可開啟，顯示「已下架」、不能購買，經非公開連結開啟也一樣；指向這場活動的入口（清單、搜尋結果）隨活動消失；創作者的優惠碼本身不動
  • 手動下架、定時下架、連動下架與 bookyay 觸發的自動下架，粉絲看到的都一樣
  • 已在購物車的這場活動品項，顯示「已失效」、不能結帳；已進入結帳、還沒付款的訂單在付款前擋下，已付款的不受影響，完整規則見電子商店販售流程的下架與封存後的粉絲端
  • ztor 不做粉絲端，以上三條只說明粉絲會看到什麼，畫面由前台團隊實作
  • 已結束的活動重新上架前會先提示：上架後粉絲找得到活動頁，但不能購買
  • 已結束的活動能再辦一場，見活動詳情的階段操作；已下架的活動能不能再辦一場，見頁尾尚待確認
  • 含這場活動門票的組合包怎麼跟著下架，見下方票務商品怎麼跟著活動變動

封存與解除封存

封存把確定不再使用的活動歸檔、離開主清單，比照電子商店商品的封存；活動沒有取消動作，不要的活動先下架、再封存。

  • 只有已下架的活動能封存；已結束的活動也要先下架才能封存，上架中時要先下架
  • 按封存先確認，說明封存後整頁唯讀、離開主清單、已售出的票與訂單不受影響、要再使用須先解除封存
  • 封存不改階段，也不是階段；已封存的活動只在活動清單的「已封存」篩選出現，見篩選與搜尋
  • 已封存的標籤優先於其他所有標籤，見活動標籤與進度的各種樣子
  • 已封存的活動整頁唯讀，只有「解除封存」一個動作，不提供編輯活動與再辦一場；撤銷票券（只有 Admin 能按）不受影響 Admin
  • 解除封存後回到已下架，不自動上架；封存前保留的設定原樣不動，要重新對外販售，另外按上架
  • 粉絲看到的跟已下架一樣：活動頁顯示「已下架」、不能購買
  • 活動封存後，含這場活動門票的組合包不能重新上架，見活動下架或結束時
  • 已售出的票與既有訂單不受封存影響，也不會自動撤銷或通知持票人；辦不成活動時怎麼處理，見撤銷票券
  • 誰能封存、封存的確認內容、尚未生效的上架排程、組合包連動，以及 bookyay 匯入活動的封存，見頁尾尚待確認

顯示、隱藏與非公開連結

顯示設定（畫面上的「顯示於商店」）管活動在不在 ztor 的活動列表與搜尋結果，跟上架是兩回事。

  • 顯示：活動出現在活動列表與搜尋結果
  • 隱藏：活動不在公開清單，只能經活動的非公開連結進入
  • 切成隱藏時產生一條非公開連結與 QR，發布後才生效；創作者可以隨時重置，重置後舊連結失效、產生新連結
  • 由隱藏改回顯示時，原本的非公開連結失效；之後再改隱藏，產生新連結，不沿用舊連結
  • 已排程、售票中與進行中都能切換；已結束與已封存整頁唯讀
  • 活動隱藏期間，單張門票與含本活動門票的組合包怎麼跟著變，見活動設定是門票與票務商品的上限
  • bookyay 匯入的活動照 bookyay 的活動性質帶入：公開活動→顯示，私人活動→隱藏；帶入後可以自己切換，bookyay 端事後改活動性質不覆蓋

完售

完售不是階段，活動照時間走，另加徽章。

  • 所有門票與票務商品都賣完時，活動另加「完售」徽章，仍照時間落在售票中，販售照時程結束
  • 只剩保留中的量、已經沒有可賣的量時，就算賣完、顯示完售；保留到期釋回後又有票可賣，徽章移除
  • 有票回補、不再全部賣完時，「完售」徽章移除
  • 完售後粉絲端只顯示「完售」，先不提供候補等其他引導
  • 要讓某張門票不在活動頁單獨賣，把門票隱藏，見單張門票怎麼停止販售
  • 要停止整場活動的販售，見停止販售的三種做法

停止販售的三種做法

三種做法效果各不相同，創作者要停止販售時從這三種挑一種。

  • 把停售時間提前：活動頁照常看得到，不能再購買；停售時間屬營運動作，活動上架中也能直接改，既有的時間限制照舊
  • 下架：不在清單與搜尋裡，活動頁顯示「已下架」，不能購買，之後可以再上架
  • 下架後封存：歸檔、離開主清單，整頁唯讀，要再用時解除封存，見封存與解除封存

撤銷票券 Admin

  • 平台不提供退款動作，票券的取消一律用撤銷；撤銷在哪裡執行，依活動來源而不同，見下方ztor 自建與 bookyay 匯入的差別
  • 撤銷入口只有 Admin 能按；創作者看得到入口與撤銷紀錄、不能按，需要撤銷時在平台外聯繫 Admin
  • 撤銷不寄 email 給持票人；撤銷的事實只記在撤銷紀錄，由 Admin 代管時查看
  • 辦不成活動時用下架：下架後已售出的票與既有訂單不自動處理，不自動撤銷、不自動通知持票人；需要退票時，Admin 在訂單詳情逐筆撤銷票券，實際退款由營運在平台外人工處理；系統只留撤銷紀錄，沒有批次撤銷，也不通知全部持票人
  • 組合包裡的門票，在訂單詳情撤銷整個組合包，見門票與組合包在哪裡撤銷
  • 撤銷後，那張票退回原本賣出的那個鎖定，見撤銷後退回原本賣出的那個鎖定

依據：5.1.6 F1、F3、F5；5.1.6.1 F7、F12b、F22、F23、F25；5.1.6.2 §3、F9、F12、F14、F16；5.1.6.3 §2.1、§2.6、§2.9.2；5.1.5.9 §2.3；主規格 §4.1 第 5 項、§7.2、§7.14「活動完售與停止販售」「非公開連結」「下架確認與組合包連動」「封存與刪除」「活動發布後的修改規則」；D188、D253、D282、D294、D341、D361、D363、D364、D371、D375、D388、D389、D390、D391、D415、D419、D422、D425、D431、D434、D435、D436、D437、D438、D447、D448、D455、D457、D465、D481、D488、D489。

票務商品怎麼跟著活動變動

門票相當於一種商品，可以被包進組合包，含門票的組合包就是票務商品，規則在組合包與票務商品。票務商品的設定怎麼受活動限制，見票務商品的設定與活動；活動不賣了票務商品怎麼辦，見活動下架或結束時；刪除草稿時一起刪什麼，見刪除草稿時。

票務商品的設定與活動

  • 票務商品另設的時間要在活動的上架區間內，可以早於活動開賣，見組合包與票務商品的上架與開賣
  • 上架、開賣、顯示不能比活動寬，票務商品自己收窄也不回寫活動，見活動設定是門票與票務商品的上限

活動下架或結束時

  • 下架時，含這場活動門票的上架中組合包一起下架
  • 活動重新上架時，組合包不會自動上架
  • 重新上架前，若有含這場活動門票、已下架的組合包，會彈窗列出名稱，問要不要同時上架：選同時上架就一起上架，選只上架活動則組合包留在已下架，取消則都不動
  • 選同時上架時，彈窗列出的組合包各自檢查下架時保存的開賣、停售、定時下架時間（只看各組合包自己的時間）：有已過或沒通過的，該組合包不上架並提示原因，其餘照常上架；沒有問題的直接恢復，不另外詢問
  • 已封存的組合包、成員有已封存者的組合包無法上架，不列入彈窗
  • bookyay 匯入的活動被自動下架後，手動重新上架同樣適用以上彈窗
  • 成員單品有已下架的組合包也不能跟著活動一起上架：彈窗會另外提示這些組合包和已下架的單品，要先把單品上架或從組合包移除，組合包才能上架
  • 活動已結束或已封存後，含這場活動門票的組合包不能重新上架，按上架時擋下並就地說明原因，見組合包的組合包重新上架時帶著成員上架
  • 活動下架或結束造成的連動下架，不算可賣條件與發布檢核要擋下的動作

刪除草稿時

  • 草稿活動被刪除時，創作者自己建立、成員含這場活動門票的草稿組合包一起刪除
  • 刪除確認時列出哪些組合包會一起刪除

依據：5.1.6.1 F12b；5.1.6.3 §2.1；主規格 §7.14「活動下架時連動組合包」「封存與刪除」；D292、D293、D294、D331、D340、D342、D352、D363、D371、D429、D437。
