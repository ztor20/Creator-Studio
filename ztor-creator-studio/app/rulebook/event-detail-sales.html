售票與名單

創作者在售票與名單分頁對帳售票紀錄、查看與匯出活動名單、確認通知寄出了沒有、查看撤銷紀錄與成本與收入摘要；通知開關是這個分頁唯一要進編輯模式才能改的設定。分頁整體的位置與各狀態有哪些分頁，見活動詳情。

概述

  • bookyay 匯入的活動，名單與撤銷唯讀，資料由 bookyay 同步回來
  • 共看派對沒有報到與撤銷紀錄

創作者進分頁後，先在子導覽選要看的區塊，再做該區塊的事。

撤銷紀錄只能查看，撤銷由 Admin 執行

  2. 在子導覽選要看的區塊，一次看一塊

    • 撤銷紀錄：看哪些票被撤銷，撤銷由 Admin 執行，見撤銷紀錄

子導覽的五個區塊各一節：售票紀錄對帳每一筆訂單，活動名單查誰會來，通知管三種通知的開關與寄送結果，撤銷紀錄列出被撤銷的票，成本與收入摘要對照收入事件與結算。各區塊在各狀態怎麼顯示，見各子區塊在各狀態的顯示。

依據：5.1.6.2 §2、§3「發布後的修改」、F17；5.1.6.3 §2.10、§4；D392、D413、D435、D455。

尚待確認

  • 「匯出中」提示的位置與樣式、匯出紀錄的入口放在哪裡，目前是畫面示意
  • 已結束與進行中以外的名單內容：非進行中場次的完整名單長什麼樣，以及最終報到統計接上真實核銷紀錄前怎麼呈現
  • 寄送紀錄要不要列出逐封的寄送明細（收件人、時間、是否開信）與重寄的路徑，目前只顯示彙總結果
  • 已封存的活動，撤銷紀錄要不要額外顯示撤銷進度
  • 進行中的活動被封存時，現場掃碼報到與報到更正是否照常
  • 辦不成活動時，已售出票券與訂單的退款、通知與撤銷怎麼處理（目前先留著不動，也不自動通知持票人）
  • 撤銷紀錄是否加一欄撤銷原因（有填才顯示、給 Admin 查）；規格目前推定比照訂單撤銷，選填、可留空
  • 通知開關有尚未儲存的改動時，要不要標示為已修改（規格為推導）
  • 售票紀錄、活動名單、撤銷紀錄與成本與收入摘要在載入中、載入失敗與沒有權限時的畫面，規格只寫照全站共用狀態規則
