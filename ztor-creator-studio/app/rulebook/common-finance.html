財務術語與收入事件

創作者與 Admin 照這頁的同一套用詞看收入、扣項與淨利，並查一筆進帳怎麼記錄、歸哪一類、用哪一版費率。總覽、項目、電子商店、活動等頁的收入數字都引用收入管理的口徑，不自行重算。

財務用詞

各頁提到收入、扣項與提款時，一律用下表的名稱。

用詞指什麼
總收入（Gross Revenue）扣除任何成本與費用前的收入頂層金額
直接成本（COGS）這筆收入直接對應的進貨、製作、物流等成本
毛利（Gross Profit）總收入扣掉直接成本
淨利（Net Income）毛利再扣掉平台費、支付費、稅費與分潤
待結算已經產生、還不能提領的金額
可提領（Available）已結算、可以申請提款的金額
提款（Payout）把可提領金額轉進收款帳戶
費用（Fee）手續費或扣項，要拆開寫出來源
收入去向（Where the money goes）從總收入一路扣到可分配淨利的拆解，見從總收入到淨利
規格與決策紀錄稱為「金流瀑布（Waterfall）」
可分配淨利（Distributable profit）項目扣完各階、要分給創作者與 NFT 持有者的那筆錢
規格與決策紀錄稱為「淨利池（Net Profit Pool）」
IP Bank 應付（IP Bank Owed）Admin 的 IP Bank 報表算出的金額＝影片淨收入 × 分成比例
只供報表閱讀，不是另一本收入帳
IP Bank 可提（IP Bank Available）IP Bank 應付減掉同一位擁有者在同一部影片已提領的金額
擁有者還沒認領時顯示 locked until claim：認領之前這筆金額鎖住、不能提

收入、提款的狀態詞見狀態語言的收入與提款的狀態。

依據：主規格 §7.3「共用欄位」「金流瀑布與淨利池」介面呈現名稱；D041、D129。

收入從總收入一路往下扣，扣到最後的可分配淨利，再分給創作者與 NFT 持有者。

流程圖：由左往右，每一支箭頭是這一階扣掉的項目；推薦分潤只有發生時才扣。

  • 毛利與淨利牽涉成本與分潤分攤，算到項目層級；一筆一筆的交易只顯示能逐筆歸屬的收入、平台費與支付費
  • 平台費與支付費一律由創作者負擔、從收入內扣，所有販售管道（電子商店、活動、項目、IP）都一樣；買家只付折後售價加運費（門票是票價），買家端看不到任何費用項目；兩筆怎麼算見優惠規則的平台費與支付費怎麼算
  • 粉絲分級折扣、創作者優惠碼、平台滿額折扣的折抵，在收入拆解各列一行，發生在平台費之前，見優惠規則的折扣由創作者與平台一起吸收
  • 多個 IP 的版稅都以毛收入平行扣，不逐層複利
  • 推薦分潤的第一個具體來源是商店優惠碼的代理分成：從發碼創作者的收入扣，不影響平台費與其他扣項，見商店設定的代理銷售紀錄
  • 可分配淨利預設創作者 60%、NFT 持有者 40%，可以逐項目在範圍內調整；沒有 NFT 的非共創項目全歸創作者
  • 可分配淨利由創作者手動觸發分配，不會自動撥款，見項目詳情
  • 每一階扣項對應它的費率版本，事後改費率不回溯，見費率版本與平台費率

依據：主規格 §7.3「共用欄位」財務階梯、「金流瀑布與淨利池」；§5.2.2；D041、D183、D278、D316、D424。

共創項目的兩筆錢

共創項目有兩筆錢：平台把募得款分期撥給創作者，以及創作者分配可分配淨利；兩筆規則分開。

可分配淨利的分配募得款撥付
哪一筆錢項目收入扣完各階之後的可分配淨利粉絲在共創期間支持的募得款
誰給誰分給創作者與 NFT 持有者平台撥給創作者
怎麼發動創作者手動觸發，不會自動撥款平台依級距與各期條件分期撥付
前提項目有已結算的收入項目已成功

募得款撥付的規則：

  • 只適用共創項目；直接發佈沒有募得款
  • 級距由平台依項目預算決定，創作者不能選，Admin 也不逐案改；預算以美金計，門檻 5 萬美金
  • 兩個級距都分期撥款，沒有一次撥款
  • 第 1 期在完成所有扣款後撥付，不經 Admin 審核
  • 之後各期的「平台確認」就是 Admin 審核，確認後 14 天內撥付
  • 各期撥付的是扣除系統費用後的金額
  • 撥付不改變項目狀態，也不新增收入分類，仍歸「項目支持」
  • 撥款進度顯示在項目詳情的共創資訊
項目預算各期撥付條件與比例
未滿 5 萬美金，分 2 期第 1 期：完成所有扣款，80%
第 2 期：平台確認發起人遞交所有物料及發行計劃，20%
5 萬美金以上，分 4 期第 1 期：完成所有扣款，10%
第 2 期：平台確認發起人遞交完整劇本，10%
第 3 期：平台確認發起人遞交演職人員名單及拍攝時間表，60%
第 4 期：平台確認發起人遞交所有物料及發行計劃，20%

依據：主規格 §7.3「募得款撥付」；§5.2.2；D041、D345、D346。

撤銷沖銷與爭議

Admin 撤銷訂單品項或票券時，沖銷以新分錄表達，原事件不改寫；項目吸收沖銷金額時，依序從三個地方扣。

沖銷準備金（Void Reserve）→當期可分配淨利→結轉到之後的赤字
  • 結轉的赤字不回收已經撥出去的錢
  • 吸收不足時暫停這個項目的分配，直到補足
  • 沖銷準備金的預扣比例目前是 0%（不預扣），這個比例可以調整
  • 平台不提供退款動作：實際退款由 Admin 在平台外（Stripe 後台）先完成，再撤銷；平台吸收的是撤銷產生的沖銷分錄，不是退款本身
  • 每個項目的收益各自結算，不能跨項目挪用或互相補貼

爭議和撤銷是兩回事：爭議由買家或銀行端發起（chargeback），平台擋不掉。

  • 爭議期間，金額從可提領扣除並凍結
  • 創作者申訴成立，金額還原到可提領；申訴不成立，維持扣除

依據：主規格 §7.3「撤銷沖銷吸收與準備金」「使用限制」；§7.6「收入事件」第 3 項；D041、D253。

收入與交易分類

交易分兩族：收入事件回答「我賺了什麼」，帳務異動回答「我的餘額為什麼變了」。這是收入管理的交易明細、收入來源與各處篩選唯一的分類來源。

收入事件的 10 類

分類收入來自哪裡
商品銷售電子商店的商品、組合包、拍賣或數位內容
活動票務活動門票、報名費或活動相關收入
項目支持共創、預購、粉絲支持或項目方案
IP 版稅自有 IP 被租用、引用或產生版稅
授權收入授權費、租用費、競標付款或其他授權合約
串流・版稅外部平台的串流、廣告或內容收益（YouTube、Spotify、OTT 等），以及平台外以報表補登或同步的版稅
合作者分潤以合作者身分參與他人作品的分潤，以及贊助與品牌合作
推薦分潤把別人的東西推出去取得的抽成：商店優惠碼的代理分成、推薦人佣金、聯盟分潤
貼文帶貨收益粉絲經創作者貼文的專屬連結完成內容租借的收益；成效指標在粉絲分析，金額只在收入管理

帳務異動的 3 類

帳務異動是錢的搬動或回吐，不套費率、不進可分配淨利。

分類指什麼
提款可提領金額轉進收款帳戶的付款紀錄
撤銷沖銷訂單品項或票券被 Admin 撤銷時記的沖銷分錄：以新分錄表達，原事件不改寫
扣款平台費、支付費、稅費、爭議調整或其他扣減

資料來源的標記

手動補登、外部平台同步、平台驗證是資料來源，不是分類，任何一類收入都可能是手動補登的。

  • 手動補登（未驗證）的收入不計入可提領與可申請提款的金額，也不計入平台稅務文件；最多計入展示用的收入統計，並標明未驗證
  • 手動輸入或預估的資料不呈現成已驗證
  • 補登的操作見手動補登收入

依據：主規格 §7.3「收入與交易分類」「使用限制」；D181、D183、D250、D253。

收入事件

每一筆收入產生時，由來源模組（電子商店、活動、項目、IP Bank）記成一個收入事件，交收入管理統一彙整；每筆進帳因此只有一個答案：從哪來、綁哪個項目或 IP、用哪一版費率、結算到哪一步。

  • 每個收入事件至少記：
    • 來源分類，見收入與交易分類
    • 所屬項目
    • 引用的 IP 版本（有的話）
    • 金額與幣別
    • 結算狀態，見收入與提款的狀態
    • 費率版本，見費率版本與平台費率
  • 收入事件只增不改：撤銷沖銷與爭議都記成新的調整事件，原事件不改寫；更正也只加沖銷分錄
  • 每筆收入事件綁一個項目，項目綁它用的 IP 版本；被引用的一方之後修改，不改寫既有事件的綁定
  • IP Bank 報表只讀取擁有者 × 影片的撥付結果並顯示算出的數字，不另建收入或提款帳本
  • 收入事件記原幣（粉絲實付的幣別與金額）與換算幣（基準幣別），見粉絲付款與收款

依據：主規格 §7.6「收入事件」「綁定原則」；§7.15「粉絲端與收款」；D041、D129、D253。

費率版本與平台費率

售出當下，當時生效的費率（平台費、支付費、分潤或版稅比例）凍結成一個費率版本，記在那筆收入事件上；平台之後改費率只影響之後的收入事件，既有事件與它的沖銷分錄都沿用原版本。

  • 平台費率只有 Admin 能在平台費率設定改；儲存就產生新的費率版本
  • 創作者端的頁面（商品細節、訂單詳情、拍賣商品細節、收入管理）只顯示解析後的費率，不提供編輯
  • 平台費與支付費是兩筆不同的扣項

平台費依收費維度與交易類型分

平台費依四個收費維度（進帳來自哪個模組）× 交易類型組成一棵費率樹，不另立第五個維度。

線上活動門票
報名與免費活動處理費
項目（Projects）共創成功抽成

實體回饋履約

  • 拍賣的費率低於一般商品，是刻意區分（拍賣是單件高價）
  • 組合包的成員含活動門票時，整筆走活動維度的門票費率，不拆成員分攤；只含商品的組合包走電子商店維度
  • 同一張訂單混有活動門票與電子商店商品時，各品項用各自維度的費率

費率怎麼決定用哪一個值

一筆收入事件的平台費依序找：這位創作者對這個交易類型有覆寫值就用覆寫值，沒有就用全平台預設（General）的值。

  • 覆寫逐個交易類型設，設定與稽核見平台費率設定
  • 找到的值連同費率版本凍結進收入事件，沖銷與對帳都沿用，不回溯
  • 收入管理收入拆解的平台費一列，取自這裡找到的值

依據：主規格 §7.6「費率版本」「平台費率」；D041、D139、D141、D292、D293、D309、D315、D316。

財務數字怎麼顯示

每個財務數字都要看得出幣別、來源、狀態與是否已驗證。

  • 跨幣別的資料顯示原始幣別、換算幣別、匯率與匯率時間
  • 跨幣別的彙總數字（摘要卡、收入趨勢等）指定一個顯示幣別，同一頁所有卡片與趨勢用同一個匯率時點，預設是結算日的匯率
  • 總覽、項目、項目淨利不自行重算收入，一律引用收入管理的口徑
  • Creator Studio 內的清單、摘要、KPI 與收入一律用基準幣別，見基準幣別與換算價

依據：主規格 §7.3「顯示規則」「使用限制」；§7.15「使用限制」。

  • 三種促銷折抵在收入去向中的確切位置，以及是否影響 IP 版稅的計算基準

  • 交件延遲或未完成時，未撥的款項怎麼處理
  • 預購項目是否適用募得款分期撥付
  • 未撥付的款項在結算狀態、可提領與收入管理交易明細中怎麼呈現
  • 「系統費用」的範圍，各期比例以扣費前或扣費後的金額為基數，費用在哪一期扣
