電子商店販售流程

一件商品「有沒有上架」「在網站上找不找得到」「能不能購買和結帳」是三件獨立的事；庫存放在一個看不見的池裡，單售與每個組合包各是一條從池裡取貨的販售管道。

本頁講商品與單售這條販售管道（Channel），以及單售、組合包、拍賣共用的開關、狀態與封存規則。組合包的成員、價格、鎖定套數、成交條件與連動，以及含門票的「票務商品」，在「組合包與票務商品」；活動的販售時間層級在「活動」。

1庫存池與販售管道

庫存池是後端概念，畫面不顯示池本身。它也不是憑空存在的——要先建立一件商品，池裡才會有東西。組合包是之後才長出來的第二、第三條販售管道，從池裡挑商品當成員、不另外進貨。

一個動作，同時生出兩樣東西。這一步沒做，就沒有池、也沒有任何能賣的東西。

三條販售管道共用商品 A 的同一個池：不論哪條售出，每售一件都從池扣一件；組合包售出一套，各成員各扣一件。販售管道各自有一組開關（下一節）與各自的可售量（第 5 節）。

池裡只有商品，組合包不在池裡——組合包是賣法、不是貨，所以組合包不能當另一個組合包的成員。組合包的成員有商品與活動門票兩種：商品從這個池扣，門票的量住在票種上（「組合包與票務商品」）。電子商店的清單把組合與拍賣也一併叫「商品」，那是清單層的傘狀說法，跟這裡講的池是兩件事。

2三個開關

單售、組合包與拍賣從草稿發布後，各自都有下面三個開關，互相獨立。「上架」是總閘門；「顯示」管在網站找不找得到；「開賣」管此刻能不能結帳。三者不互相蘊含：隱藏的東西可以開賣，未開賣的東西可以顯示。

開關意思排程
上架 ／ 下架
Listed ／ Unlisted
上架＝這條販售管道可以販售這件商品。下架＝這條販售管道不能賣；公開與非公開連結都失效。可設立刻上架，或排定自動上架、自動下架日期與時間
顯示 ／ 隱藏
Shown ／ Hidden
顯示＝以這條販售管道的身分出現在電子商店。隱藏＝商店裡找不到，只能經非公開連結進入。—
開賣 ／ 未開賣
On sale ／ Off sale
開賣＝粉絲可以結帳。未開賣＝停售（販售結束），兩者是同一個值。可設現在開賣，或排定自動開賣、自動停售日期與時間

商品的開關管不管得到組合包

  • 商品的上架／下架管到商品本身：單售下架時，含它的上架中組合包會一起下架。
  • 商品的顯示／隱藏與開賣／未開賣只管單售：單售隱藏、還沒開賣或已販售結束時，組合包照樣能帶著它成交。
  • 所以停售只停單售；要把一件商品連同組合包一起停賣，要用下架。
  • 逐項規則、門票成員看什麼，見「組合包與票務商品」的「三個開關在組合包上怎麼運作」。

活動也有自己的上架、顯示、開賣三個開關；活動與票務商品的時間層級見「活動」的「販售層級與時間」。

下架時，顯示與開賣不可調

  • 上架是總閘門。販售管道處於下架時（包括排定上架日期與時間還沒到、定時下架已過），顯示開關與開賣設定（立即／定時開賣、定時停售）留在畫面上但停用，旁邊說明「要重新上架後才能調整」；上架排程本身仍然可以改。
  • 電子商店清單列上的顯示開關同樣停用，提示「要先上架才能調整顯示」。
  • 建立流程選「不上架」＝還是草稿，這兩層直接不出現。
  • 原因：下架時這兩層對粉絲端沒有任何效果，允許改只會讓人以為改了有用。
  • 下架（手動、定時到期、被組合包連動、被成員連動）同時清除四個排程時間（上架、下架、開賣、停售），開賣退回未開賣；顯示與其他內容設定保留（D290）。

清單列的顯示開關先確認再切

電子商店清單每一列有一個顯示開關，點了先出確認彈窗（標題帶品名，內文講後果：隱藏＝粉絲在商店找不到、持非公開連結仍可買、含它的組合包照賣、不等於下架；顯示＝回到陳列、非公開連結撤銷），確認才切換，取消則維持原狀。

4售罄與販售結束

「售罄」與「販售結束」都不是開關，是推導出來的粉絲端狀態。

售罄（Sold Out）

這條販售管道的可售量歸零。

補貨後、仍在販售窗口內 → 自動回到販售中（鎖定模式要重新鎖定，見第 5 節）。

販售結束（Ended）

停售日期與時間已到。

要改停售日期與時間才恢復。

順序固定

售罄狀態下停售日期與時間到，文案由「售罄」改為「販售結束」。

例：售賣期 9/1–9/3。9/3 或之前賣光 → 售罄；9/4 還沒賣光 → 販售結束。

5庫存規則：共用池與鎖定

預設：共用池

  • 所有販售管道共用池裡的量，每售一件扣一件。
  • 池空 → 所有販售管道一起售罄，不論組合包的其他成員還有沒有貨。
  • 補貨進池 → 所有販售管道自動恢復可售。

鎖定庫存（Inventory Allocation）

在哪裡設（單一規格商品）：建立商品時只填目前在庫，這一步不收鎖定量（草稿還沒進池，沒有東西可鎖）。要鎖給單售，到商品細節頁的庫存分頁填；要鎖給某個組合包，在建立或編輯該組合包時填「鎖定套數」，各成員要鎖走幾件由系統從套數算出，見「組合包與票務商品」的「庫存與鎖定套數」。多選項商品逐選項組合設，見下方「多選項商品」。

  • 任何販售管道（單售或某個組合包）都可以從池裡鎖定 N 件給自己；鎖定的數量只有該販售管道能賣。
  • 鎖定量填 0 或不填＝不鎖定。鎖定量是配額、不是剩餘量：某個販售管道賣完，是它剩餘數量歸零的事，跟鎖定欄位無關。所以 0 跟空白同義，都代表這個販售管道沒鎖定、共用沒有被鎖定的庫存量；沒有「鎖定 0 件」這種狀態。
  • 沒有被鎖定的庫存量＝目前在庫 − 所有販售管道的鎖定量，由沒設鎖定的販售管道共用。
  • 鎖定的販售管道賣完鎖定量就售罄，不會再去吃沒有被鎖定的庫存量。
  • 防呆：鎖定量不得大於當前沒有被鎖定的庫存量，表單層擋。
  • 補貨後：補進池的是沒有被鎖定的庫存量；有鎖定的販售管道要再鎖定一次才能繼續賣，沒鎖定的販售管道自動恢復。
  • 所有販售管道都設了鎖定時，剩下沒有被鎖定的庫存量留在池裡、沒有人能賣；畫面會提醒創作者重新分配——電子商店清單在庫存欄旁加註「（N 件未鎖定）」，商品細節頁的提醒方式由介面決定。
  • 調整鎖定量不需要先下架任何販售管道。

組合包的可售量、鎖定套數（以套為單位，各成員的鎖定量由套數算出）與試算分配，見「組合包與票務商品」的「庫存與鎖定套數」。

多選項商品：鎖定逐選項組合

  • 多選項商品的庫存住在每一個選項組合上（M 有幾件、L 有幾件是兩回事），鎖定也逐組合記：一個「選項組合 × 販售管道」一個鎖定量。單一規格商品等於只有一個組合，行為不變。
  • 該組合沒有被鎖定的庫存量＝該組合的目前在庫 − 該組合各販售管道的鎖定量之和；防呆同樣是不得大於該組合當前沒有被鎖定的量。
  • 某個販售管道在這件商品上的可售量＝各選項組合在該販售管道可售量之和。組合包可售量的公式不變，只是多選項成員那一項改成這個加總。
  • 「所有販售管道都鎖定、剩下沒人能賣」逐組合判定：M 鎖了、L 沒鎖時，單售仍拿得到 L 的剩餘量。
  • 在哪裡設：單售的鎖定量在商品細節頁逐選項組合設（一列一個組合、一格單售鎖定量）；組合包在該組合包端填鎖定套數，成員是多選項商品時在那裡展開成逐組合、選填分配（規則見「組合包與票務商品」）。商品細節頁不呈現組合包的分配——要鎖的是「這個組合要留幾套」，那是組合的事。
  • 補貨規則不變（補進來的算未鎖定），只是落在該選項組合上。

6非公開連結

  • 顯示時，販售管道的連結就是前台公開連結。
  • 切成隱藏時，系統產生一條獨立的非公開連結；創作者可隨時重置（舊連結撤銷、產新連結）。
  • 切回顯示時，非公開連結撤銷，回到公開連結。
  • 下架時，公開與非公開連結都失效。

8封存與刪除

2026-09-18 定案（D284／D285／D286），2026-09-22 D307 修訂：單售、組合包、拍賣統一走同一套生命週期收尾——下架先讓功能失效，之後才視情況封存收進歸檔區；有成交的販售管道封存後不能真正刪除，因為背後掛著訂單、收入與領取紀錄；零成交且已下架或已封存的販售管道可以刪除。

生命週期

草稿 → 發布（＝第一次上架）→ 顯示 → 開賣 → 下架（所有功能失效、可再開「上架」回到上架中）→ 封存 → 解除封存（回到已下架，設定保留、不自動上架）。

「發布」與「第一次上架」是同一個動作；下架不是終點，還能重新上架、回到顯示原本保留的設定，開賣則退回未開賣（D290）；封存才是收尾動作。

零成交的販售管道在已下架或已封存這兩站可以直接刪除、跳出這個生命週期，見下方「有成交只能封存；零成交可刪除」。

封存前提與效果

  • 封存的前提是已下架：上架中的販售管道，封存動作停用並提示「要先下架」。
  • 封存的同時，系統會取消這條販售管道所有尚未生效的上架排程。
  • 封存後：離開清單的主要陳列，只有切到「已封存」篩選才看得到；細節頁面轉為唯讀，三個開關與排程都不能再調；訂單、收入紀錄與領取單位完全不受影響，仍可查看。
  • 已封存的販售管道不提供釘選；封存時若已釘選則解除。

主要動作互斥、解除封存回到已下架

下架、封存、解除封存三個動作依狀態只會出現一個，不會同時出現：上架中只有「下架」；已下架有「封存」與「上架」兩個動作（D290 規則不變）；已封存只有「解除封存」。已封存的販售管道只有「解除封存」可用，解除封存回到已下架狀態，設定保留、不自動上架；要恢復販售，須在已下架狀態再按「上架」，回到上架＋顯示沿用＋未開賣。「上架」是同一個動作（D314）：不論從細節頁頁首按「上架」、或把第 2 節的上架開關撥到「上架」、或從電子商店清單三個點點的下拉選「上架」，三處都是同一個動作、同一個狀態，不是三套各自獨立的機制。

下架確認與下架後

  • 下架一律先確認：三種販售管道的下架動作按下後都要跳確認彈窗，確認才下架；取消＝不下架。定時下架到期的自動下架不經確認。
  • 單售商品還在任何上架中的組合包裡時，下架會連同那些組合包一起下架，確認內容列出這些組合包名稱。組合包與成員之間的連動（含組合包重新上架時連帶成員、活動取消或下架時連帶組合包）見「組合包與票務商品」的「下架、連動與刪除」。
  • 下架後（D290）：清除四個排程時間（上架、下架、開賣、停售），開賣退回未開賣；顯示與其他內容設定（含鎖定量）保留。已下架期間，販售管道的內容仍可編輯，只鎖住顯示與開賣這兩個開關，只有封存才是全頁唯讀。
  • 重新上架後（D290）：回到上架＋顯示沿用＋未開賣；要販售須再設開賣，避免沒檢查就突然開賣。
  • 封存只看已下架這一件事，不再檢查組合包——已下架的單售不會留在任何上架中的組合包裡。封存後細節頁全頁唯讀，涵蓋所有分頁與逐列操作。

有成交只能封存；零成交可刪除

  • 零成交定義：這個販售管道自建立起沒有任何訂單品項；已取消、已撤銷的訂單品項也算曾有銷售，不算零成交。
  • 零成交且已下架或已封存的販售管道，可以刪除（須先確認、刪除後不可復原）；上架中的販售管道不可刪除。
  • 有成交的販售管道維持只能封存，不能刪除；草稿可刪除不變——草稿還沒真正建立、池裡沒有這件東西，刪除前一律要跳確認彈窗。
  • 單售商品仍是任何組合包的成員時（不論組合包上架中、已下架或已封存），刪除擋下並列出這些組合包，須先自行把它從組合包移除；刪除組合包不影響成員。
  • 兩個例外：bookyay 套票自動建立的組合包在任何狀態都沒有刪除入口（「組合包與票務商品」）；含活動門票的組合包，刪除或停賣若會讓活動沒有可賣的東西就擋下（「活動」的「可賣性與發布檢核」）。

下架與封存都沒有粉絲端頁面

下架與封存這兩個狀態，粉絲端一律看不到任何頁面：公開連結與非公開連結都會失效，不保留任何「已下架」或「已封存」的過渡頁面。

9拍賣：同樣採三開關

2026-09-18 定案（D285／D286）：拍賣不再是另一套模型，改成與單售、組合包同一套上架／顯示／開賣三開關，第 8 節的封存規則一併適用；競標中不可下架，結標後才進入可下架、可封存的流程。

  • 拍賣的「開賣」＝「開拍」：開賣日期與時間就是開拍時間；「停售」＝開拍時間＋競標時長，也就是結標的時間，由系統算出、不能單獨手填。
  • 拍賣的生命週期狀態（Upcoming／Live／Sold／Unsold）由三開關推導：Upcoming＝上架＋顯示＋還沒到開拍時間；Live＝競標中；Sold＝完售；Unsold＝流標，兩者都是結標後才會進入的狀態。
  • Sealed（密封終局）是一種競標模式，不是狀態——跟 Upcoming／Live／Sold／Unsold 不是同一個維度，不會出現在三開關推導的狀態裡。
  • 拍賣不套用第 5 節的庫存池與鎖定庫存規則，只套三開關、狀態組合、非公開連結與封存。
  • 封存規則（第 8 節）同樣適用於拍賣：已下架才能封存、封存後只剩「解除封存」；有成交只能封存，零出價且未成交才可刪除，見下方。
  • 拍賣解除封存同理（D298）：回到已下架，設定保留、不自動開拍；要重新開拍須在已下架狀態再按「上架」並重設開拍時間。
  • 競標中（已開拍、未結標）不可下架：下架動作停用並提示「競標結束後才能下架」，不論有無出價；顯示／隱藏仍可調整。
  • 結標時（開拍時間＋競標時長到）沒有任何出價 → 進入 Unsold（流標）；有出價 → 進入 Sold（完售）。
  • 流標與完售同路：可下架，下架後可封存。
  • 刪除比照第 8 節零成交規則，拍賣以零出價認定：零出價且未成交（不是 Sold）、且已下架或已封存，才能刪除；有出價或已完售的維持只能封存。
  • 下架同樣依 D290：清除上架排程與開拍時間，開賣（開拍）退回未開賣；重新上架後為未開拍，須再設開拍時間才能開始競標。
  • 出價者處理（暫定，可再改）：拍賣一律跑到結標時間，由最高出價者得標，平台不提供中途中止拍賣。
  • 仍待確認：有出價但未達保留價的處理、流標的拍賣能否重新開拍，見本頁頁尾「產品待確認」。

互動示意（第 3 節「試撥開關」）未包含封存態與拍賣，只示範單售／組合包的三開關與售罄／販售結束。
