電子商店販售流程

創作者用上架、顯示、開賣三個開關，決定每條販售管道（Channel，一條能賣東西的路）能不能賣、在商店找不找得到、此刻能不能結帳，並把庫存分配給各條販售管道。單售、組合包與拍賣都適用本頁的開關、狀態與封存規則。

1一份庫存、多條販售管道

建立一件商品時，系統同時建一份庫存與一條單售；之後建的每個組合包，都是從同一份庫存取貨的另一條販售管道。

建立商品同時生出庫存池與單售；沒建商品，就沒有任何能賣的東西。

  • 庫存池（Inventory pool，系統記一件商品庫存的地方）畫面上不顯示，創作者看到的是這件商品的「目前在庫」
  • 不論哪條販售管道售出，每售一件都從池扣一件
  • 組合包售出一套，各成員各扣一件
  • 每條販售管道各有一組開關，也各有自己的可售量
  • 池裡只有商品：組合包是賣法、不是貨，所以組合包不能當另一個組合包的成員
  • 組合包的門票成員不從池扣，量在票種上，見組合包與票務商品
  • 電子商店清單把組合包與拍賣也叫「商品」
  • 本頁的「商品」只指庫存池裡那件有庫存的東西

依據：主規格 §7.14「庫存池與商品」；D241、D292。

電子商店清單的顯示開關

電子商店清單每一列都有顯示開關，讓創作者在清單上直接切換商品在商店陳列或隱藏。

  • 電子商店清單每一列有一個顯示開關，點了先跳確認彈窗，確認才切換，取消則維持原狀
  • 確認彈窗的標題帶品名，內文寫切換的後果：
    • 隱藏：粉絲在商店找不到，持非公開連結仍可買
    • 隱藏：含這件商品的組合包照賣
    • 隱藏不等於下架
    • 顯示：回到商店陳列，非公開連結撤銷

商品的開關對組合包的影響

商品的三個開關之中，只有下架會帶著含這件商品的組合包一起停賣。

  • 上架與下架管到商品本身：單售下架時，含這件商品的上架中組合包一起下架
  • 顯示與隱藏只管單售：單售隱藏時，組合包照樣能帶著這件商品成交
  • 開賣與未開賣只管單售：單售還沒開賣或已販售結束時，組合包照樣能帶著這件商品成交
  • 要連組合包一起停賣一件商品，要用下架
  • 停售只停單售
  • 門票成員看什麼，見組合包的上架、顯示、開賣開關
  • 活動另有自己的一組上架、顯示、開賣開關，見活動的販售時間的三層
  • 含活動門票的組合包，上架、顯示、開賣另以所屬活動為上限：活動隱藏時不能顯示，活動沒上架時不能上架，見組合包的上架、顯示、開賣開關

下架期間的顯示與開賣

販售管道下架期間，顯示與開賣都不能調整，要重新上架後才能調。

  • 下架包括排定的上架時間還沒到，以及定時下架已過
  • 顯示開關與開賣設定（立即開賣、定時開賣、定時停售）留在畫面上但停用，旁邊說明「要重新上架後才能調整」
  • 上架排程本身仍然可以修改
  • 電子商店清單列上的顯示開關同樣停用，提示「要先上架才能調整顯示」
  • 建立流程選「不上架」時仍是草稿，顯示與開賣兩層直接不出現
  • 不論下架怎麼觸發（手動、定時到期、被組合包連動、被成員連動），都會清除上架、下架、開賣、停售四個排程時間
  • 下架時，開賣退回未開賣
  • 下架時，顯示的值與其他內容設定保留

依據：主規格 §7.14「三個狀態開關」「下架確認與組合包連動」；5.1.5 F4；D241、D263、D265、D290、D332、D363。

4售罄與販售結束

售罄與販售結束都不是開關，是系統依可售量與停售時間推導出的粉絲端狀態。

售罄（Sold Out）

這條販售管道的可售量歸零。

補貨後、仍在販售窗口內，自動回到販售中；有鎖定的販售管道要重新鎖定，見庫存怎麼分配。

販售結束（Ended）

停售日期與時間已到。

要改停售日期與時間才恢復。

兩者的先後

售罄狀態下停售時間一到，文案由「售罄」改為「販售結束」。

例：假設售賣期是 9/1–9/3。9/3 或之前賣光，標售罄；到 9/4 還沒賣光，標販售結束。

依據：主規格 §7.14「售罄與販售結束」；D241。

5庫存怎麼分配：共用與鎖定

所有販售管道預設共用同一份庫存；創作者也可以替某條販售管道鎖定一部分庫存，只給那條販售管道賣。

共用庫存

共用庫存是預設做法：所有販售管道一起從池裡賣，每售一件扣一件。

  • 池空時，所有販售管道一起售罄，不論組合包的其他成員還有沒有貨
  • 補貨進池後，所有販售管道自動恢復可售

鎖定庫存（Inventory Allocation）

鎖定庫存讓創作者替某條販售管道保留 N 件，鎖定的數量只有那條販售管道能賣。

  • 單售與每個組合包都可以鎖定
  • 鎖定量是配額、不是剩餘量：填 0 或不填都＝不鎖定，沒有「鎖定 0 件」這種狀態
  • 沒有被鎖定的庫存量＝目前在庫 − 所有販售管道的鎖定量，由沒設鎖定的販售管道共用
  • 鎖定的販售管道賣完鎖定量就售罄，不會再去賣沒有被鎖定的庫存量
  • 鎖定量不得大於當下沒有被鎖定的庫存量，表單直接擋下
  • 補貨進來的量算沒有被鎖定的庫存量：有鎖定的販售管道要再鎖定一次才能繼續賣，沒鎖定的自動恢復
  • 所有販售管道都設了鎖定時，剩下沒有被鎖定的庫存量留在池裡，沒有人能賣
  • 遇到上一條的情況，電子商店清單在庫存欄旁加註「（N 件未鎖定）」提醒創作者重新分配
  • 商品細節頁的提醒方式由介面決定
  • 調整鎖定量不需要先下架任何販售管道
  • 建立商品時只填目前在庫、不收鎖定量，因為草稿還沒進池
  • 單一規格商品的單售鎖定量，在商品細節頁的庫存分頁填
  • 組合包在建立或編輯時填「鎖定套數」，各成員要鎖幾件由系統算出，見組合包與票務商品的庫存與鎖定套數

多選項商品的鎖定

多選項商品的庫存放在每一個選項組合上（例如 M 有幾件、L 有幾件是分開的），鎖定也逐選項組合記。

  • 一個「選項組合 × 販售管道」有一個鎖定量
  • 單一規格商品等於只有一個選項組合，規則不變
  • 某選項組合沒有被鎖定的庫存量＝該組合的目前在庫 − 該組合各販售管道的鎖定量之和
  • 鎖定量不得大於該選項組合當下沒有被鎖定的量
  • 某條販售管道在這件商品上的可售量＝各選項組合在這條販售管道的可售量之和
  • 組合包可售量的公式不變，多選項成員那一項改用上一條的加總
  • 「剩下的量沒人能賣」逐選項組合判定，例如 M 鎖了、L 沒鎖時，單售仍拿得到 L 的剩餘量
  • 單售的鎖定量在商品細節頁逐選項組合設，一列一個選項組合
  • 組合包在組合包那一端填鎖定套數
  • 成員是多選項商品時，可以選填逐選項組合的分配，見組合包與票務商品
  • 商品細節頁不呈現組合包的分配
  • 補貨進來的量算未鎖定，落在對應的選項組合上

依據：主規格 §7.14「庫存規則：共用池與鎖定」「組合包：鎖定套數」「多選項商品：鎖定逐選項組合」；5.1.5.1 §2.10；D241、D255、D258、D265、D266。

6非公開連結

販售管道切成隱藏時，系統產生一條非公開連結，只有拿到連結的人進得了頁面。

  • 顯示時，販售管道的連結就是前台公開連結
  • 切成隱藏時，系統產生一條獨立的非公開連結
  • 創作者可以隨時重置非公開連結：舊連結撤銷，產生新連結
  • 切回顯示時，原本的非公開連結失效，回到公開連結；之後再切成隱藏，會產生新的非公開連結
  • 下架時，公開與非公開連結都失效

依據：主規格 §7.14「非公開連結」；D241、D264、D375。

8下架、封存與刪除

不再賣的販售管道先下架，下架後可以封存收進歸檔區；有成交的只能封存，零成交的可以刪除。

生命週期

草稿 → 發布（＝第一次上架）→ 顯示 → 開賣 → 下架 → 封存 → 解除封存（回到已下架）。

  • 「發布」與「第一次上架」是同一個動作
  • 下架不是終點，已下架可以重新上架
  • 封存是收尾動作
  • 零成交的販售管道在已下架或已封存時，可以直接刪除，見下方「刪除」

每個狀態能做的動作

下架、封存、解除封存三個動作依狀態出現，不會同時出現。

  • 細節頁頁首的「上架」、上架開關撥到「上架」、電子商店清單列下拉選單的「上架」，三處是同一個動作、同一個狀態

下架與重新上架

下架一律先跳確認，確認後才下架，取消就不下架。

  • 單售、組合包、拍賣三種販售管道的下架都要先確認
  • 定時下架到期的自動下架不經確認
  • 單售商品還在任何上架中的組合包裡時，下架會連同那些組合包一起下架，確認內容列出這些組合包名稱
  • 組合包與成員、組合包與活動之間的連動，見組合包與票務商品的下架連動與刪除
  • 下架會清除四個排程時間、開賣退回未開賣，見下架期間的顯示與開賣
  • 已下架期間，販售管道的內容（含鎖定量）仍可編輯，只鎖住顯示與開賣兩個開關
  • 重新上架後是「上架＋顯示沿用＋未開賣」，要販售須再設開賣

封存

封存把已下架的販售管道收進歸檔區，訂單、收入紀錄與領取單位都完整保留。

  • 只有已下架的販售管道能封存
  • 上架中的封存動作停用，提示「要先下架」
  • 封存不檢查組合包
  • 封存時，系統取消這條販售管道所有尚未生效的上架排程
  • 封存後離開清單的主要陳列，只有切到「已封存」篩選才看得到
  • 封存後細節頁全頁唯讀，涵蓋所有分頁與逐列操作
  • 封存後三個開關與排程都不能調
  • 訂單、收入紀錄與領取單位不受影響，仍可查看
  • 已封存的販售管道不能釘選
  • 封存時若已釘選，一併解除

刪除

零成交、且已下架或已封存的販售管道可以刪除；有成交的只能封存，因為背後掛著訂單、收入與領取紀錄。

  • 零成交指這條販售管道自建立起沒有任何訂單品項
  • 已取消、已撤銷的訂單品項也算曾有銷售，不算零成交
  • 刪除前要先確認，刪除後不可復原
  • 上架中的販售管道不能刪除
  • 草稿還沒真正建立，可以刪除，刪除前一律要確認
  • 單售商品仍是任何組合包的成員時（不論組合包上架中、已下架或已封存），刪除會被擋下並列出這些組合包，要先自行把這件商品從組合包移除
  • 刪除組合包不影響成員
  • bookyay 套票自動建立的組合包在任何狀態都沒有刪除入口，見組合包與票務商品
  • 含活動門票的組合包，刪除或停賣若會讓活動沒有可賣的東西就擋下，見活動的可賣條件與發布檢核

下架與封存後的粉絲端

下架或封存後，粉絲端看不到任何頁面：公開與非公開連結都失效，不保留「已下架」或「已封存」的過渡頁面。

依據：主規格 §7.14「下架確認與組合包連動」「封存與刪除」；D284、D286、D288、D289、D290、D298、D307、D314、D330、D331、D340。

9拍賣的開關與封存

拍賣跟單售、組合包用同一套上架、顯示、開賣開關與封存規則，不同的地方都跟競標有關。

開拍與結標

拍賣的「開賣」就是「開拍」，「停售」就是結標。

  • 開賣日期與時間＝開拍時間
  • 停售＝開拍時間＋競標時長，也就是結標時間，由系統算出、不能單獨手填
  • 結標時沒有任何出價，進入 Unsold（流標）
  • 結標時有出價，進入 Sold（完售）
  • 拍賣一律跑到結標時間，由最高出價者得標，平台不提供中途中止拍賣（暫定，可再改）

拍賣的狀態

拍賣的狀態由三個開關推導。

  • Upcoming：上架＋顯示＋還沒到開拍時間
  • Live：競標中
  • Sold：完售，結標後才會進入
  • Unsold：流標，結標後才會進入
  • Sealed（密封終局）是一種競標模式、不是狀態，不會出現在三個開關推導出的狀態裡
  • 拍賣套用三個開關、開關組合出的狀態、非公開連結與封存
  • 拍賣不套用庫存池與鎖定庫存的規則

拍賣的下架、封存與刪除

競標中的拍賣不能下架；結標後才能下架、封存。

  • 競標中（已開拍、未結標）不論有無出價都不能下架，下架動作停用並提示「競標結束後才能下架」
  • 競標中仍可調整顯示與隱藏
  • 流標與完售之後都可以下架，下架後可以封存
  • 已下架才能封存，封存後只剩「解除封存」
  • 解除封存後回到已下架，設定保留、不自動開拍
  • 要重新開拍，在已下架狀態按「上架」並重設開拍時間
  • 下架時清除上架排程與開拍時間，開拍退回未開拍
  • 重新上架後要再設開拍時間才能開始競標
  • 拍賣以零出價認定零成交：零出價、未成交，且已下架或已封存，才能刪除
  • 有出價或已完售的拍賣只能封存

依據：主規格 §7.14「適用範圍與產品待確認」第 5、6 項、「封存與刪除」的拍賣的刪除；D285、D286、D287、D290、D298、D307。
