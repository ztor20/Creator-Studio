影片上架審核

Admin 在這頁審核創作者送出的影片作品：看完創作者填的全部內容，決定通過放行，或寫下理由退回創作者。

概述

  • 送審來源有兩個，送來的欄位與審核動作相同：
    • 共創與預購：從項目詳情的完成作品發文送審
    • 直接發佈的影片：從建立項目流程送出即送審
  • 通過的意思是平台放行，作品什麼時候上線由上映日期決定，見審核通過之後
  • 這頁跨全平台所有創作者，Admin 不需要先選定創作者就能進入

操作流程

一件送審作品從創作者送出，到 Admin 通過或退回，走下面幾步。

1創作者送審狀態：待審核
2接手審核狀態：審核中
3看完送審內容影片、素材、詳情、演職名單
4可以上線嗎？
可以
審核通過項目落在準備中，等上線
不行
審核不通過附退件理由退回
創作者改完重送，回到待審核

流程圖：由左往右走，圓圈數字對應下方步驟清單的編號；綠框是放行，橘框是退回。

  1. 創作者送出作品，狀態為待審核，出現在待審清單
  2. Admin 接手審核，狀態轉為審核中，並記下審核者
  3. 在送審內容看完創作者填的全部內容
  4. 可以上線嗎？
    • 可以：審核通過，之後怎麼上線見審核通過之後
    • 不行：審核不通過，必填退件理由，退回創作者
    • 創作者修改後重送，回到待審核

依據：5.1.0.4 頁面定位、F4、F5、情境；D179、D182、D192。

待審清單

待審清單讓 Admin 看出目前有哪些作品在等、誰送的、等多久了，決定先處理哪一件。怎麼縮小範圍，見篩選與搜尋；每一列顯示什麼、怎麼排，見清單。

送審內容

審核者在同一處看完創作者填的全部內容，據以判斷能不能上線。審核者只看與判斷，不代創作者修改作品，要改一律退回創作者自己改後重送。看哪些內容，見作品內容；這件作品屬於哪個項目、通過後會發出什麼，見來源項目；以前送過幾次、為什麼被退，見送審歷程。

來源項目

  • 顯示這件作品屬於哪一個項目、送審來源、項目目前的狀態
  • 完成作品發文送來的，項目狀態應為已成功；建立項目流程送來的，應為準備中
  • 完成作品發文送來的，另顯示待發布的那則完成作品更新的內容與受眾，讓審核者知道會發什麼給粉絲
  • 直接發佈的沒有這則更新

送審歷程

  • 列出這件作品歷來的送出、通過與退件，每一筆有時間、動作、審核者與退件理由
  • 只增不改，重送件的審核者看得出上一次為什麼被退
  • 已審完的作品仍可檢視，內容唯讀，結果與退件理由一併顯示

依據：5.1.0.4 F3；5.1.2.2.1；5.1.2.2 §2.2.9；D179、D182。

審核動作

審核者把判斷落成一次明確的動作。已審完的作品不再提供通過與不通過，只能檢視。

作品審核的狀態

一件送審作品走過草稿、待審核、審核中，最後是審核通過或審核不通過；五種狀態的意思見項目規則的作品審核。這頁只有 Admin 這一側的規則：

  • 草稿不進這頁的清單，送出後才以待審核出現
  • 接手審核讓待審核轉為審核中，通過或不通過見審核動作
  • 審核通過是終態，這頁不再提供通過與不通過

依據：5.1.0.4 F2「資料邊界」、F4、F5「作品審核狀態流」（審核通過：終態）；主規格 §7.2 作品審核；D179。

審核結果的後續

審核結果決定作品接下來怎麼走，並顯示在創作者的項目詳情。通過後作品什麼時候上線，見審核通過之後；創作者在哪裡看到結果，見創作者在哪裡看到審核結果。

審核通過之後

審核通過只代表平台放行，作品還沒上線；作品上架與項目轉為已上線，發生在作品實際上線的那一刻。

  • 通過當下，項目落在準備中：共創與預購從已成功轉入，直接發佈原本就在準備中
  • 作品上線那一刻，作品在 ztor 前台上架、項目轉為已上線，兩件事一起生效；任一項失敗就都不生效，作品維持未上線、項目維持準備中
  • 完成作品更新在審核通過之前一律不發出；直接發佈沒有這則更新
  • 審核不通過時，上面這些都不發生

作品什麼時候上線，看創作者填的上映日期：

上映日期作品什麼時候上線
已到或已過跟審核通過同一刻
在未來停在準備中，到那一天上線
留白停在準備中，等創作者到項目詳情的作品區設定日期
  • 審核者不決定上映日期，也不會因為日期還沒定就不能通過

創作者在哪裡看到審核結果

  • 項目詳情讓創作者看到這次送審的審核狀態、最近一次送出時間、不通過時的退件理由與退件時間，以及回到作品上架修改重送的入口
  • 共創、預購與直接發佈一律顯示在進度摘要與時間軸的上架階段
  • 兩處讀同一份送審資料，畫面見項目詳情

依據：5.1.0.4 F4、F5；主規格 §7.2；D178、D179、D182、D192、D193、D203、D204、D455。

誰能審核與操作紀錄

只有 Admin 能審核，創作者不能審自己的作品，每一次審核都留紀錄。

  • 只有 Admin 能進入這頁與執行審核動作；創作者工作區沒有這頁
  • 沒有權限時，顯示無權限狀態並說明需要什麼身分，不只是把入口藏起來
  • Admin 代為操作某位創作者時，做的是創作者那一側的事
  • 審核一律回到這頁以 Admin 身分執行，不能用代操身分把自己送的件審過
  • 每一次接手、通過與不通過，都記錄執行者、時間、對象作品與退件理由；只增不改，更正以新的一筆表示
  • 審核紀錄與代為操作的紀錄看得出差別，見代為操作創作者的工作區

依據：5.1.0.4 F1、F6、頁面狀態；主規格 §4.1；D179。

尚待確認

  • 完成作品更新是否在作品上線那一刻才發出（目前是建議，待使用者覆核）
  • 作品標題有多種語言時，清單以哪一種為主
  • 等待時間要不要設逾時提醒，以及審核時效（送出後多久內要有結果）
  • 清單能不能切換其他排序
  • 是否一定要先接手才能通過或不通過；同一件能不能多位審核者同時接手
  • 審核者怎麼指派、能不能轉派，Admin 團隊是否分可檢視與可裁決兩種權限
  • 審核判準（內容合規、素材規格、分級與定價等）
  • 審核者能不能加只給內部看的註記
  • 退件理由要不要另提供預設分類、字數上限多少，退件次數有沒有上限
  • 能不能撤回通過或撤回退件，可以的話已發出的粉絲通知怎麼處理
  • 審核時是否決定這件作品的交易適用哪一個平台費率
  • 等待審核或等待上映日期期間，要不要給創作者或粉絲提示
  • 審核結果是否通知創作者、走哪一條通路
  • 操作紀錄在哪裡查看、能不能篩選
  • 清單載入中、載入失敗時怎麼顯示
