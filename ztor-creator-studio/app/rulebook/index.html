2權限層與角色

產品分三層：未登入層（登入頁）、平台營運層（Admin）、創作者工作區。Admin 與創作者是兩個不同的權限層，不是同一個工作區裡的角色高低。

平台營運（Admin）

平台內部營運團隊，範圍跨所有創作者。登入後落地 Creator 管理；不必先選創作者，就能使用 Admin 的各個目的地。

創作者工作區

單一創作者範圍內的完整後台。創作者本人登入後落地總覽；Admin 在 Creator 管理選定一位創作者後，也能進入這位創作者的工作區代為操作。

Admin 代管

  • Admin 代管時看到的畫面與創作者本人相同，另外多兩樣：導覽 logo 前的「返回 Creator 管理」入口，以及「目前操作中的創作者」標示。這兩樣只在 Admin 選定創作者時出現。
  • 代管一律發生在被選定創作者的範圍內，不跨創作者混用資料。
  • Admin 還沒選創作者就想進創作者工作區時，畫面說明「請先從 Creator 管理選取一位創作者」並提供入口，不只是把模組藏起來。

Admin 專屬操作

  • 有些操作只有 Admin 代管時能執行。目前的例子是訂單詳情的「撤銷品項」：營運人員已在平台外完成人工退款，創作者看不到那個後台，所以不開放給創作者。
  • 創作者本人看得到這類操作、但不能按，並說明「需要 Admin 角色」；不直接隱藏，讓創作者知道平台做得到、該找誰。

創作者工作區裡的角色

角色能做什麼
創作者本人所有功能頁的查看、建立、編輯、發布、結算與設定
合作者出現在項目、收益拆解或分潤裡，目前不是能登入後台的完整角色
粉絲不操作後台，只接收後台設定轉譯到粉絲端的內容

登入與權限顯示

  • 同一個登入頁提供電子郵件、手機號碼、第三方帳號（Apple、Google、Facebook、LINE）三種方式；登入後依身分分流起始頁，不改變兩層的架構。
  • 權限不足時不能只把入口藏起來：看得到但不能操作時，要說明缺少哪種權限、需要什麼角色或找誰。
  • 涉及付款、提款、稅務或合作者分潤時，優先保守顯示並要求明確確認。

依據：§4.1～§4.4、§6.4、§3.2.1；D086、D170、D252。

導覽原則

  • 主導覽只放頂層模組；帶下拉子選單的群組只有 IP、電子商店、粉絲三組，群組本身不是頁面。
  • 建立流程、詳情頁與多數子頁都從各自的落地頁進入，不進主導覽。
  • 商店設定不在電子商店下拉裡，由電子商店頁的按鈕開啟獨立頁面；返回時還原清單的篩選、搜尋與分頁。
  • 編輯活動不是獨立頁面，是活動詳情頁的編輯模式。
  • 草稿項目不進項目詳情：點草稿一律回到建立項目流程續填。
  • 導覽可在頂列與側邊欄兩種模式切換、預設側邊欄；兩種模式是同一套產品地圖，切換不改變頁面內容。

流程路徑內容

可被引用的單元

  • 商品、IP、活動可以被其他模組引用或組合，不只存在於單一頁面：
    • 商品可被項目的方案引用，也可組成組合包
    • IP 可被項目引用（在項目裡只有「IP 租借」這一種身分），或在 IP 市場被租用
    • 活動可在總覽、收入管理等處被引用呈現
  • 引用時以來源模組為單一資料來源；被引用的一方修改時，要提示可能影響引用方（例如商品改價時提示已引用它的項目方案）。
  • 收入事件綁定所屬項目，項目綁定使用的 IP 版本；被引用方事後修改，不改寫既有事件的綁定。

5全域能力

全域能力不是獨立頁面，而是在各頁面被調用的共用能力。

全域導覽框架

  • 提供主導覽、搜尋、通知中心、顯示模式切換、帳戶選單（個人檔案、設定、登出、四語系語言切換）。
  • 麵包屑：除了總覽，所有頁面在內容區頂端顯示；路徑是產品地圖中從頂層模組到目前頁面的祖先，祖先可點、目前頁不可點，不因進入路徑不同而改變。建立流程自己提供位置與進度，不另加麵包屑。

通知中心

  • 待辦（需要你處理）在上、通知（狀態更新）在下；每則有來源圖示、標題、一行摘要、時間與來源模組標籤，入口圖示上標未讀數。
  • 通知只提醒狀態，點擊一律導向對應功能頁處理；待辦在對應動作完成後自動解除。
  • 通知裡的金額一律引用收入管理的口徑，不自行重算。

項目淨利

  • 回答「這個項目到底賺多少」，出現在建立項目（預期收益結構）、項目詳情（收益摘要）與收入管理（實際拆解）。
  • 依財務階梯呈現：總收入 → 直接成本 → 毛利 → 平台費、支付費、稅費與合作者分潤 → 淨利，附預期與實際的差異、每筆資料的來源與驗證狀態。
  • 自動計算、手動輸入、系統預估與文件驗證分開標示；手動輸入的外部成本不能顯示成平台已驗證。

建立流程的共同行為

  • 所有建立與編輯流程共用離開、流程識別、進度、草稿儲存與主要送出的行為。
  • 下表五個建立流程是多步驟，最後一步是全頁的預覽畫面；建立拍賣目前是唯一的單頁表單：
流程步驟最後一步

  • 草稿自動儲存與手動「儲存為草稿」並行。
  • 主要動作要通過該流程的發布前檢查才可用。

7共同規格

以下是全站共用、各頁只引用不重新定義的規格。每項列出它是什麼、最核心的規則，以及在本手冊的位置；完整規則以主規格 §7 為準，之後陸續在「共同規格」底下開子頁。

7.1 商品主分類與次分類

  • 商品是平台的基礎單位：電子商店直售、組合、拍賣，活動當門票，項目引用為回饋品，全平台共用同一套分類語言。
  • 三個主分類：實體商品、數位商品、體驗與活動；跨頁引用以最細一層的次分類為準。
  • 數位的影視類與音樂類只能透過項目發售，不進電子商店；IP 資產不進項目。

權威：§7.1　手冊：商品分類與模組應用

7.2 狀態語言

  • 同一類資料在不同頁面用同一組狀態詞；狀態第一次出現要讓人看懂實際含義（例如「待結算」不等於可提領）。
  • 平台不提供退款動作：訂單沒有「已退款」狀態；唯一的取消途徑是 Admin 撤銷，撤銷只改狀態、回補庫存、讓領取碼失效，不碰金流。
  • 作品審核狀態描述一件送審作品，項目狀態描述整個項目，兩套不能互相代用。

權威：§7.2　手冊：共同規格「狀態語言」（待補）

7.3 財務術語與資料來源

  • 財務階梯：總收入 − 直接成本 ＝ 毛利；毛利 − 平台費、支付費、稅費 − 分潤 ＝ 淨利。
  • 平台費與支付手續費一律由創作者負擔、從收入內扣，所有販售管道都一樣；買家只付折後售價加運費，看不到費用項目。
  • 促銷折抵（粉絲分級折扣、創作者優惠碼、平台滿額折扣）發生在平台費之前，各列一行。
  • 總覽、項目等頁面不自行重算收入，一律引用收入管理的口徑；手動補登的收入未驗證前不計入可提領。
  • 共創項目有兩筆錢、規則分開：
    • 募得款撥付（平台撥給創作者）：一律分期，期數由平台依項目預算決定，創作者不能選。第 1 期在完成所有扣款後撥付、不需審核；之後各期由 Admin 審核確認後 14 天內撥付。撥付金額已扣除系統費用
    • 以下為影視類的各期條件，其他內容類型另定。預算未滿 5 萬美金，分 2 期：
      • 完成所有扣款：80%
      • 確認所有物料及發行計劃：20%
    • 預算 5 萬美金以上，分 4 期：
      • 完成所有扣款：10%
      • 確認完整劇本：10%
      • 確認演職人員名單及拍攝時間表：60%
      • 確認所有物料及發行計劃：20%
    • 淨利池分配（分給創作者與 NFT 持有者）：由創作者手動觸發，系統不自動分配

權威：§7.3（含「募得款撥付」）、§5.2.2；D345、D346　手冊：優惠規則（折抵與費用負擔）

7.4 語言與在地化

  • 支援英文、繁中、簡中、印尼語。語言只有一個概念「預設語言」，同時決定介面語言與內容的輸入語言；設定頁、帳戶選單、登入畫面改的是同一個值。
  • 登入畫面選的語言先只用在登入畫面；登入後與帳號的預設語言比對，不同時才詢問要改還是保留。
  • 表單只用預設語言輸入；多步驟流程的最後一步是全頁的預覽畫面，主區是粉絲看到的完整頁面，側欄有語言、幣別與發布前檢核三段，主鈕按下即發布、不再彈第二層確認。
  • 其他語系自動翻譯，原文一改就重新生成；活動例外，改為手動翻譯。
  • 發布後可在活動詳情、商品細節頁、組合商品細節頁重開同一個畫面（預覽與在地化）修改。

權威：§7.4　手冊：建立活動（預覽與發布、手動翻譯）

7.5 粉絲分級與指標術語

  • 四個分級，忠誠點數是排名分數、不能花用兌換，升級要同時通過前 % 名與最低忠誠點數兩道閘，每夜重算。

權威：§7.5　手冊：分級與分工

7.6 收入事件與費率版本

  • 每一筆收入由來源模組記成一個收入事件，交收入管理統一彙整；原事件不可改寫，調整以新的事件表示。
  • 售出當下凍結當時的費率版本，平台日後調整費率只影響之後的交易。
  • 平台費率的唯一設定入口是 Admin 的平台費率設定：四個收費維度（電子商店、活動、項目、IP）× 交易子類，某位創作者有覆寫值就用覆寫值，否則用全平台預設。
  • 平台費以品項實付（扣完所有折抵、不含運費）計算；支付費以買家實付（含運費）計算。

權威：§7.6　手冊：優惠規則（計費基準）

7.7 IP 授權與版本

  • 授權從草稿轉生效要雙方明確核准、九項條款齊全；生效後改條款要開新版本，不原地修改。
  • 每個 IP 的版本只增不改，可還原任一時點的權利狀態；收入事件綁定當時的 IP 版本。

權威：§7.7　手冊：尚無

7.8 用詞規則

  • 粉絲權益、群發訊息、公告、共創說明等可編輯文字，不能用暗示保證報酬的字（investment、yield、guaranteed payout、ROI、passive income、dividend），可改用 performance-based distribution 這類中性說法。

權威：§7.8　手冊：共同規格「用詞規則」（待補）

7.9 受眾指標術語

  • 受眾數字分「次數」與「人數」兩種單位，不能互相加總或比較，每個數字都標單位。
  • 只存在於會員資料的屬性只能用人數，並揭露涵蓋率；不把多個維度合成單一影響力分數。

權威：§7.9　手冊：粉絲分析

7.10 展示素材

  • 展示素材槽同時收圖片與影片，共用張數額度；全站唯一標準比例是直式 2:3（750×1125px）。
  • 展示素材的影片支援 MP4、MOV、WEBM，單檔上限 1.8GB，縮圖由系統取第一幀。
  • 專用影片槽（活動影片預告、項目宣傳片）另計：MP4、MOV，上限 2GB。
  • 活動另有必填的橫式橫幅（16:9），其他模組不比照。

權威：§7.10　手冊：建立活動（活動素材與內文媒體）

7.11 年齡分級

  • 六級單選、預設「全部」：全部、7+、10+、13+、16+、18+；作品上架、建立項目、項目公開資訊三處共用同一份資料。

權威：§7.11　手冊：尚無

7.12 打包單位：組合與方案

  • 電子商店的組合包與項目的方案是同一種模式：成員引用既有商品、價格由系統推導、折扣用百分比。
  • 差別：方案依附於項目、賣的是承諾；組合包獨立存在、賣的是現貨。

權威：§7.12　手冊：組合包與票務商品

7.13 項目的組成：作品與方案

  • 項目由「作品」與「方案」構成；直接發佈、共創、預購三型都有作品，只有共創與預購有方案。

權威：§7.13　手冊：商品分類與模組應用

7.14 庫存池、三開關與鎖定庫存

  • 單售與每個組合包各是一個販售管道，各自有上架、顯示、開賣三個獨立開關；庫存預設共用，任一管道可鎖定一部分只給自己賣。
  • 有成交只能封存；零成交且已下架或已封存才可刪除。活動比照：草稿可刪、發布後只能取消。

權威：§7.14　手冊：電子商店販售流程、組合包與票務商品、活動總覽

7.15 定價幣別

  • 一位創作者只有一個創作者幣別，由 Admin 建立帳號時選定，之後創作者與 Admin 目前都不能改；可選 USD、TWD、HKD、SGD、JPY。
  • 每個可販售項目的基準幣別就是建立當下的創作者幣別；其他四種幣別由系統換算。
  • 電子商店的換算價唯讀；活動票價可以逐幣別覆寫，基準價一改，覆寫全部重算。
  • 改價只影響之後的購買，已售出不追溯。

權威：§7.15　手冊：共同規格「定價幣別」（待補）
