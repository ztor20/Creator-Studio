訂單詳情

創作者在訂單詳情查看單一訂單的付款、品項、金額、門票與買家，並標記出貨；撤銷品項、撤銷整張訂單與補寄信只有 Admin 能做。

概述

  • 從訂單列表或活動詳情的交易明細打開，兩處打開的是同一筆訂單、同一個頁面
  • 平台不提供退款動作，退款由 Admin 在平台外完成
  • 平台上取消品項的唯一方法是 Admin 撤銷
  • 金額與收入管理（Earnings）同一個來源，這一頁不另外計算

操作流程

一筆訂單從粉絲下單開始，品項各自完成出貨、取貨或數位交付後，整筆訂單完成；途中可能被 Admin 撤銷，或被買家的銀行發起爭議。

流程圖：由左往右走一筆訂單，同一列是同一條路線；上面三列是品項依交付方式各自完成，第四列是 Admin 撤銷，最下面一列是爭議。紫色虛線框是要回答的問題，綠框是訂單完成，橘框是品項被取消或金額被凍結。圓圈數字對應下方步驟清單的編號。圖上沒畫的細節（混合訂單、撤銷的條件、補寄信）列在下方步驟清單後面。

  1. 粉絲在 ztor 前台下單：
    • 訂單出現在訂單列表
    • 含活動門票時，也出現在該活動的交易明細
  2. 付款完成，下列資料記在付款資訊：
    • 付款時間
    • 金流商
    • 付款方式
    • 付款編號
  3. 品項怎麼交付？
    • 物流配送：創作者按「標記出貨」，填物流商與追蹤碼，見標記出貨視窗
    • 現場 QR 領取：在取貨場次掃領取碼核銷，核銷結果寫回品項明細
    • 數位商品：交付下載或存取權限
  4. 所有品項都完成對應的履約後，訂單轉為已完成
  5. 買家來信申請退款，或 Admin 因其他因素決定取消時，見撤銷品項：
    • Admin 先在 Stripe 後台退款，再撤銷未完成的品項
    • 品項轉已取消
    • 全部品項都取消時，訂單轉已取消
    • 整筆訂單都要取消時，Admin 也可以按頁首的「撤銷整張訂單」，見整單撤銷
  6. 買家或其銀行發起爭議時，見爭議與平台外退款：
    • 訂單轉爭議、金額凍結
    • 調查解決後，回到對應的結算狀態
  • 同一筆訂單同時有物流商品與取貨商品時，物流商品可以先標記出貨，取貨商品維持待取貨，直到掃碼核銷
  • 取貨期限過了也不會自動取消，沒取貨的品項一直停在等待取貨，取消只能由 Admin 撤銷
  • Admin 可以補寄訂單確認信，見頁首

依據：5.1.5.3.1 §1、§2.5、§2.6、§2.8、§4；主規格 §7.2；D252、D253、D271、D411。

訂單的狀態

一筆訂單同時有兩條狀態，分開顯示、不合併，見兩條狀態；每個品項與領取單位另有自己的狀態，見品項與領取單位的狀態。

兩條狀態

狀態管什麼例如
付款與結算（Payment · Settlement）付款與收入結算的進度已付款（Paid）
爭議（Disputed）
履約（Fulfilment）出貨、取貨或數位交付的進度待出貨（To ship）
已出貨（Shipped）
已完成（Completed）
已取消（Cancelled）

訂單的狀態共有七種：

狀態意思
待付款（Unpaid）還沒付款
已付款（Paid）已經付款
待出貨（To ship）等待物流出貨
已出貨（Shipped）已標記出貨
已完成（Completed）所有品項都完成對應的履約：已出貨、已核銷或已交付
爭議（Disputed）買家或其銀行發起爭議，見爭議與平台外退款
已取消（Cancelled）所有品項都已撤銷；這是終態，之後不再有出貨或取貨
  • 沒有「已退款」：平台不提供退款動作，退款在平台外完成、一定先於撤銷，所以只用「已取消」表達
  • 只有部分品項被撤銷時，訂單狀態不變，取消只顯示在品項上
  • 同一筆訂單同時有物流商品與取貨商品時，履約狀態可以並列兩顆徽章，例如「待出貨」加「待取貨」
  • 取貨狀態不改寫成訂單的狀態
  • 已取消與爭議在訂單列表可以併成同一個篩選分組，但一筆訂單只屬於其中一種

品項與領取單位的狀態

領取單位（Pickup unit）是一件實體商品的一個實例：買幾件就有幾個，每個各有一組唯一的領取碼（QR）。

  • 組合包下單時展開成成員的領取單位，數量是成員數量 × 組數
  • 組合包本身沒有領取碼，每個領取單位記得來自哪個組合包
  • 活動門票一票一碼，也算一種領取單位
  • 領取單位的狀態：
    • 取貨場次待設定：商品還沒加入任何取貨場次
    • 待核銷
    • 已核銷：掃一個領取碼核銷一個領取單位，同一位買家有好幾件時逐件掃
    • 已取消：只來自 Admin 撤銷，領取碼即刻失效、不能再核銷
    • 已取消是終態
  • 場次結束後沒核銷的領取單位維持待核銷
  • 品項被撤銷後轉為已取消，品項的列上顯示撤銷紀錄

依據：5.1.5.3 F3；5.1.5.3.1 §2.2、§2.3.1、§2.5；主規格 §7.2「訂單」「取貨資格／核銷」「使用限制」「領取單位的正式定義」；D169、D240、D242、D252、D253。

撤銷整張訂單看得到入口，但不能按，說明需要 Admin能撤銷，見整單撤銷

撤銷品項

撤銷是平台上取消訂單品項的唯一方法，把 Admin 已在平台外退款的那一筆在 ztor 收乾淨。整個流程見撤銷的步驟；哪些品項能撤銷，見能撤銷的條件；送出後會發生什麼，見撤銷之後；整筆訂單都要取消時，見整單撤銷；門票與組合包在哪裡撤銷，見門票與組合包在哪裡撤銷。

撤銷的步驟

  1. 決定要撤銷，有兩種來源：
    • 買家寫信申請，由 Admin 審核，可以接受也可以拒絕
    • Admin 因其他因素自行決定，例如：
      • 缺貨
      • 重複下單
      • 付款異常
      • 取貨場次取消
  2. Admin 在 Stripe 後台完成退款，用付款資訊的付款編號找到交易
  3. Admin 回到訂單詳情，按該品項的「撤銷」，在撤銷確認視窗核對後送出
  • 買家申請的收件、審核與准駁都在平台外，買家用通知信頁尾的「聯絡我們」地址聯繫
  • 品項的「撤銷」一次撤銷一個品項
  • 整筆訂單都要取消時，用頁首的「撤銷整張訂單」一次撤銷全部品項，見整單撤銷

能撤銷的條件

要同時符合兩項才能撤銷：目前是 Admin，而且這個品項還沒完成履約。

品項還沒完成，可以撤銷已完成，不能撤銷
現場 QR 領取，含組合包裡的取貨成員所有領取單位都還沒核銷任一件已核銷
物流配送還沒標記出貨已標記出貨
數位商品還沒交付下載或存取權限已交付
  • 不能撤銷時，入口停用並說明原因，不只是隱藏：
    • 不是 Admin：說明需要 Admin 角色
    • 已完成履約：說明這個品項已完成，是終態、不能撤銷
    • 已撤銷過：顯示這個品項已取消
  • 爭議中的品項，符合條件時照樣可以撤銷

撤銷之後

確認後，下列各項同時發生：

  • 品項轉為已取消
  • 品項有領取單位時，全部領取單位轉為已取消，領取碼即刻失效
  • 撤銷的是組合包時，展開的成員領取單位一起失效
  • 實體商品的件數補回庫存，組合包補回各成員的庫存
  • 數位商品沒有庫存，不適用補回庫存
  • 買家收到「訂單已取消」email，信中列出被撤銷的品項
  • 有填原因時，email 附上原因，信中不預設是買家申請的
  • 訂單的所有品項都取消時，訂單轉為已取消
  • 還有品項未取消時，訂單狀態不變
  • 記進操作紀錄，標記執行的 Admin，有填原因時一併記錄
  • 不呼叫金流、不產生退款
  • 撤銷不能還原，沒有「取消撤銷」
  • 取貨期限過了不會自動撤銷

整單撤銷

整筆訂單都要取消時，Admin 不必逐個品項撤銷，在頁首按「撤銷整張訂單」，一次撤銷這筆訂單的全部品項。

  • 入口在訂單詳情的頁首
  • 只有 Admin 能按：創作者看得到入口，但停用，說明需要 Admin
  • 確認視窗跟撤銷品項相同，見撤銷確認視窗
  • 撤銷對象列出全部品項
  • 撤銷原因套用到每個品項
  • 效果等同每個品項各撤銷一次，各項效果見撤銷之後
  • 訂單轉為已取消
  • 每個品項的撤銷紀錄都標註「整單撤銷」
  • 不呼叫金流，Admin 要先在 Stripe 後台完成退款

什麼情況下整單撤銷可以用，規格還在確認，見頁尾的尚待確認。

平台費與支付費

平台費與支付費都是創作者這一端的扣項，從創作者的收入裡扣；買家只付折後售價加運費，買家的收據不列這兩筆。

  • 平台費與支付費的算法（逐品項算、折抵分攤、買家看不到），見優惠規則的平台費與支付費怎麼算
  • 支付費一筆訂單只算一次：以買家實付（含運費）為基準，每筆固定額不因品項多寡重複算
  • 售出當下每個品項各記一筆收入，費率鎖在當時的版本
  • 之後改費率不回溯，展開看到的費率也是售出當時的，不是平台費率設定現在的值

依據：5.1.5.3.1 §2.3.2；主規格 §7.6「費率版本」「平台費率」；D278、D309、D316、D333。

爭議與平台外退款

爭議與退款都不是創作者在這一頁能按的操作，這一節說明兩件事怎麼反映在訂單上。

  • 爭議由買家或其銀行發起（chargeback），創作者不能操作
  • 訂單爭議中時，金額從可提領暫扣並凍結，調查解決後回到收入管理對應的結算狀態
  • 爭議跟撤銷是兩件事：撤銷不會讓爭議提前解決，平台也擋不掉爭議
  • 退款由 Admin 在 Stripe 後台完成，平台不記錄退款金額，也沒有退款查詢
  • 平台上看得到的只有撤銷的結果：品項轉為已取消
  • 訂單詳情與收入管理都不出現「退款」這個動作或狀態

依據：5.1.5.3.1 §2.2、§2.6；主規格 §7.2、§7.3；D253。
