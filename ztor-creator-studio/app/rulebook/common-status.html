狀態語言

創作者與 Admin 在每一頁看到的狀態，都照這頁的同一組狀態詞；各類資料有哪些狀態集中列在這裡，怎麼轉換寫在各自的規則頁。

狀態用詞的通則

同一類資料全站只用一組狀態詞，任何一頁都不另創狀態。

  • 流程進行中需要暫時的狀態時，要能對回這頁列的狀態，或標明是流程中的狀態
  • 狀態第一次出現時，要讓人看懂實際含義，例如：
    • 待結算不等於可提領
    • 項目的進行中不等於已成功
    • 外部整合的部分支援不等於完整同步
  • 同一個對象有好幾條獨立的狀態時（例如商品的上架與庫存、訂單的付款與履約），各條分開顯示，不混成一個狀態
  • 平台不提供退款動作，所有資料都沒有「已退款」狀態；取消一律由 Admin 撤銷，見訂單詳情的門票與組合包在哪裡撤銷

依據：主規格 §7.2「規格用途」「顯示規則」「使用限制」；D252、D253。

收入與提款的狀態

一筆收入照結算狀態走：待結算 → 已結算，之後可能因 Admin 撤銷變成已取消，或因買家端發起爭議變成爭議中。

待結算→已結算 已結算之後 → 已取消（Admin 撤銷）或 爭議中（買家或銀行端發起）
  • 只有已結算的收入計入可提領（Available）與項目的可分配淨利；待結算的不能提領，也不進可分配淨利
  • 已取消來自 Admin 撤銷時產生的沖銷分錄：沖銷以新分錄表達，原事件不改寫
  • 爭議中的金額從可提領扣除並凍結，處理方式見財務術語與收入事件的撤銷沖銷與爭議
  • 收入類交易顯示待結算、可提領、已付款、爭議；提款類交易顯示提款申請中、已付款、提款失敗；一列交易只顯示自己那一類的狀態
  • 已付款在收入類表示這筆收入已撥付結清，在提款類表示提款已成功入帳
  • 手動補登、未驗證是資料來源的標記，不是交易狀態，可以和上面的狀態並存，見收入與交易分類

依據：主規格 §7.2「共用欄位」收入列、「使用限制」；§7.3「使用限制」；D041、D253、D452。

商品的庫存狀態

庫存狀態是商品上架開關以外的另一條狀態，兩條並存、不混用；庫存狀態每次售出、撤銷、補貨與手動調整後重新計算。

庫存狀態什麼時候
充足（In stock）在庫量不低於低庫存門檻
低庫存（Low Stock）在庫量低於低庫存門檻
門檻預設是庫存上限的 10%，可以逐商品調整
售罄（Sold Out）販售管道的可賣量歸零
和販售結束（停售時間到了）是兩回事
補貨中（Restocking）送出計時補貨後，到收貨確認之前
不限量（Unlimited）不受售出扣減
跟庫存版本的「不限量」是兩件事，庫存版本見實體商品的庫存版本
  • 立即補貨送出就計入庫存並重新計算，不進補貨中
  • 計時補貨送出後進補貨中；收貨確認後計入庫存，回到充足或低庫存
  • 補貨的操作見補貨
  • 清單上的徽章（例如即將開賣、已結束、售罄、低庫存、隱藏、已下架、已封存）由三個開關與庫存推導出來，不是另外存的欄位，見電子商店販售流程

依據：主規格 §7.2「共用欄位」商品列、「使用限制」第 2 段；5.1.5.6；D105、D241。

項目的狀態

項目照發行模式走不同的狀態順序，任一階段都可以轉已取消；完整規則見項目規則的項目的階段。

依據：主規格 §7.2「共用欄位」項目列、作品審核列，「使用限制」項目狀態機與適用範圍；D151、D154、D177、D178、D179、D182、D192、D196。
