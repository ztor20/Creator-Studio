項目規則

創作者與 Admin 照這頁的規則判斷一個項目是哪一種類型、由什麼組成、走到哪個階段、什麼時候看得到與買得到，其他項目頁提到這些規則時會連回這裡。

項目的類型

項目分三種類型，類型決定建立流程走哪幾步、有沒有方案、平台費什麼時候收。直接發佈另依作品家族分兩條路，見直接發佈的兩個作品家族。

項目的組成：作品與方案

一個項目由作品與方案兩個成分組成，直接發佈只有作品。兩個成分各是什麼，見作品與方案；IP 在項目裡只有一種身分，見IP 在項目裡的身分。

作品

作品是這個項目要直接發佈、共創或預購的那個主要物品，沒有作品就沒有項目。

  • 作品的類型就是建立時選的內容類型，選項見內容類型與作品家族；落到哪個商品分類見商品分類與模組應用
  • 作品上架講的作品是同一個東西：影片家族的作品多走一道檔案上架與審核，其他家族不走
  • 數位影視類與數位音樂類的次分類只能以作品的身分存在於項目，不能在電子商店販售，也不會出現在方案的商品清單；同名的實體版照常在商店賣
  • 作品能落的次分類有 15 個，方案能引用的商品次分類有 22 個；談「項目支援哪些分類」時先講清楚問的是作品還是方案

方案

方案是共創與預購打包給粉絲的一組東西：粉絲先付錢、東西還沒做出來時，方案說明粉絲會拿到什麼。直接發佈的作品已完成、直接賣，所以沒有方案。

  • 方案依附於一個項目而存在，離開項目沒有意義
  • 共創方案的主體是分潤名額，名額可以是 0（純回饋方案）
  • 預購方案必含作品至少一份，可以再加附屬商品
  • 方案與電子商店的組合包是同一套定價模式，見組合包與票務商品：
    • 成員引用既有商品
    • 價格自動算出
    • 折扣用百分比
  • 方案的欄位與價格算式見方案

IP 在項目裡的身分

IP 資產不是項目的貨：IP 在項目裡只能以 IP 租借出現，用來揭露作品借用了哪些 IP 並連結授權，見IP 租借。

  • IP 資產不能當作品
  • IP 資產不能被方案引用，方案的商品清單不出現 IP 資產次分類；借用關係不是可販售的貨
  • IP 租借屬關於項目的權利揭露，不是營利模式，不取代營利設定的廣告與品牌合作
  • IP 資產包括 Story World、Person-Based、Brand、Event Format、Other 五類
  • IP 的販售與出租走IP 市場，與項目是兩條路

依據：主規格 §7.12、§7.13；5.1.2.1 §3、§4.1 F5、§5.2.2、§5.3.2；D166、D167、D227、D228、D230、D232、D251。

項目的階段

一個項目從草稿往前走，同時只落在一個階段，任一階段都可以轉成已取消。每個階段誰能做什麼，見各階段誰能做什麼；三種類型各走哪幾個階段，見各類型走哪幾個階段；一個項目算在哪個階段，見階段怎麼判定。

草稿→準備中→進行中→已成功→已上線 任一階段 → 已取消

Admin 能做創作者能做的一切（代管），表中「Admin 額外能做」只寫創作者做不到的事。

各類型走哪幾個階段

直接發佈沒有募集階段，不經進行中與已成功。

路徑階段順序
直接發佈 · 影片家族草稿 → 準備中 → 已上線
送出審核即進準備中
直接發佈 · 非影片家族立即發布：草稿 → 已上線
稍後排程：草稿 → 準備中 → 已上線
共創、預購草稿 → 準備中 → 進行中 → 已成功 → 準備中 → 已上線
已成功之後，影片作品審核通過才回到準備中，等作品上線

階段怎麼判定

  • 影片作品轉已上線只有一條路：作品審核通過，且作品實際上線；沒有手動切換
  • 作品什麼時候上線由上映日期決定，見作品上架的上映日期與審核
  • 準備中在影片作品上可能是在等三件事之一：
    • 等審核放行
    • 等創作者設定上映日期
    • 等上映日期到
  • 清單與項目詳情都要讓創作者分辨在等哪一件
  • 直接發佈非影片家族不經審核，發布或排程時間到就轉已上線
  • 共創或預購到期沒達標，轉已取消，終止原因是未達標

依據：主規格 §7.2「項目」與「適用範圍與待確認」；5.1.2.1 §5.1.1 F18、§5.1.2「送出的結果」；5.1.2.2 §2.2.4；D151、D154、D177、D178、D179、D182、D192、D196、D239、D345、D346。

項目的時間

項目的時間分兩段：什麼時候看得到（從發布到下架），以及什麼時候買得到（販售期間）。發布是看得到的起點，販售期間依類型不同。

路徑什麼時候看得到什麼時候買得到
直接發佈 · 非影片家族立即發布或稍後排程
可另設下架日期與時間，到時項目頁不可見；不填不自動下架		看得到就買得到
直接發佈 · 影片家族由上映日期決定，見階段怎麼判定作品上線後，依設定的畫質與價格租看
共創發布後看得到共創周期，7–90 天
預購發布後看得到預購截止前
  • 共創周期與預購截止的天數，以開賣的日期與時間為起點換算，不以發布為起點
  • 看得到但還沒開始募集或販售時，項目在準備中；看得到也已開始募集或販售時，項目在進行中

依據：5.1.2.1 §5.1.1 F18「兩軸對應」、§5.2.1 F21、§5.3.1 F27；主規格 §7.14 適用範圍；D192、D239。

項目的取消

已取消是死路階段：不能轉回其他階段，也不會再往前走。

  • 任一階段都可以轉成已取消；會影響金流或粉絲承諾的轉換要確認
  • 轉入已取消時必帶終止原因，有兩種：
    • 未達標（Not funded）：共創或預購到期沒達到目標
    • 創作者取消（Creator cancelled）：創作者主動終止
  • 終止原因寫入後不能改
  • 取消的操作、退款怎麼處理與取消後哪些內容凍結，見項目詳情

依據：主規格 §7.2「適用範圍與待確認」終止原因；5.1.2.2 §2.2.4；D151、D154。

作品審核與項目階段

影片作品另有一套審核狀態，描述一件送審作品走到哪一步；項目階段描述整個項目走到哪一步。兩套並存顯示，不能互相代用，例如不能把「待審核」寫成項目階段。

草稿→待審核→審核中→審核通過 審核中 → 審核不通過，修改後重送回到待審核
狀態什麼時候進入
草稿（Draft）創作者在作品上架或建立項目流程按「儲存草稿」產生，還沒送出
不進審核佇列
待審核（Pending review）創作者送出，還沒有審核者接手
退件後重送也回到這裡
審核中（In review）已有審核者接手處理
對創作者來說和待審核一樣是等待中，作品還沒上線
審核通過（Approved）審核者通過；只代表放行，作品這一刻還沒上線
審核不通過（Rejected）審核者不通過，附退件理由退回創作者
  • 送審來源有兩個：直接發佈影片家族由建立項目流程送審，共創與預購由項目詳情走作品上架送審
  • 審核通過只代表放行，項目不會因此轉已上線，見階段怎麼判定
  • 審核不通過時作品退回創作者並附退件理由，項目留在原本的階段；修改後可以重送
  • Admin 審核的操作與退件理由，見影片上架審核

依據：主規格 §7.2「作品審核」列與「適用範圍與待確認」；5.1.2.1 §5.1.2「送出的結果」；5.1.2.2.1 §3.3；5.1.0.4 F2、F4；D179、D182、D192。

尚待確認

  • 影片以外的內容類型，共創與預購怎麼從已成功轉到已上線（目前只有影片作品有上架流程）
  • 準備中的三段等待，是否要在清單篩選或狀態標示上各自表達
  • 共創與預購的開募或開賣時間在哪裡設定；預購截止的欄位說明寫「自發布起計」，與「以開賣為起點換算」的規則不一致
  • 共創與預購沒有下架日期與時間的欄位，看得到的終點怎麼定
  • 未達標時是否一律全額退款：建立流程寫未達標全額退款，項目詳情另有可開可關的「未達標時自動全額退款」開關；預購是否套用這個開關也未定
  • 終止原因由誰決定：終止當下自動判定，或創作者取消時自己指定
  • 兩種終止原因給支持者的通知文案是否相同
  • 平台端是否提供誤取消的復原路徑、由誰執行
  • 方案能不能引用組合包
  • 共創與預購的完成作品更新，是否在作品實際上線的那一刻才發布（規格已寫入，待使用者覆核）
