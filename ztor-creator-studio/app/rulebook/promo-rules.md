# 優惠規則

來源：promo-rules.html（ztor-cs-rulebook 規則手冊站）　轉換日期：2026-10-01

ztor 的折扣分三層：創作者自己定的價（**特價**、**組合折扣**、**方案優惠**）、給特定買家的（**分級折扣**、**優惠碼**）、平台對全體買家的**滿額折扣**與**平台優惠碼**。平台抽成看買家折完之後實際付的品項金額，所以折扣由創作者與平台照費率比例一起吸收。

權威定義：`0-設計規格書.md §7.3 / §7.6 / §8.22`　裁決：`decisions.md D183`（優惠碼兩型，2026-08-10）、`D272／D273／D274／D275／D276／D277`（2026-09-15）、`D278／D279／D280`（2026-09-17）、`D299`（2026-09-22）、`D316`（幣別收斂與費用負擔方，2026-09-23）、`D342`（票務商品的購買條件與折扣分開，2026-10-01）　頁面：`5.1.5.5-商店設定.md F8`、`5.1.0.7-平台優惠設定.md`、`5.1.5.2-建立商品流程.md F13`、`5.1.5.4-建立組合流程.md F3／F7`、`5.1.7.2-分級權益.md`、`5.1.2.1-建立專案流程.md` 方案

## 1 七種折扣

先看全貌：誰設、對誰、在哪裡設。前三種是「定價的一部分」，買家看到的就是那個價；後四種是「結帳時的折抵」。細則在第 4 節。

### 排程特價

商品層。限時檔期內用特價取代定價，買家什麼都不用做。

- 誰設：創作者，在建立商品 F13
- 誰出錢：創作者

### 組合折扣

組合包層。常態折扣 %：組合售價＝成員原價合計 ×（1 − %）。另可再排限時折扣 %，疊在組合售價上。

- 誰設：創作者，在建立組合 F3／F7
- 誰出錢：創作者

### 方案優惠

項目層。方案售價＝（名額 × 單價 ＋ 商品加總）×（1 − %），用於早鳥或成組；是方案定價的一部分。

- 誰設：創作者，在建立項目的方案
- 誰出錢：創作者

### 粉絲分級折扣

粉絲層。依粉絲等級給週邊折扣 %（例：核心圈（Inner Circle）20%）；另有搶先購買天數，那是權益不是折扣。

- 誰設：創作者，在分級權益
- 誰出錢：創作者（比照優惠碼）

### 優惠碼

商店層。買家結帳時輸碼才折。分自用碼（自己發給粉絲）與代理碼（發給另一位創作者代賣、成交後分成）。

- 誰設：創作者，在商店設定 F8
- 誰出錢：創作者

### 平台滿額折扣

平台層。訂單達門檻自動折，買家不輸碼。一檔一筆設定（名稱、期間、啟用、例外）；創作者不能退出，Admin 可設例外藝人。

- 誰設：Admin，在平台優惠設定
- 誰出錢：創作者

### 平台優惠碼

平台層。平台自己發、買家輸碼，欄位與買家端行為跟創作者優惠碼一樣；一組一筆設定、各自有例外。

- 誰設：Admin，在平台優惠設定
- 誰出錢：創作者（待確認）

**上線階段（D279）**：Phase 1 只有藝人商店的**自用優惠碼**，欄位只有三組——開始／結束時間、百分比折扣（固定金額 Phase 4，D320）、適用範圍（全部商店，含活動票種；或指定商品，可多選：單售商品、組合包、活動票種）。活動票種可使用優惠碼；Phase 1 不限每人使用次數，每人總次數欄留 Phase 4。其餘全部 Phase 4（最終完整版）：

- 優惠碼的固定金額折扣（含固定金額的折法）、類型樹、每張訂單可折件數／每人總次數／總兌換次數、多碼疊加、代理碼
- 平台滿額折扣與平台優惠碼（Admin 平台優惠設定整頁）
- 排程特價、組合折扣、方案優惠、分級折扣依各自模組的上線階段

## 2 折扣底層規則

不管哪一種折扣，下面四條都成立。

1. **折扣由創作者與平台一起吸收**：分級折扣、優惠碼（創作者的或平台的）、平台滿額折扣的折抵在收入拆解各列一行，都發生在平台費之前；平台抽成跟著折後金額縮水，折 10 元、費率 15% 就是平台少抽 1.5、創作者少拿 8.5。特價、組合折扣、方案優惠是定價的一部分，不另列。
2. **平台費看折完的品項實付，支付費看買家實付**：平台抽成以所有折扣算完後的品項金額計，不含運費；金流商手續費對買家實際付的錢（含運費）計。**平台費與金流商手續費兩筆都向創作者收**，從創作者的收入裡扣——買家只付折後售價＋運費，買家端不會看到任何費用線項（D316）。平台費**逐件算**：每件用自己的折後實付 × 自己那個維度的費率——同一單混有活動票券與商品時，票券用活動費率、商品用電子商店費率；整單只折一筆的折抵（固定金額碼、滿額折扣）先按各件實付比例分到每件再各自乘費率。兩個維度預設費率現在同值，分開後算法不用改。折扣只落在符合範圍的品項金額，範圍外的品項與運費照原價，滿額門檻也只看品項小計。
3. **多種折扣的優先順序：定價層 → 買家層 → 滿額**：先套特價／組合折扣／方案優惠得到標示售價，再套買家層的分級折扣與優惠碼（創作者碼、平台碼），最後判門檻折滿額。買家層能不能疊在定價層之上，由商品的疊加開關決定（4.5.5）；滿額永遠疊在最後、不受那個開關影響。
4. **拍賣不折**：競標沒有固定售價：排程特價與優惠碼（含平台碼）明文不套用拍賣；滿額折扣暫比照排除、待確認；組合折扣與方案優惠結構上碰不到拍賣；分級折扣對拍賣規格沒寫。組合包可以折，整組算一件。

## 3 基本算法

用一件 T-shirt 走一遍：定價 1,000、特價 900、優惠碼折 50、滿額折 50、運費 100；平台費 15%、支付費 2.4%。平台費在第四站「品項實付」才算。前提是這件商品的疊加開關開著（預設關閉時，特價與優惠碼只取對買家最有利的一項，見 4.5.5）。

- 定價（創作者設的價格）：1,000
- − 特價（或組合折扣、方案優惠）：100 — 定價層：創作者自己定的價，不是扣項
- ＝ 標示售價（買家在商品頁看到的價）：900 — 定價層的價，不是扣項
- − 優惠碼（分級折扣也在這一站，同一套算法）：50 — 買家層：看這個買家是誰、有沒有輸碼
- ＝ 買家層折後小計：850 — 「滿額門檻看這裡」 達門檻才有下一行
- − 平台滿額折抵：50 — 平台層：自動折抵
- ＝ 品項實付：800 — 「平台費看這裡」 800 × 15% ＝ 120
- ＋ 運費：100 — 不折
- ＝ 買家實付：900 — 「支付費看這裡」 900 × 2.4% ＝ 21.6

創作者拿到：800（品項實付）− 120（平台費）− 21.6（支付費）＝ 658.4，兩項折抵 100 已經在實付裡扣掉、平台也因此少抽 15；運費本身與運費那份支付費的歸屬不在本頁。分級折扣沒放進這個例子，因為特價檔期內特價優先、分級折扣不套用；檔期外它跟優惠碼同一站扣、同樣算進品項實付。三個公式見下。

**平台費**

`品項實付 × 費率`

費率依商品類型（費率樹），逐件各用各的：票券用活動費率、商品用電子商店費率。品項實付＝所有折扣算完、不含運費的金額；商品、組合包、票券、方案都一樣。整單折一筆的折抵先按各件實付比例分到每件。

**支付費**

`買家實付 × 金流商費率（＋每筆固定額）`

金流商只對真正刷的金額收費，折扣越多這筆越少。

**創作者收入**

`品項實付 − 平台費 − 支付費（− 代理分成）`

三項折抵在收入拆解各自一行、發生在平台費之前；運費另計。代理分成以優惠碼折後金額計、只在代理碼成交時出現。

## 4 七種折扣細則

### 4.1 排程特價

| 項目 | 規則 |
|---|---|
| 在哪設 | 建立商品 › 折扣設定 F13；商品細節頁可改。實體與數位商品適用，拍賣不適用。 |
| 怎麼設 | 開關預設關閉；開啟後填特價價格（必填、需低於定價，大小校驗規則待確認）與起訖日（必填、結束晚於開始）。 |
| 買家看到 | 檔期內以特價取代定價；這個特價就是標示售價，平台費以它再扣各項折抵後的實付計。 |
| 疊加開關 | 「可與優惠碼疊加」預設關閉：特價、分級折扣、優惠碼三者擇一取最有利；開啟則優惠碼再疊上去。 |
| 與分級折扣 | 特價優先：檔期內以特價為準，分級折扣不疊上也不比較；檔期外分級折扣照常。 |
| 待確認 | 時區與時間粒度<br>檔期結束是否自動回定價<br>是否與組合包共用同一套能力 |

### 4.2 組合折扣

| 項目 | 規則 |
|---|---|
| 在哪設 | 建立組合 › F3 組合價格（常態）與 F7 限時折扣；組合商品細節頁可改。 |
| 常態折扣 | 組合折扣 %（選填 0–100）；售價＝成員原價合計 ×（1 − %），自動算出、唯讀；成員有多選項時顯示「從 $X 起」。空或 0 ＝ 沒有組合優惠。 |
| 限時折扣 | 限時折扣 %（啟用時必填 0–100）＋檔期起訖，疊在常態售價之上：檔期內買家付＝售價 ×（1 − 限時 %）。 |
| 平台費 | 以買家最終的品項實付計（組合售價再扣限時折扣與各項折抵後）。 |
| 疊加開關 | 與商品相同的「可與優惠碼疊加」開關，預設關閉：關閉＝優惠碼與組合折扣（常態 %＋限時 %）擇一、取對買家最有利的一項；開啟＝優惠碼疊在組合售價之上。 |
| 票務商品 | 含門票的組合包另有購買條件與限購，管誰能買、什麼時候能買、最多買幾套；價格只由組合折扣與限時折扣決定。<br>票務商品要做早鳥，用這裡的限時折扣；單張門票自己的折扣不沿用到組合包。<br>規則見[第 3 章「票務商品的購買條件」](bundles.html#rules)。 |
| 待確認 | 買家結帳時依所選成員選項算出的實際組合價<br>是否另有平台層組合優惠 |

### 4.3 方案優惠

| 項目 | 規則 |
|---|---|
| 在哪設 | 建立項目 › 方案（每個方案各自設）。 |
| 怎麼設 | 方案優惠 %（選填 0–100，預設 0），自動算價、唯讀。<br>共創方案：（支持者位數 × 每名額單價 ＋ 商店商品定價加總）×（1 − %）。<br>預購方案：（單位價格 × 含作品份數 ＋ 附屬商品定價加總）×（1 − %）。 |
| 用途 | 早鳥或成組優惠，讓方案售價低於各項加總。 |
| 地板 | 優惠只折商品那一段：折後價格不得低於該方案的分潤名額總價，名額賣的是股份、不打折。 |
| 性質 | 是方案定價的一部分，不是結帳折抵；買家看到的方案價已經含它。平台費以最終實付計。 |

### 4.4 粉絲分級折扣

| 項目 | 規則 |
|---|---|
| 在哪設 | 粉絲 › 分級權益，逐等級設。 |
| 怎麼設 | 週邊折扣 %（例：核心圈（Inner Circle）20%、超級粉絲（Super Fans）10%、上榜粉絲（Ranked Fans）5%、一般粉絲（Fan）無，數字為示意）。同一頁的「搶先購買天數」是權益、不是折扣。 |
| 對誰 | 該等級的粉絲結帳時自動套用，買家不用做任何事。 |
| 錢怎麼算 | 比照優惠碼：折抵在收入拆解單列一行、發生在平台費之前（平台費看折後實付）；計入滿額門檻的折後小計。 |
| 與其他折扣 | 特價優先：商品在特價檔期內以特價為準、分級折扣不套用。檔期外，分級折扣與優惠碼由商品的疊加開關管：預設擇一取最有利。 |
| 待確認 | 正式的等級清單與數值 |

### 4.5 優惠碼

Phase 1 只有：碼、期間、百分比折扣、範圍（全部商店含活動票種，或指定商品可多選）。固定金額折扣是 Phase 4（D320）。活動票種含 bookyay 帶入的活動，優惠碼不在 bookyay 的鎖定範圍。4.5.1 表格裡的其他欄位、4.5.3 的次數規則、4.5.5 的疊加開關都是 Phase 4；Phase 1 不限每人使用次數，每人總次數欄留 Phase 4。

#### 4.5.1 一組碼有哪些設定

| 設定 | 規則 |
|---|---|
| 類型 | 自用碼 ／ 代理碼。代理碼多兩格：推廣者（一組碼綁一位）與分成比例；買家端兩者行為相同。代理碼整支（類型選擇、推廣者、分成、代理銷售紀錄）只在完整版 Phase 4，前面階段只有自用碼。 |
| 優惠碼 | 買家輸入的字串，商店內唯一；8–20 個英數字、不含符號，比對不分大小寫。欄旁有「自動產生」，按了填入一組可再改。 |
| 折扣 | 百分比（1–100%）或固定金額（≥ 1，該創作者的創作者幣別）。固定金額不超過該件售價，超過就折到 0。Phase 1 只有百分比、沒有型態切換（D320）。 |
| 固定金額的折法 | 可折多件時由創作者選：整單只折一次（預設，已裁決 D297）或每件各折一次。只在固定金額且每張訂單可折件數不是 1 時出現。折法本身：整單只折一次＝符合範圍的品項小計加總後扣一次、折到 0 為止，範圍只圈到一件商品時，只對那件的小計折一次、買多件也只折一次（D297）。Phase 1 沒有固定金額，這一整欄與固定金額都是 Phase 4（D320）。 |
| 適用範圍 | 三級可混選，見下表。 |
| 期間 | 開始時間必填；結束留空＝不設結束。 |
| 每張訂單可折件數 | 預設 1；留空或 0＝不限。一單裡符合範圍的商品多於這個數時，自動折售價最高的那幾件。 |
| 每人總次數 | 留空或 0＝不限。同一個 ztor 帳號跨訂單累計，以件計。 |
| 總兌換次數 | 留空或 0＝不限。全部買家合計，以件計；用完狀態轉「已用完」。 |
| 可與其他優惠碼疊加 | 開關，預設關。兩組碼都開才能同一單並用；任一關閉就擇一、取對買家最有利。跟商品的疊加開關（管優惠碼對特價／分級折扣）是兩個開關。 |

折抵怎麼落：百分比折扣套用到訂單內所有符合範圍的數量；Phase 1 沒有「每張訂單可折件數」欄，折最貴幾件的規則只在 Phase 4 設了件數上限時生效；固定金額一律整單只折一次（D297，Phase 4 起才有）。

#### 4.5.2 適用範圍：三級可混選

| 層級 | 選什麼 | 例 |
|---|---|---|
| 「全部商店」 | 預設，商店裡所有可折的品項。 | — |
| 「特定品項」 | 商品類型樹，可勾整個層級或只勾子類型，可勾多個（Phase 4）。 | 實體商品 › 服飾配件＋數位商品 |
| 「特定商品」 | 單售商品、組合包或活動票種，可多選。票務商品（成員含票券的組合包）就是組合包，整組算一件。 | 「26MS Hoodie」＋「A＋B 套組」＋「VIP ＋ 巡演 Tee」 |

一組碼的範圍＝勾的類型 ∪ 勾的商品。拍賣永遠不在範圍內。

#### 4.5.3 次數怎麼數

「一次」＝折一件符合範圍的商品；同品項買 3 個算 3 件。同一組碼在一張訂單只能輸一次；不同的碼能不能同單並用，看各自的「可與其他優惠碼疊加」開關。

| 每張訂單可折件數 | 每人總次數 | 效果 |
|---|---|---|
| 1 | 留空／0 | 每張訂單折 1 件，想買幾單都行。 |
| 2 | 2 | 這個人一共能折 2 件，可以一單折兩件、也可以分兩單。 |
| 1 | 3 | 每單最多折 1 件，一共 3 單就用完。 |
| 5 | 留空／0 | 一單最多折 5 件，人數與單數不限（搭配總兌換次數才擋得住）。 |

- 計數時點：下單成功就計入每人總次數與總兌換次數。
- 歸還：訂單被撤銷，那幾件的次數還回去。活動票券撤銷也一樣——票是訂單裡的一種品項，次數歸還、跌破門檻的滿額折抵追回。

#### 4.5.4 狀態

由期間、啟用旗標、總兌換次數推導，創作者不直接指定。

「未開始」「進行中」「已用完」「已結束」「已停用」

停用＝即刻停收這組碼，既有訂單與分成紀錄保留。

#### 4.5.5 與特價、分級折扣的疊加

能不能在已有折扣上再用優惠碼，由**商品或組合包**決定：建立商品 F13／建立組合 F7 的「可與優惠碼疊加」開關，預設關閉。優惠碼本身不逐碼設疊加。

| 開關 | 結果 |
|---|---|
| 「關閉」（預設） | 商品：優惠碼與已生效的折扣（特價檔期內＝特價；檔期外＝分級折扣）**擇一**，取對買家最有利的一項。<br>組合包：優惠碼與組合折扣（常態 %＋限時 %）**擇一**，取對買家最有利的一項。 |
| 「開啟」 | 優惠碼疊在已生效的折扣之上（商品：特價或分級折扣；組合包：組合折扣）。 |

特價與分級折扣不比較：特價檔期內一律特價優先。擇一是逐件比還是整單比，規格仍未定。

### 4.6 平台滿額折扣（Phase 4）

在 Admin 的平台優惠設定裡，一檔活動一筆：名稱、門檻、折抵、生效期間、啟用、備註、本筆例外藝人、修改歷史。

| 項目 | 規則 |
|---|---|
| 怎麼觸發 | 訂單的品項小計（分級折扣與優惠碼折後、不含運費）達門檻，自動折，買家不輸碼。 |
| 門檻用哪個幣別 | 門檻金額以**平台基準幣別**記錄（平台自己的記帳幣別，預設港幣）。判斷某張訂單有沒有達標時，依當時匯率把門檻換算成該創作者的幣別再比對，畫面同時顯示換算後金額與匯率時點。站上沒有「全站幣別」這回事——每位創作者各有各的幣別（D316）。 |
| 多筆同時生效 | 可以。一張訂單只套用它達到門檻的各筆裡**折抵最高的一筆**，不累加。 |
| 折多少 | 固定金額或百分比；固定金額不超過品項小計。 |
| 範圍 | 全平台：電子商店、活動票券、項目。拍賣暫比照優惠碼排除。 |
| 誰出錢 | 創作者與平台依費率比例一起吸收：折抵在收入拆解單列一行「平台滿額折扣」，平台費以折後實付計。 |
| 例外藝人 | 三層：全局例外（所有平台優惠都不套用）、這一筆自己的例外、某組平台碼自己的例外；實際排除＝三層聯集。例外藝人的品項不計門檻、也不被折；同一單混有例外與一般藝人時，只以一般藝人的品項小計判門檻與分攤。 |
| 多位藝人一單 | 門檻以一般藝人（非例外）的品項小計合計判定，折抵依各藝人品項小計比例分攤、各自吸收（暫定，若結帳一店一單則不適用）。 |
| 改設定 | 儲存即生效，只對之後成立的訂單；既有訂單不回溯。每一筆自帶修改歷史（時間、操作者、改了什麼）。 |
| 撤銷 | 撤掉任一品項就重算門檻；不再達標時，已給的滿額折抵從那次撤銷的退款裡扣回。 |

### 4.7 平台優惠碼（Phase 4）

平台自己發的碼，一組一筆設定；欄位與買家端行為跟創作者優惠碼（4.5）一樣，差別只在誰發、以及有自己的例外藝人。

| 項目 | 規則 |
|---|---|
| 設定欄位 | 名稱、碼（全平台唯一，8–20 英數字、可自動產生）、折扣（%／固定，固定金額的折法同 4.5.1）、生效期間、啟用、每張訂單可折件數／每人總次數／總兌換次數（留空或 0＝不限）、可與其他優惠碼疊加（預設關）、備註、本組例外藝人、修改歷史。 |
| 範圍 | 全平台；能不能限定模組或商品類型待確認。拍賣不折。 |
| 買家端 | 結帳輸碼，自動驗證範圍、期間、次數；折售價最高的那幾件；運費不折。 |
| 與創作者的碼 | 同一單能不能一起用，看雙方各自的「可與其他優惠碼疊加」開關。 |
| 誰出錢 | 同滿額折扣：折抵發生在平台費之前，創作者與平台依費率比例一起吸收（待確認）。 |
| 狀態 | 未開始／進行中／已用完／已結束／已停用。 |

## 5 UI 流程

同一套規則，散在 Creator Studio 的四個地方設定、兩個地方看結果；買家端不在本專案。

### 5.1 創作者在商店設定中的設定

#### 優惠碼

商店設定 › 優惠碼 F8

1. **新增**：選類型（自用／代理），填碼、折扣、適用範圍（類型樹＋商品多選）、期間、每單可折件數、每人總次數、總兌換次數；代理碼再填推廣者與分成比例。
2. **發出去**：自用碼貼給粉絲；代理碼交給另一位創作者去推。
3. **看清單**：狀態（未開始／進行中／已用完／已結束／已停用）與「已用／上限」；可編輯、複製、停用、刪除。
4. **代理銷售紀錄**：透過代理碼成交的訂單與分成金額（完整版才有）。

### 5.2 創作者在建立與詳情中的設定

#### 商品

建立商品 F13 › 商品細節頁

1. 開「排程特價」，填特價與檔期。
2. 決定「可與優惠碼疊加」開關（預設關）。
3. 商品細節頁可改同一組設定。

#### 組合包

建立組合 F3／F7 › 組合詳情頁

1. F3 填組合折扣 %，看自動算出的售價。
2. F7 要限時再開限時折扣 %＋檔期。
3. 疊加開關同商品。

#### 項目方案

建立項目 › 方案 › 項目詳情

1. 每個方案填方案優惠 %。
2. 價格依名額、商品加總自動算出，唯讀。

### 5.3 創作者在粉絲分級中的設定

#### 分級權益

粉絲 › 分級權益

1. 逐等級填週邊折扣 %。
2. 搶先購買天數在同一頁，但那是權益、不進折扣計算。

### 5.4 Admin 在 Admin 端的優惠設定（Phase 4）

#### 平台優惠設定

Admin Creator Studio › 平台優惠設定（與平台費率設定同層）· 四個分頁：滿額折扣／平台優惠碼／例外藝人／紀錄

1. **開一檔滿額折扣**：新增一筆，填名稱、門檻、折抵、生效期間、啟用、備註；要排除誰就在這一筆裡加例外。儲存只對之後的訂單生效。
2. **發一組平台碼**：新增一組，填名稱、碼、折扣、期間、次數限制、疊加開關、備註；例外同樣在這一組裡加。
3. **全局例外**：某藝人完全不參與任何平台優惠，加到「例外藝人」分頁。
4. **暫停或改**：關那一筆的啟用即刻停套；改動寫進那一筆的修改歷史，舊訂單不變。
5. **對帳**：紀錄分頁逐筆看訂單套了哪一筆、折多少、分攤到誰；可依藝人彙總。

### 5.5 折扣在哪裡看得到結果

#### 創作者

訂單詳情、收入管理、代理銷售紀錄

1. 每筆訂單逐項列出分級折抵、優惠碼折抵（創作者碼、平台碼）、平台滿額折抵、代理分成；平台費以折完的品項實付算。這幾頁的規格下一輪才補，原型先行。
2. 收入管理彙總同一組扣項。

#### 買家

粉絲端結帳 · 本專案不做

1. 商品頁看到特價、組合售價、方案售價；有等級的粉絲看到自己的折扣。
2. 結帳輸優惠碼，自動驗證範圍、期間、次數，折售價最高的那幾件。
3. 達門檻自動再折滿額；下單成功那一刻次數算用掉；撤銷則沖銷、次數歸還，跌破門檻的滿額折抵扣回。

## 6 試算

調數字看各站金額與收入拆解（不含分級折扣；固定金額碼在這裡照「每件各折一次」算，實際由創作者逐碼選）。預設：兩件 T-shirt 各 1,000、一張海報 500、優惠碼 10% 且每單只折 1 件、滿 2,000 折 100、平台費 15%、支付費 2.4%。

輸入欄位（預設值）：

- T-shirt 單價（優惠碼範圍內）：1000
- T-shirt 件數：2
- 海報單價（範圍外）：500
- 運費：100
- 優惠碼折扣：「百分比」（預設選取）／「固定金額」
- 折扣值：10
- 每張訂單可折件數：1
- 滿額門檻：2000
- 滿額折抵：100
- 平台費率 %：15
- 支付費率 %：2.4

依上列預設值代入頁面公式算出的結果：

| 站 | 金額 | 說明 |
|---|---|---|
| 定價合計 | 2,500 | 例子裡沒有特價 |
| − 優惠碼折抵 | −100 | 折 1 件 T-shirt（每單可折 1 件），海報在範圍外 |
| − 平台滿額折抵 | −100 | 優惠碼折後小計 2,400 ≥ 門檻 2,000 |
| 品項實付 | 2,300 | 所有折扣算完；平台費以此計 |
| **買家實付** | 2,400 | 品項實付＋運費；支付費以此計 |
| 平台費 | −345 | 品項實付 × 費率 |
| 支付費 | −57.6 | 買家實付 × 費率 |
| **創作者收入** | 1,897.4 | 品項實付 − 平台費 − 支付費；運費另計 |

示意數字。費率確切值、運費歸屬、支付費固定額不在本頁。
