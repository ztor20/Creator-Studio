6.0.1 Surface layers表面階層

From Figma 856:27798 (visualised in design-layers.html): L0 canvas solid → L1 card solid → L2 translucent film that brightens whatever it sits on, and can stack → L3 stops filling and keeps only a hairline.

模型出自 Figma 856:27798（design-layers.html 有可視化）：L0 畫布實色 → L1 卡片實色 → L2 半透明薄膜（疊在誰身上就跟著誰亮一階，可再疊）→ L3 不再疊填色、只留線框。

L1 cardL1 卡片

L2 grouped block — brighterL2 分組面 — 比卡亮

Brighter (stacked on top)往亮（疊上去的一層） --nest-surface + --nest-line. Consumers消費者: .nest, .card--muted, .bd-sec. Light mode has both layers white, so the hairline is what separates them.亮色兩層同為白，靠線框才分得出來。
Darker (a well cut into the surface)往暗（挖出來的凹槽） --muted. Consumers消費者: .segmented track軌道, media wells (image placeholders)媒體井（圖片佔位格）, progress bar troughs進度條底. Not in scope of the flip.不在翻向範圍。
Controls (buttons on a surface)控件（浮在表面上的按鈕） --control-raise (dark深色 rgba(222,223,233,.04) / light亮色 var(--card)). Consumer消費者: .btn--outline. Never an absolute surface colour — hardcoding --card made the same button read brighter on canvas, identical inside a card, and darker inside an L2 block (Q67).不要用絕對表面色——寫死 --card 時，同一顆按鈕在畫布上比底亮、在卡裡同色、在 L2 分組面裡反而更暗（Q67）。
Clickable cards (hover)可點卡片（hover） --clickable-card-lift (-4px) + --clickable-card-hover-bg (aliases別名 --control-raise-hover: dark深色 rgba(222,223,233,.12) / light亮色 var(--accent)). Declared in both theme blocks of _tokens.css so the alias resolves the dark value. Consumers and exceptions: see §5.3 · Clickable card hover.亮暗兩個主題區塊都宣告，別名才吃得到暗色值。消費者與例外見 §5.3「可點卡片 hover」。
Rule of thumb判斷句 Is this a layer stacked on the container, or a well cut into it? Former brightens, latter darkens.這塊東西是「疊在容器上的一層」還是「容器上挖出來的一個凹槽」？前者往亮，後者往暗。
.form-section--outlined Page-level grouping — never put it inside a card or dialog. It takes the absolute --surface-shell #1C1D1E, which reads correctly against the #0C0D0D canvas but is darker than --card #212223, so nesting it sinks a level. Use the brighter set instead.頁面層的分組——不要放進卡或彈窗。它吃絕對色 --surface-shell #1C1D1E，坐在畫布 #0C0D0D 上方向正確，但比 --card #212223 暗，一放進卡就往下沉一階。卡／彈窗內要分組請用上面往亮那組。

Rows with a kebab menu (--menu, 2026-08-20 · D212)

列尾是 kebab 選單的清單 （--menu，2026-08-20 · D212）

The wrapper's overflow-x:auto clips vertically too, so a row menu opening downward gets cut in half — always on the last row. .admin-table-wrap--menu lets the menu escape and drops the 840px min-width (that figure belongs to the much wider Admin IP Bank table); with overflow released the wrapper's radius no longer clips, so the head row and last row round their own corners. Same approach as variant-table-wrap--menu. Used by the size-guide and discount-code lists in Store settings.

外框的 overflow-x:auto 連縱向一起裁，列尾選單往下長出去就只剩半截（最後一列必中，2026-08-20 使用者回報）。.admin-table-wrap--menu 放行 overflow（外框與 .ztor-table 兩層都要——表格自己也是 overflow:hidden，只放行外框選單仍然出不來），並把 840px 最小寬歸零——那個寬度是給欄位多得多的 Admin IP 銀行表用的，三欄的清單硬留著只會逼出一條沒必要的橫捲。overflow 放行後外框圓角不再 clip 內容，所以首列表頭與末列自己補圓角貼齊內緣。做法沿用 variant-table-wrap--menu。消費頁：商店設定的尺寸指南與優惠碼兩張清單。

ztorUI reskin (2026-08-28 Wave 3 · B-grade sweep fix): .admin-table-wrap now uses the glass card recipe (--ztu-glass-bg + backdrop-filter: blur(var(--ztu-blur-glass)) + 1px --border + --shadow-card/--shadow-edge-top, same formula as .card/Q77), replacing the old solid --card fill with a single --shadow-card. The nested .ztor-table keeps its own header/hover tokens unchanged — verified readable on admin-ip-bank, admin-platform-fees, admin-video-review and store-settings.

ztorUI 換裝（2026-08-28 Wave 3 B 級巡檢補修）：.admin-table-wrap 外框改玻璃配方（--ztu-glass-bg ＋ backdrop-filter: blur(var(--ztu-blur-glass)) ＋ 1px --border ＋ --shadow-card/--shadow-edge-top，同 .card／Q77 配方），取代原本實色 --card 底＋單層 --shadow-card。巢狀 .ztor-table 的表頭／hover token 不變——已在 admin-ip-bank、admin-platform-fees、admin-video-review、store-settings 四頁實測可讀。
