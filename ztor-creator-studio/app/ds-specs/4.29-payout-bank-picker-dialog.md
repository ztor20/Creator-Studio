### 4.29 Modal shell（彈窗殼）＋ Payout bank picker（原名 Payout bank picker & dialog）

**彈窗有哪些類型** — 本元件只管外殼（頭身腳、遮罩、寬度修飾類 `--narrow` 460／預設 620／`--wide` 880／`--xwide` 1180）。要做哪一種彈窗、放什麼、按鈕怎麼排、用哪個寬度，先看 5.1.8 彈窗類型（[5-pattern.md](../ds-pillars/5-pattern.md)，Q141–Q144）。

**共用確認／告知程式** — `js/ztor-dialog.js`（2026-11-09）：`ztorDialog.confirm({ title, body, items, okLabel, cancelLabel, danger, noCancel })` 回傳 Promise<boolean>、`ztorDialog.notice({ title, body, okLabel })`。用本殼的 `--narrow` 現做一個彈窗，涵蓋 5.1.8 的「確認後執行」「破壞性確認」「提示告知」三類；`items` 會在內文下方列出受影響項目（`.payout-dialog__list`）。取代原生 `confirm()`／`alert()` 與借 Leave dialog 殼的確認（Q141）。頁面要連 `payout-modal.css` 並載入這支程式。

**Pattern** — 所有 5.1.8 彈窗類型 實例共用的彈窗殼，見 [5-pattern.md](../ds-pillars/5-pattern.md)。

**`_layer`** · organism — Two-part payout flow (spec §5.1.8): a page-side bank picker card grid (`.payout-bank-*`) on Earnings · Payouts, plus the request-payout modal (`.payout-modal` blurred backdrop + `.payout-dialog` shell with head / body / foot, 34px display-type amount input, fee summary, step views and success view). Mounted from `partials/payout-request-modal.js`; promoted out of earnings.html inline styles on 2026-06-09. **2026-07-23 footer/header 釘住收斂到元件層**：`.payout-dialog` 改成 flex column＋`overflow:hidden`，`__head`／`__foot` `flex:none` 釘在上下、`__body` `flex:1＋overflow-y:auto` 只捲內容——原本整框 `overflow:auto` 會讓 footer 隨內容捲走，各 popup 得各自補救（restock 曾 scope 修過，已移除）；現在所有 `.payout-dialog` 消費者一次到位。

**頁尾手機換行（2026-10-15 目視檢查 C7）** — ≤640px 時 `.payout-dialog__foot` 改 `flex-wrap: wrap`，頁尾裡的說明句（`__foot-note`，以及直接放在頁尾的 `.field__hint`，例：單張門票彈窗「由 bookyay 帶入，不能刪除；要改請回 bookyay 改。」）`flex: 1 0 100%; order: -1`——佔滿一整行、排在按鈕上方，按鈕群在下一行照舊靠右；原本 375px 會被擠成四行窄條。


**Variants** — Bank card: default / `--selected` (inset 2px foreground ring) / `--add` (dashed). Form grid: 2-col / `--single`. **`.payout-dialog__split`** (2026-08-09; first consumer = the ticket edit dialog in `create-event.html`, §4.114 Ticket tier card) — splits `__body` into a main column (fields to fill in) + a side column, `align-items: start` so the side column never stretches to the main column's height; collapses to a single column ≤640px, side column falls to the end. **Side width is `--payout-split-side` since 2026-08-10**, defaulting to the original hard-coded 200px (ticket edit dialog unchanged); create-event's Ticket setup sets 360px for the generated-ticket list, which cannot fit five fields in 200px. A variable rather than a second modifier, because the only difference is one number. **`.payout-dialog__split-side` (2026-08-10, optional)** — makes the side column `position: sticky` with its own `overflow-y`. For dialogs where the left column is the settings and the right column is what those settings produce: if the side scrolls away with the main column you can no longer see the result, which is the whole reason for splitting. Its own `max-height: 100%` makes a long result list scroll inside the column instead of stretching the dialog. Reverts to `static` at ≤640px, where stacking already scrolls and sticking would just cover what follows.

**Usage** — Earnings · Payouts tab (earnings.html). The dialog shell is the project's canonical modal pattern — reuse it for future modals instead of re-rolling. Already reused by the F10 manual-entry modal (`partials/manual-entry-modal.js`), which mounts the same `.payout-modal` / `.payout-dialog` shell with form fields instead of payment steps; and by `partials/restock-modal.js` / `partials/pickup-session-modal.js` / `creators.html`'s inline create-creator form. The ticket edit dialog in `create-event.html` also reuses this shell and is the first consumer of the `.payout-dialog__split` layout above.

**Do & Don't**

- ✅ Do mount via `partials/payout-request-modal.js` so every consumer gets the same dialog.
- ✅ Do keep the fee summary visible before confirm.
- ❌ Don't rebuild the dialog shell per page.
- ❌ Don't forget `.is-modal-open` scroll lock when opening.
