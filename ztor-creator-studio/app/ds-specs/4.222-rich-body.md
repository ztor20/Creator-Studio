### 4.222 Rich body（描述區塊編輯器：文字／圖片／影片區塊）

**Purpose** — 活動「描述」（5.1.6.1 §4.2 F2、5.1.6.2 F2、主規格 §7.10）。**2026-10-05 D354 改成區塊模型**（使用者裁決，取代 D335「媒體夾在文字之間」與 D340 決定八「只做粗體與清單」）：描述＝一串可排序的區塊，三種型別——**文字**、**圖片**、**影片**；每個區塊**沒有標題**、都可以拖動排序、都可以刪除；粉絲看到的順序＝區塊的順序。第一個文字區塊即原本必填的描述（至少一個文字區塊有字才算已填，只有媒體不算；文字區塊不能刪到一個都不剩）；「新增描述」加一個文字區塊。在文字區塊插入圖片或影片，媒體成為獨立區塊、排在那個文字區塊之後（已經跟在它後面的媒體之後，連續插入照順序排）。文字區塊的工具＝粗體、斜體、連結、編號清單、項目符號清單、分隔線；連結只收 http／https、粉絲端新分頁開啟〔產品待確認〕。媒體上限＝**整份描述**圖片＋影片合計 10 個〔產品待確認，原本每段 10 個〕。圖片與影片尺寸比例不限；格式與單檔大小沿用展示素材的規則（上游未定數字，本元件只照檔型分流）。說明區塊（§4.221）同輪退場、由本元件承接。

**`_layer`** · molecule（組成：Button、Textarea、Upload tile、Input、Card；區塊殼沿用 card--muted 不另寫外觀） ｜ **source tier** · Project ｜ **surface 層** · 編輯器坐在 `.field` 裡（`.form-section--outlined`，L1）；每個區塊是 `.card.card--muted`（L2 薄膜，Q66）；`.textarea`／`.upload-tile`／`.input` 各自有邊框，兩層都成立（暗色已目視驗證，亮色沿用 card--muted 與 textarea 既有的雙主題配方）。

**Anatomy**
- `.rich-body` — 容器（flex column，`gap: --sp-12`，Q103）
- `.rich-body__blocks` — 區塊清單（flex column、`gap: --sp-12`）
  - `.rich-body__block.card.card--muted[data-rb-block="text|image|video"]` — 一個區塊（`--card-pad: --sp-12`，flex 橫排、`gap: --sp-8`）：
    - `.rich-body__grip`（`.btn.btn--icon.btn--sm` ＋ `grip-vertical`）— 排序把手；按住才可拖、聚焦時上／下鍵移動一格
    - `.rich-body__main` — 內容欄（flex column、`gap: --sp-8`）
      - 文字區塊：`.rich-body__tools`（工具列，flex wrap）＝ `.rich-body__fmt`（格式鈕群組，`role=group`：`bold`／`italic`／`link`／`list-numbers`／`list`／`separator`，`.btn.btn--ghost.btn--sm.btn--icon`，`aria-pressed="true"`＝游標所在是粗體／斜體或在連結／清單裡，畫導覽類已選的淡橘 `--selected-surface`／`--selected-ink`）＋ `.rich-body__ins`（`.rich-body__sep` 1px 直線＋「插入圖片」`image`／「插入影片」`film`，`.btn.btn--ghost.btn--sm`，整份滿 10 個時 `disabled`）；`.rich-body__linkbar`（按連結鈕才展開：`.input[type=url]`＋套用 `.btn--primary.btn--sm`＋移除連結／取消 `.btn--ghost.btn--sm`＋`.field__error.rich-body__link-err`）；`.textarea.rich-body__text[data-rb-text][contenteditable]`（外觀照 `.textarea`；最小高度＝`--rb-rows` 列，第一個依宿主、其餘 2；`.is-blank` 畫 `data-placeholder`，絕對定位疊在第一行；內容只含 `p／br／strong／em／a／ul／ol／li／hr`）
      - 媒體區塊：`.upload-tile.rich-body__media[data-rb-media]`（重用上傳格：寬 `min(280px, 100%)`、`aspect-ratio: var(--rb-ratio, 16 / 9)` 照媒體本身比例；hover 出現替換／播放，上傳格自己的刪除鈕在這裡收起，刪除走區塊的 ✕）
    - `.rich-body__remove`（`.btn.btn--icon.btn--sm` ＋ `x`）— 刪除這個區塊；只剩一個文字區塊時 `disabled`
- `.rich-body__foot` — `.btn.btn--outline.btn--add.rich-body__add`（「新增描述」）＋ `.field__hint.rich-body__limit`（滿額說明「圖片與影片合計最多 10 個」，平時 `hidden`）
- 內文格式：段距 `--sp-8`、清單縮排 `--sp-20`、粗體 `--fw-semibold`、斜體、連結沿用字色加底線（不用品牌橘，STYLE-DECISIONS 維度 5）、分隔線 1px `--border`、上下 `--sp-12`
- 狀態：`.rich-body--has-media`；`.rich-body__block.is-dragging`（`opacity:.5`）；`.rich-body__block.is-locked`（單一區塊鎖定的 API 能力，D362 起 bookyay 帶入改走下方整份鎖定：工具列、連結列、刪除收起，文字 `aria-disabled` 不可編輯，比照 `.textarea:disabled` 透明底＋`--locked-field-ink`，媒體不可替換；仍可拖動）；`.rich-body--locked`（2026-10-07 D362 整份鎖定：每個區塊都 `.is-locked`，另收起 `.rich-body__grip` 與 `.rich-body__foot`——不能拖動、新增描述或插入）

**Behavior** — `partials/rich-body.js`：`window.ztorRichBody.mount(host, { blocks|text, rows, placeholder, placeholderKey, label, labelKey, proxy, maxMedia:10, feat, fmtFeat, addFeat, onChange })` 回傳 `{ el, get(), text(), media(), set(v), lock(on, opts?), add(), insert(type, fileOrSrc, row?), format(cmd, row?), move(from, to) }`，同一個物件也掛在 `host.ztorRichBody`。資料 `blocks`＝`[{ type:'text', text, html }, { type:'image'|'video', src }, …]`，**每個文字區塊各自一筆、不合併**；`get()` 略過空白文字區塊與沒有來源的媒體；`text()` 是所有文字區塊的純文字（proxy 同步它，必填與自動儲存讀 proxy）。格式：粗體／斜體用 `document.execCommand`；**清單與分隔線自己動 DOM**（Chrome 的 insertOrderedList 在段落裡會產生 `<p><ol>` 並把游標丟到清單開頭）——以文字塊的直接子節點為一塊，清單切換＝段落 ↔ 清單項、緊鄰同種清單自動併成一串，分隔線插在游標所在那一塊之後並補一個空段落；空白文字塊聚焦時先放一個空段落。格式鈕 mousedown 先擋掉以保住選取，讀回一律經 `sanitize()`（連結只留 http／https，補 `target=_blank rel=noopener noreferrer`）。連結：選字後按連結鈕→輸入列展開→Enter 套用／Esc 取消；沒選字時插入網址本身當連結文字；游標在連結裡時再按可改網址或「移除連結」；不合法網址顯示錯誤句、不套用。排序：按住把手才讓該區塊 `draggable`（避免在文字裡選字時誤拖），dragover 依游標在目標區塊上半／下半決定插在前或後；把手聚焦上／下鍵移動一格、焦點留在把手（沿用退場的 info-sections 寫法）。新增描述後焦點進新區塊；刪除後焦點交給上一個區塊的把手。貼上一律轉純文字。鎖定：`lock(true)` 只鎖第一個文字區塊＋緊接的媒體（仍可拖動）；`lock(true, { all: true })`（D362，2026-10-07，create-event 帶入與 event-detail 的 bookyay 活動都用這個）整份鎖定——每個區塊 `.is-locked`、host `.rich-body--locked`，`add()`／`insert()`／`move()` 不動作、把手 pointerdown 不開 draggable，`set()` 重畫後維持鎖定，`lock(false)` 解除。靜態工具：`toBlocks／normalize／textOf／mediaOf／hasMedia／hasText／sanitize／plainOf／textToHtml／isFormatted／safeUrl`、`fromHtml(html)`（bookyay 一段 → 一個文字區塊＋其後的媒體區塊，粗體、斜體、連結、清單保留）、`migrate(desc, infoSections)`（舊資料轉區塊：說明區塊的標題併成該區塊第一行粗體）、`fieldKeys(base, blocks)`／`textFields(base, blocks)`（翻譯欄位：每個有字的文字區塊一格，只有一格時沿用 `base`，多格時 `base~0…`；譯文放回同一個區塊、媒體不翻譯）。

**兩段式面板（檢視態）** — 2026-10-12 起（STYLE-DECISIONS Q128）：`[data-mode="view"]` 內區塊卡面與文字框都留著，文字框由 shared.css 畫成 disabled（透明底、`--view-field-ink`、`pointer-events:none`）；工具列、連結列、底部整列收起，把手與刪除是 button 隨 shared.css 收起。媒體格照常顯示、替換鈕隨 `[data-mode="view"] .upload-tile__actions` 收起。（沿革：2026-09-21～10-12 Q119 時期區塊攤平、文字塊當讀數、空白畫「—」，已退場。）

**與 Upload tile 的分工** — Upload tile 是「一個固定用途的上傳槽」（展示素材、內容檔）；本元件的媒體區塊只是描述的一部分，上傳格在這裡只當外殼，不帶槽位比例、不佔展示素材額度（主規格 §7.10「內文媒體」）。

**Token usage** — `--sp-2`／`--sp-4`／`--sp-8`／`--sp-12`／`--sp-20`（間距）、`--fw-semibold`（粗體）、`--muted-foreground`（占位字）、`--view-field-ink`（鎖定，2026-10-12 Q128 由 `--locked-field-ink` 改；檢視態「—」讀數同日隨 Q119 退場）、`--selected-surface`／`--selected-ink`（格式鈕按下態）、`--border`（直線與分隔線）；邊框、填色、圓角來自 `.card--muted`、`.textarea`、`.upload-tile`、`.input`。

**Consumers** — `create-event.html`（步驟 2 第二組「描述」`#ce-desc`，proxy `[data-ce="desc"]`；「新增描述」`data-feat="S67"`、插入鈕 `S58`、格式鈕 `S59`）；`event-detail.html`（活動內容描述 `#ed-desc`，proxy `[data-ed="desc"]`，兩段式編輯）；只用靜態工具：`event-localization.html`、`js/fan-event-page.js`（§4.215）；`design-system.html` §4.222 demo。
