**第三段（平台表現）的排版**：一塊約三分之一寬、由上而下一塊一行（2026-08-31 使用者裁示三段：「這些區塊都不要這麼寬，大概佔頁面三分之一就好」「這三個各一行」「這也換一行」）。最早是「一個類型一行、標題固定 200px 在左、清單吃剩下的寬度」，在 1440 的視窗裡把長條拉到 1000px 以上——長條的工作是比長短，只需要夠長到看得出差距；拉滿一整行之後第一名與第五名隔著半個螢幕，眼睛反而得來回掃。中途試過三塊並排，使用者裁示改成一塊一行：版稅／影視／音樂／平台觸及／觀眾在哪裡五塊，各自標題在上、清單在下（`.perf-twin` 與它底下的兩個容器都改成單欄 flex），寬度一律 `max-width: 33%`（實測 400px），五塊共用同一條左緣，第一名的長條起點因此全部對齊。bento 收成單欄、覆寫卡片自帶的 `--span-6`。**卡標題前面那顆圖示一律不畫**（2026-08-31 使用者裁示）：卡收到 480 之後，標題只有四五個字，前面掛一顆彩色方塊會比標題本身更先被看到；這一頁的節奏是「字自己排出層次」（第一屏三格、第二屏的卡都沒有圖示）。只在這一頁改——正式儀表板的同一批卡仍有圖示，那一頁的卡更大、卡的種類也更多，圖示在那裡是分辨用的。卡片本身也不吃滿頁寬（2026-08-31 使用者裁示「不要充滿頁寬」）：收到 `max-width: 480px`，清單吃滿卡的內寬（實測 438px）——清單只有 400 上下、卡面卻橫跨 1254 時，一張卡有三分之二是空的，那塊空白會讀成「這裡本來還有東西」。後兩張卡（平台觸及／觀眾在哪裡）的名稱欄改吃內容寬——預設上限 148px 是為作品全名訂的，平台與地區一律 2–7 個字，照 148 留位會把長條壓到只剩 12px。**踩過的坑**：渲染器在兩個家族之間插了一個 `.mt-16` 當間隔，留著會多一段雙倍空白（間隔改由 `gap` 給）；早先它在格線版裡還會佔掉一格、把後面的 cap／rank 全部錯開一位。**每一類只留前五名**：第六名之後在這個位置不幫忙做決定，完整清單走每張卡自己的「依項目查看」。**代價要知道**：五塊疊起來 1379px、比一屏高約六成，這一段要捲一下才看得完（第一、二段仍是一屏）。
**空的樣子分兩類（2026-09-01 使用者裁示「空畫面有很多種」）**——**全新帳號**與**有資料但很少**，不是同一件事。cheat code › 情境 › DATA STATE 因此由兩檔加到四檔（Empty ／ Only product ／ One project ／ Has Data；`empty` 與 `has-data` 的鍵刻意不動——全站三十幾頁的空狀態都掛在 `html[data-data-state="empty"]`，改鍵會一次弄壞所有頁）。

**① 全新帳號 → 引導畫面（`.canvas-start`）**：不假裝是儀表板。頂列留著（這仍是他的工作台），底下換成一句主張 ＋ 三個起點（建立項目／建立商品／建立活動，玻璃卡，目的地站上都真的存在）。**刻意不做「零值儀表板」**：對什麼都還沒開始的人顯示 `$0`、`0 位粉絲`，讀起來是「你不及格」而不是「來開始吧」。一屏不捲——左欄、右排、往下看更多、下面兩屏一律 `.dash-data-only`（實測整頁高 856 < 900，不出現捲軸）。**不畫 `.empty-card`**：那是給有卡框的頁面用的，這一頁左欄本來就不畫卡，在滿版的地上貼一張白卡會是整屏唯一浮起來的東西。**底圖那幾層一起關掉**（`__bg`／`__img`／`__scrim`／`.live-bg`）——沒有作品就沒有海報可以當地。

**② 有資料但很少 → 逐區降級，不是另一個畫面**。使用者點出的關鍵案例是**只建了商品**：右排只吃項目與活動，所以它必然是空的。右排沒有東西時**留一行**「還沒有排定的項目或活動」＋一個建立入口，不整排消失（右半邊莫名空一大塊比留一行糟，而這一行同時是這一頁唯一提示「你還可以建立項目或活動」的位置）；沒有可選主視覺時**退用商品主圖**（`ZTOR_PRODUCTS` 既有欄位，只讀）；收入／粉絲收成一張零值卡（`mode: 'zero'`，大數字＋一句話、**不畫圖**——全平的線或空的環讀起來像壞掉，只剩一張時箭頭自己收掉）；待辦留一則（不歸零：剛建立第一件東西的人，站上本來就有必辦事項在等他）；下面兩屏依狀態收放（只有商品→兩屏全收、提示跟著收；只有一個項目→第二屏成立、第三屏仍不成立）。

**兩個實作要點**：**取數層改在這一頁、不動 store**（`canvasScope`／`canvasSparse`／`canvasTrim` 讀 `<html>` 上的狀態，把餵給渲染器的資料裁到該有的量——store 是三十幾頁共用的，為了一頁的示範去改它等於把風險攤到全站）；**要掛 `ztor:devstate-changed` 重畫**（devtools 只改屬性、不會叫任何人重畫，不掛這一條在面板上切檔位畫面會停在上一種資料，看起來像開關壞了，實測踩到）。權宜與待補見 ASSUMPTIONS CANVAS-005。**主色鋪底的歸位要在 JS 做、不能只寫 CSS**：`--canvas-tint` 是 `canvasTint()` 寫成行內樣式的（當下那張海報的平均色），行內贏過任何選擇器；不清掉的話空狀態會是一片說不出來歷的橘褐（實測踩過）。該函式因此改成先看 `data-data-state`，空就移除變數，並掛上 `ztor:devstate-changed` 重算，空↔有資料切回來時顏色會回來。文案沿用既有的 `canvas.empty.title`／`canvas.empty.text`／`dash.empty.ops.cta` 三支 key，不另寫一份。

**捲動要在整頁都有效**：底圖 `pointer-events: none`（2026-08-31 使用者回報「滑鼠只有對著左邊內容滑動畫面才會往下」）——它是 `fixed` 的，滾輪落在它身上時瀏覽器找的是它的容器塊，那是視窗，而視窗這一層鎖住不捲；放行之後滾輪穿過去交給 `.main`。**頂列與右緣切換器包在同一塊 sticky（`.canvas-hero__chrome`）**（同日使用者裁示兩次：先「要 fix 住，直到下一段出現才滑掉」，再「他們應該同步往上滑不見」）：容器是 `.canvas-hero`，整塊只在第一段的範圍內釘著，第二段推到頂時被推走。**兩者一定要在同一塊裡**——sticky 的元素是被自己容器的下緣推走的，時機取決於元素自己的高度，切換器 250px、頂列 46px，各自 sticky 一定不同步（實測捲到 860 時頂列還在 4、切換器已到 -139）。切換器因此從浮層裡搬出來、自成一個渲染器（`canvas-picks`），在 chrome 裡用 `position: absolute; top: 100%` 掛在頂列底下、貼內容區右緣（不佔版面高度）。**中途曾用捲動事件算位移，那是錯的**：JS 比瀏覽器的捲動繪製慢半拍，右側會一路抖。**左欄往上捲時上緣漸消**（淡出長度跟著捲動量長、不是固定值——固定值在還沒捲時就把最上面那段蓋掉一半，使用者回報「還沒開始滑就被遮住了」）：遮罩位置由 JS 依捲動量寫進 `--rail-fade-start/-end`（遮罩是相對元素自己的框算的，「畫面頂端切到這一欄的哪裡」只有捲動量知道）；用遮罩不是蓋實色漸層——底下是照片，任何一塊實色都會留下看得見的邊。**遮罩只在 `is-scrolled` 之後才掛上**（2026-09-01 使用者回報「這個 hover 壞掉了」）：帶遮罩的元素會自成一層「背景根」，它裡面任何 `backdrop-filter` 就只取樣得到這一層自己的內容——待辦那幾則 hover 時的毛玻璃因此整個失效，畫面上只剩一層幾乎看不見的白。還沒捲動時遮罩的兩個端點都是 0px、本來就沒在遮任何東西，掛著只有副作用。**待辦事項有幾則就排幾則**（同日使用者裁示）：原本固定三則、多的看不到；現在清單撐高左欄，第一段跟著長高（`.canvas-hero` 是 `min-height` 不是 `height`），往下捲仍在第一段裡。**第一段快走完時底圖與切換器一起淡掉**（門檻＝第一段底邊剩四分之一個螢幕；原本寫成固定的「半個螢幕」，第一段變長之後那個位置還在半路上，照片消失時左欄才捲到待辦事項、看起來像圖突然壞掉。切換器跟著一起走：它是「這張照片是哪一件作品」的控制，照片不在了它就沒有對象，不跟著走會比頂列晚 128px 離開、正好壓在第二段的磚列上）：底圖是 `fixed` 的、不會自己離開，而磚列與排行這種工作內容躺在一張人臉上讀不乾淨；淡掉之後第二段就回到站上原本的星空檯面，與其他頁一致（背景要不要整段換回舊設計，使用者尚未定案）。**做成另一頁而不是改儀表板**：「不捲」是很強的限制，會逼著砍掉工作台需要的深度（分組、完整清單、往下的區塊）；兩種需求各自最佳化比一個版型兩邊遷就好。**入口 2026-08-31 由 cheat code 的 Demo 版本改成正式導覽**（使用者裁示）：側欄「總覽」下面一格「新版總覽」（`nav.dashboard-new`），原本的總覽**不取代**、兩份並存（規格 §3.2.1 沒有這一項，屬刻意的過渡狀態，記在 ASSUMPTIONS CANVAS-001）。新頁進正式導覽時要動三處：`sidebar.js` 的 `NAV` 與 `FULL_ROUTES`、`devtools.js` 的同名 `FULL_ROUTES`（兩份清單必須一致，只改一邊會讓低版本導覽藏得掉、頁內連結卻點得進去）。**原本的 `home-canvas` 版本鍵同時撤除**：留著的話，切版本用的回程守衛會把「停在別版目標頁」的人導回來源頁——正式進站的人一點新版總覽就被彈回總覽（實測踩過）；鍵仍留在兩份 `isFullBaseVersion` 白名單裡，只為了讓還存著舊 devstate 的瀏覽器不會掉進「未知版本＝限縮導覽」。1024px 以下解除高度鎖、改成上下堆疊。 | [canvas-home.css](../ds-components/canvas-home.css) |
