### 4.204 Row disclosure（可展開子列）

**Purpose** — 一筆清單項目其實是好幾筆時：母列收成一列，底下每一筆點開才出現。站上「可展開子列」這個視覺角色的**單一答案**。2026-09-03 依 `STYLE-DECISIONS.md` Q107 的裁決「要有新的」建立，取代此前並存的兩份實作——表格型清單的 `product-list.css` `__row--group`／`__row--child`（2026-08-06 為活動系列場次而建）與清單型的 `data-list.css` `__row--child`（源自專案詳情的收支小計展開列）。**2026-09-04 改寫成 L3「整組換層」**：使用者從探索頁 `lab-row-layers.html` 的五個候選裡挑定這一版，階層不再靠縮排與左緣線說，改由「這一組坐在哪一層平面上」說——收合時整列與其他資料列同層，展開時母列與它的子項一起被包進一塊 L2 薄膜面板，子項欄位與表頭嚴格對齊、零縮排。

**`_layer`** · molecule ｜ **source tier** · App ｜ **surface 層** · 收合時無樣式、與容器同層；展開時成 L2 薄膜面板（`--ztu-film` 底、`--border-soft` 描邊）；第二層（見下方 `.rowdis__frame`）用 1px `--border` 框，不再疊第三層填色

**它擁有揭露與階層那塊面，不擁有欄位** — 歸它的是三件事：把手的位置與轉向、`aria-expanded` 狀態、以及「這一組展開時坐在哪一層面」（收合同層 vs. 展開後的 L2 面板／第二層的框）。欄寬、欄數與每一格的內容仍歸它疊上去的那個容器（`.product-list__row` 的 grid 欄，或 `.data-list__row-main`／`__amount`）。所以它是與容器列**同時掛**的一層 class，不是另一種清單——這也是它能同時服務兩種容器骨架、而不必把兩套欄位模板合併的原因。

**Anatomy**
- `.rowdis__group` — 群組容器，包住「母列＋它的子項」（新增這一層 wrapper 是 L3 模型的核心）。收合無樣式；展開時（`:has()` 偵測內部把手 `aria-expanded="true"`）成為 L2 薄膜面板——`--ztu-film` 底、四周一圈 inset box-shadow 畫的 1px `--border-soft`、`--radius-lg` 圓角，面板內部的列底線轉透明。**間距**（2026-09-04 使用者於 `lab-rowdis-spacing.html` 調參定案）：`padding-block: --sp-12`、`margin-block: --sp-8`；左右一律 `padding-inline` 搭配等值負 `margin-inline`，讓面板往外長而列的 x 位置不動——表格型 `--sp-8`（疊上列自帶的 `--sp-10`，內容距面板邊 18px），清單型走 `--gutter` 的 `--sp-16`（列本身無內距，一次補到位）。兩者都必須大於 `--radius-lg` 的 16px 半徑，否則左上角的標題會卡進圓角的弧線裡
  - `--gutter`（清單型容器要加）— `.data-list__row` 本身左右無內距，由這個變體把左右內距**覆寫**成 `--sp-16`（不是疊加），讓內容距面板邊 16px、與表格型的 18px 視覺等距；一樣是負外距往外長、等值內距把列推回原位，欄位起點完全不動。表格型（`.product-list__row` 自帶 `--sp-10`）吃基準的 `--sp-8` 就夠
  - 捲動容器補償 — 表格型的清單包在 `.product-list-scroll`（`overflow-x: auto`）裡，面板往外長的 8px 會被它剪掉（左側溢出在 LTR 捲不到，圓角被切平）。`row-disclosure.css` 因此帶一條 `.product-list-scroll:has(.rowdis__group)` 把捲動容器本身往外撐同樣的 8px。寫在本元件而不是 `product-list.css`：這是本元件的出血造成的需求，跟著它一起維護、一起退場
  - `--static`（唯讀群組用）— 面板恆亮，不看把手的 `aria-expanded`。給「名單不可展開、單位一律攤開，但『這幾件屬於同一買家』要跟可展開的清單一樣清楚」的情境（scanner 的 F3 名單）
- `.rowdis__head` — 母列，須是 `.rowdis__group` 的直接子節點（`:has(> .rowdis__head …)` 這樣寫）；帶 `data-rowdis-row` 時整列可點（此時才給 `cursor: pointer`），只有把手可點的用法游標歸按鈕本身
- `.rowdis__lead` — **列首欄**（2026-09-04 · Q109）：列最前緣的一個窄格，寬 `--rowdis-lead-w`（`--sp-28`，等於 `.btn--icon.btn--xs` 的邊長）。母列在這裡放把手、子列放它在該組內的序號、沒有群組的一般列留空。詳見下方「列首欄」
- `.rowdis__num` — 子列的序號，純文字、不可聚焦；`--fs-12`／`--column-head-ink`／等寬數字，比照表頭欄名的份量
- `.rowdis__label`（選配，**2026-09-04 起正式頁面已不消費**）— 把手與「單行截斷的標題」並排的那一格。把手改站列首欄之後，標題格裡沒有要防截斷的並排元素，五個消費頁與 DS demo 都已移除。CSS 規則留著只為了凍結保存的探索頁 `lab-row-hover.html`；那批探索頁清理時本規則跟著退場。新頁面不要再用它
- `.rowdis__toggle` — 把手；外觀吃 `.btn.btn--icon`（尺寸由頁面決定），本支只加「不被壓縮」與「隨 `aria-expanded` 轉 180°」
- `.rowdis__child` — 子列；零縮排，只退一階字級與文字色（`--fs-13`／`--foreground-muted`），自帶 `[hidden] { display: none }`
- **子列不重複母列已經說過的欄位**（2026-09-04）— 群組列已經標了買家與來源，子列的同名欄位若與母列相同就留空，只有**不同**時才印出來。取貨名單的實例：同一位買家在同一場次可能同時有商品的取貨資格與活動票券（規格 5.1.5.15 F4.1「混合來源」），那時候每一件的來源才真的不一樣、值得逐列標。留空不影響搜尋——搜尋吃的是列上的 `data-*` 屬性，不是畫面上的文字。
- `.rowdis__frame` — 第二層的框（見下方「為什麼第二層是框」），1px `--border`，同樣用負外距＋等值內距讓框比裡面的列寬一點、列的 x 位置不動

**Variants**
- `.rowdis__group--gutter` — 見上方 Anatomy；清單型容器加、表格型不加
- `.rowdis__group--static` — 見上方 Anatomy；唯讀群組加
- `.rowdis__child--compact` — 清單型容器的密度：上下留白收窄（`--sp-8`）。⚠ 這個變體現在**只管密度、不管階層**——列線與組尾線都已改由 `.rowdis__group` 那塊面承擔，不是它的職責

**States** — 收合／展開（`aria-expanded` 在把手上）驅動 `.rowdis__group`／`.rowdis__frame` 亮不亮那塊面，純 CSS `:has()`，不經過 JS。**面板亮著時，母列與子列的 hover 改由本支定義**（見下方「面板內 hover」），取代容器（`.product-list__row`／`.data-list__row`）原本提供的通用 hover；面板外的列與收合狀態的母列仍吃容器提供的通用 hover，本支不介入。focus-visible 由 `.btn` 提供，本支不另定義。

**Token usage** — `--sp-28`（列首欄寬，經 `--rowdis-lead-w`）／`--fs-12`／`--column-head-ink`（子列序號）／`--sp-4`（把手與標題的間距）／`--sp-6`（`.rowdis__frame` 的負外距＋內距）／`--sp-8`（compact 的上下留白、`.rowdis__group` 的上下留白）／`--sp-10`（`--gutter` 的負外距＋內距，對齊表格型容器的列內距）／`--fs-13`（子列字級）／`--foreground-muted`（子列文字）／`--ztu-film`（展開面板底色）／`--ztu-glass-strong`（面板內列 hover 底色）／`--border-soft`（面板描邊）／`--border`（第二層框）／`--radius-lg`（面板圓角）／`--radius-md`（第二層框圓角）／`--duration`／`--easing`（把手轉向、面板內動作選單 opacity 過渡）。無裸值。

**列首欄：展開在最前緣、`⋯` 在最末端（2026-09-04 · Q109，指名參考 Braintrust）** — 此前把手貼在標題文字後面（列的中段），與列尾的 `⋯` 動作選單讀不出「這是同一列的兩個控制項」，而且每一組的標題長度不同時把手的 x 位置跟著浮動，一整欄的把手站不成一條線。使用者看過 Mobbin 上八個實例（Midday／Evernote／Xero／Salesforce／Braintrust／ClickUp／Asana／Zoho CRM）後裁定改採業界一致的做法：**展開控制在列的最前緣、`⋯` 在最末端，兩者分踞兩端、從不相鄰**。

- **這一欄從來不空著，也從來不是「有分組才長出來」** — 同一張表裡的每一列都有它，包括沒有群組的一般列（Braintrust 亦然）。所以它是欄位版面的一部分：**表頭也要跟著多一欄**，否則表頭與資料列會差一格。
- **三種內容** — 母列放 `.rowdis__toggle`（chevron）／子列放 `.rowdis__num`（它在該組內的序號，1 起算）／一般列留空。
- **寬度歸元件** — `row-disclosure.css` 在 `:root` 定義 `--rowdis-lead-w: var(--sp-28)`，消費頁的 `grid-template-columns` 與格子本身都引用它，兩邊不各寫一次數值。28px 不是隨手取的：它等於 `--control-h-xs`（`.btn--icon.btn--xs` 的邊長），欄寬剛好包住把手。變數掛 `:root` 是因為軌道寫在消費頁的 grid 容器上，那個容器不在 `.rowdis__lead` 的祖先鏈上讀不到元件自己的 class（同一手法見 `preview-panel.css` 的 `--preview-w`）。
- **序號是資料、不是控制項** — 純文字、`tabIndex` -1，鍵盤 Tab 不會停在上面；這一欄唯一的可聚焦元素是母列的把手。
- **窄框（≤760px）不藏這一欄** — 把手是鍵盤使用者唯一的展開入口（整列可點只服務指標與觸控），所以堆疊版面裡它仍釘在第一列第一格，其餘欄位往右順移一軌。
- **群組列的其餘欄位大多留空，只在標題下方留一個彙總**（「1 of 5 collected」「3 dates」）——照 Braintrust 的做法，群組列講整組的事，逐筆的值歸子列。

**只在表格型容器套用（2026-09-04 判斷）** — `pickup-detail.html`（名單）與 `events.html`（系列場次）兩個表格型消費頁已導入。三個清單型消費頁維持把手現況，理由各自不同：`order-detail.html` 有兩層展開，組合成員那一列同時是第一層的子列（該有序號）與第二層框的母列（該有把手），一個列首格放不下兩種角色，Braintrust 的單層模型沒有答案；`project-detail.html` 的列首已經是 ＋／−／＝ 的記號晶片（那一列的身分標記），而把手貼著金額擺才讀得出「這個數字展開成它的組成」；`scanner.html` 的名單是 `--static` 唯讀恆亮、根本沒有把手可搬，列首同樣被記號晶片佔著。三者都不是欄格線結構、也沒有表頭可對齊，硬套只會多一欄空格。

**為什麼一圈邊用 inset box-shadow 畫、不用 border** — `border` 會佔版位，母列與面板外的資料列會因此差 1px、欄位對不齊；`box-shadow` 疊在既有版面上不吃版位，欄位起點因此一格都不動。

**為什麼面板內部的列底線轉透明** — 邊界已經由那塊面在說，裡面再畫幾條線就變成兩套說法。用後代選擇器（不是 `>` 直屬）才涵蓋第二層框裡的列，限定在 `.rowdis__head`／`.rowdis__child` 兩個角色上、不誤傷列裡其他有邊框的東西（例如 `.data-list__icon` 的 1px 晶片框）。

**為什麼第二層是框、不是第三層填色** — 縮排退場後第二層需要另一個訊號。依既有規則辦：`ds-components/nest.css` 檔頭明文「只有兩層填色（L1 卡片 `--card`／L2 薄膜），第三層以後不再疊填色、改用 1px 邊框表達層級」。`order-detail.html` 的「訂單品項 → 組合成員 → 成員各自的領取單位」正好落在這一格——不是新規則，是那條既有規則在這個情境的套用。

**為什麼狀態放在按鈕上而不是母列上** — 按鈕才是可聚焦、可用鍵盤操作的那個元素；`aria-expanded` 放在它身上，Enter 與 Space 由原生 `<button>` 免費提供，讀屏也讀得到狀態。母列只是點擊區域的擴大。

**面板內 hover（H1 提亮一階＋H4 動作浮現，2026-09-04）** — 面板亮著時（展開，或 `--static` 恆亮），母列與子列的 hover 改吃本支的規則，取代容器（`.product-list__row`／`.data-list__row`）原本提供的「浮起玻璃卡」通用 hover（`STYLE-DECISIONS.md` Q34）。這是 Q34 的範圍例外，見 Q108；面板外的列、以及收合狀態的母列，仍吃 Q34 的通用規則、完全不變。

- **H1 提亮一階** — hover 時底色在面板底 `--ztu-film` 之上再提亮一階（`--ztu-glass-strong`）。不浮起、不模糊、不加陰影；`--gutter` 的清單型列自 2026-09-11 起有自己的內距與圓角（列往外長 `--sp-8` 再用等值內距推回、`--radius-md`，文字 x 不動）——使用者指出亮面「沒有 padding 也沒有圓角」像一條貼邊的方塊，要跟面板的內距與圓角一起看——同一平面上的暫時強調，並明確中和容器 hover 帶來的 `position:relative`／`backdrop-filter`／`box-shadow`。
- **H4 動作浮現** — 同一個 hover 讓該列右側的動作選單（⋮ kebab，`.dropdown` 元件）由 `opacity: .5` 提到 `1`；`:focus-within`（掛在 `.dropdown` 本身）與 `[open]` 也同樣不透明，鍵盤 Tab 到選單或選單已展開時都看得見，不是只有滑鼠使用者才看到。
- **母列子列同一階** — 兩者吃同一條規則，不分強弱。母列的可點性已由手型游標與 chevron 交代，用亮度差分強弱既讀不出來，又要多發明一個「半階」新值、多一條要維護的規則。

**為什麼面板內不能沿用通用的浮起玻璃卡（三個矛盾）**
1. **方向反了** — 玻璃卡底色 `--ztu-glass-bg`（5% 白）比面板底 `--ztu-film`（8.6% 白）更暗，hover 讀起來是往下沉、不是浮起，違反 Surface-Layer Contrast「淺灰填只在比自己亮的底上成立」。
2. **模糊沒有意義** — `backdrop-filter` 在面板內只會取樣到面板自己（同一教訓 `ds-components/nest.css` 檔頭已記過一次）。
3. **語意打架** — 一列浮出面板，跟「這一組是同一個平面」矛盾。

探索過程見 `lab-row-hover.html`（基準＋ H1–H5 六個候選）；裁決紀錄見 `STYLE-DECISIONS.md` Q108。

**✝ 退場（2026-09-04，縮排模型整組退場）** — `--rowdis-indent` 變數、`.rowdis__child--level-2`／`--level-3` 兩個縮排刻度變體、`.rowdis__child` 的 `padding-inline-start`、`.rowdis__child::before` 的 2px 左緣階層線、`--compact` 底下原本承擔階層的 `border-bottom: 0` 與組尾線，一併退場，CSS 原處留墓碑。退場原因：縮排把子項的欄位推離表頭，欄位對不齊；左緣線與組尾線是「用幾條線拼出一個群組」，邊界因此永遠是暗示而非事實。連帶：`shared.css` 的 `.pd-deep` 曾覆寫 `--rowdis-indent` 對齊 44px 文字起點，隨本次一併移除（零縮排之後沒有要對齊的東西）。依據：`STYLE-DECISIONS.md` Q107（元件的存在）＋ 2026-09-04 L3 裁決（本次的模型）。

**JS module — `js/row-disclosure.js`**

- **用途** — 展開／收合的互動。此前三個頁面各寫一份（`pickup-detail.html` 的 `data-group-toggle`、`order-detail.html` 的 `data-od-toggle`、`scanner.html` 的頁內函式），收斂後消費頁只寫 markup。面板本身純 CSS `:has()` 驅動，不經過這支 JS——JS 只切 `aria-expanded` 與子列的 `hidden`。
- **對外契約（data-attribute）** — `data-rowdis="<gid>"` 掛在把手（必須是 `<button>`，自帶 `aria-expanded`）；`data-rowdis-child="<gid>"` 掛在每一條子列（初始態由 markup 的 `hidden` 決定）；`data-rowdis-row`（選配）掛在母列＝整列可點，列內的連結、選單與其他按鈕一律放行。
- **對外契約（API）** — `window.rowDisclosure.init(root, { onToggle })`（登記容器與 callback，給「展開只是可見性其中一個條件」的頁面重算用）／`set(head, open)`／`toggle(head)`／`sync(root)`／`isOpen(head)`。
- **點擊走 document 級單一委派** — 動態渲染的列不必重新綁定；`init()` 只登記容器，不會再加第二顆監聽器（加了會讓同一次點擊被處理兩次、等於沒切）。
- **Consumer 頁** — `pickup-detail.html`（買家分組，帶 `onToggle` 重算搜尋與狀態篩選）· `order-detail.html`（品項展開單位、組合展開成員、成員再展開單位，兩層）· `events.html`（系列場次，帶 `onToggle` 重算「子列可見＝母列過篩選且展開」，搜尋中一律攤開）· `project-detail.html`（收支小計，`init(deep)` 即可，無 callback）。`scanner.html` 只用 CSS 的 `--static` 面板，名單唯讀、不展開，不載這支 JS。

**Dependencies** — 組成：`.btn`（`--icon`／`--xs`／`--sm`）、`.ztor-icon`（`chevron-down`）。疊在：`.product-list__row`（§4.27）、`.data-list__row`（§4.22）——子列的字級明寫覆蓋這兩支的標題 class（`.product-list__title` 自帶 14）。第二層是否用框（不再疊填色）依 `ds-components/nest.css` 的既有規則（見上方「為什麼第二層是框」）。分組清單再疊上篩選與搜尋之後的行為（子列跟著母列過篩選、搜尋中一律攤開）是 Pillar 5 的組合規則，見 §5.1.3。
