### 4.3 Badge / Status pill

**`_layer`** · atom — Read-only soft "category-tag" pill: flat tinted background + saturated same-hue text, rounded-rectangle corners, **no status dot, no ring**. Serves both live-status (payout / transaction / live·draft) and category/taxonomy (IP type, fan tier) roles. Plus an inline metric pill for prose.

> **2026-06-05 restyle:** moved from a dotted, ringed, full-pill capsule to the flat soft-tag look (per request, to match a Notion/Airtable-style select tag). `.badge__dot` is now `display:none` (markup kept for back-compat, renders nothing), corners are `--radius-md`, the hairline ring is removed, and a purple `--accent` variant was added.
>
> **2026-07-10:** `badge__dot` 已棄用（`display:none`），markup 不再需要——design-system.html 的 Badge demo（Status pill 表格 7 處）已移除 `<span class="badge__dot">`；其餘元件 demo 裡沿用 badge 的既有 markup 未動（保留不影響視覺）。

**Token usage** (→ Pillar 2 Role)

- neutral bg `--ztu-film`（2026-08-28 換裝，原 `--muted`） + `color-mix` of `--status-success` / `--status-error` / `--status-info` / `--status-accent` / `--primary` against `--card` (tints track light/dark automatically) · text = matching hue tokens (`--status-*` / `--primary` for orange) or darkened for warning / `--foreground-muted` for neutral · radius `--radius-pill`（2026-08-28 換裝，原 `--radius-md`，badge） / `--radius` (ztor-badge) · font `--font-ui` · **no box-shadow**

**商品與組合的狀態徽章是推導出來的，不是欄位（spec §7.14 · D241，2026-09-04）**

上架品項有三個互相獨立的開關（上架 `listed`／顯示於商店 `shown`／開賣 `saleStart`–`saleEnd`）再加一個可售量 `qty`，徽章是它們算出來的結果。八態的推導由 `js/listing-state.js` 的 `deriveStatus(entity, ctx, now)` 持有，**優先序固定、各頁不得自行調換**：

| 主徽章 | tone → class | 推導條件 |
|---|---|---|
| Draft／未完成 | neutral → `.badge--neutral` | 尚未發布；沒有開關、沒有連結，池裡還沒有這件商品 |
| Unlisted／已下架 | neutral → `.badge--neutral` | `listed` 關著，或上架日期與時間未到，或下架日期與時間已過。粉絲端頁面顯示「已下架」、不能購買（D415）；非公開連結下架後能否開「已下架」頁〔產品待確認，D415〕 |
| Hidden／已隱藏 | neutral → `.badge--neutral` | 已上架但 `shown` 關著；商店找不到，持非公開連結仍可買，也能被組合包帶著賣 |
| Ended／販售結束 | neutral → `.badge--neutral` | 停售日期與時間已過；不會自己回來，要改停售日期與時間 |
| Sold out／售罄 | error → `.badge--error` | 該販售管道 `qty === 0`。鎖定的販售管道賣完鎖定量即售罄，池裡還有未鎖定的數量也一樣 |
| Coming soon／即將開賣 | info → `.badge--info` | 開賣日期與時間在未來；看得到、看得到時間，不能買 |
| Low stock／急需補貨 | warning → `.badge--warning` | `qty` 已達或低於低庫存門檻（不限量的池不會走到這裡） |
| Live／販售中 | success → `.badge--success` | 上架＋顯示＋在販售窗口內＋有貨 |

- **`hidden` 排在 `ended` 與 `soldout` 之前**：清單列只有一個徽章位置，「商店裡找不到」是比較該先講的事。細節頁擺得下兩顆，改叫 `deriveFlags(entity, ctx, now)`——它回 `{ status, hidden }`，`status` 跳過 hidden 那一層，`hidden` 旗標另掛第二顆徽章（例：售罄 ＋ 已隱藏並排）。
- **class 走 `ListingState.badgeClass(status)`、文案走 `status.*` 這組 i18n key**（`shop.status.draft`／`live`／`coming`／`ended`／`soldout`／`low`／`hidden`／`unlisted`）。舊的 `e-shop.status.*`、`e-shop.row.*`、`product-detail.badge.*`、`bd.badge.*` 保留到各頁改版為止，改完再一併清。
- **`qty` 是「哪一個販售管道」的可售量**：單售用 `channelQty(product, 'single')`、某個組合包用 `channelQty(product, { bundle: id })`、組合包自己用 `bundleQty(bundle, productsById)`。同一件商品在不同販售管道的狀態本來就不同，元件層不猜。
- tone 只用既有的五個變體，不為這八態新增顏色。四個 neutral（draft／unlisted／hidden／ended）是刻意的：它們都是「現在不賣，但沒有異常」，用同一個安靜的殼，差異由文字承擔。

**Usage** — Surface a state or a category at a glance (payout status, transaction state, live/draft; IP type, fan tier). Avoid for clickable filters — use Chip (§4.5) — and never as a button.

**Do & Don't**

- ✅ Do pick a variant hue that matches the meaning (status or category).
- ✅ Do reserve `--orange` for the highlight state, not generic info.
- ❌ Don't make a badge clickable (it has no interactive state).
- ❌ Don't invent ad-hoc status colors — use the variant tokens.


**Code example**

```html
<span class="badge badge--success">Available</span>
<span class="badge badge--accent">Reference</span>
<span class="badge badge--outline">Paid</span>          <!-- 帳的搬動：提款／作廢沖銷／扣款 -->
<span class="badge badge--outline-danger">Failed</span>
<span class="ztor-metric-pill"><svg class="ztor-metric-pill__icon">…</svg>1,204 fans</span>
```
