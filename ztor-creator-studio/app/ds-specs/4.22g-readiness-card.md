### 4.22g Readiness card

**`_layer`** · molecule — 上架前就緒檢查卡（規格 5.1.5.2 §4.4「Ready to sell?」）。逐項列出要備齊的內容：已備齊打勾（`--status-success` 實心）、未備齊空心圈；卡底 banner 統計還差幾項，全部備齊轉綠字「Ready to sell!」。

**Class API**

| Class | Effect |
|---|---|
| `.readiness` | 玻璃卡容器（2026-08-28 換裝：`--ztu-glass-bg` ＋ `backdrop-filter: blur(var(--ztu-blur-glass))` ＋ 1px `--border`，原 `--card` 實色＋`--shadow-card`）；懸浮版 `.readiness__pop .readiness` 退回 `--popover` 實色（浮層一律不透明，見 §3.2） |
| `.readiness__list / __item(.--done)` | 檢查項；done 態文字轉深、mark 轉綠勾 |
| `.readiness__mark` | 狀態圈（空心 inset 邊框／done 實心綠勾） |
| `.readiness__banner(.--ready)` | 卡底統計；ready 轉 `--status-success` |
| `.readiness__chip(.--ready)` / `.readiness__anchor` | `__pop` 的兩種掛法：chip＝footer 常駐就緒指示；anchor＝直接包住主動作按鈕、hover／focus 才浮出檢查卡（anchor 的 hover 目標是外層容器而非按鈕，因為未備齊時按鈕 `disabled`、部分瀏覽器不送滑鼠事件給它） |

**Usage** — create-product 依類型換檢查項（實體 5／數位 5；拍賣已獨立成 create-auction，8 項）；待補項標 pending、不擋上架。建立流程共用。檢查項與硬性必填的對應見規格 §4.6（D026 待協調）；實體型的「1+ gallery images」2026-08-31 依 D226 撤除。

**Token 例外** — done 勾用 `#fff`（白勾置於 `--status-success` 綠底上），屬固定前景白、非主題色。

**CSS** — [`readiness.css`](../ds-components/readiness.css)
