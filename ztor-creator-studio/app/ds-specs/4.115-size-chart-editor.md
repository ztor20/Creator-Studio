### 4.115 Size chart editor

**Purpose** — 兩個維度都能被使用者增減的資料表（spec 5.1.5.5 F7.2 · D171）。用在商店設定的商店尺寸指南與建立商品的商品專屬指南（同一支編輯器，D211）：列是尺碼、欄是量測項，而「這件衣服要量哪幾個部位」本來就因商品而異，所以欄不能寫死。站上其他表格的欄位都是已知固定集合，這是第一支欄數由使用者決定的表。

**Q112（2026-09-11）**：`--radius-xl` 外框內的列左右內距下限 `--sp-16`（首欄文字不壓在圓弧上；右側 icon 欄不動）。

**Anatomy**
- `.sce` — 外層；表格與底部新增鈕之間的 8px 間距
- `.sce__wrap` — 1px `--border` 外框＋`--radius-xl`＋`overflow-x:auto`（窄視窗橫捲，沿用 `.variant-table-wrap` 的做法）
- `.sce__table` — **欄定義的唯一住處**：`--sce-cols` 宣告在這一層，`__head` 與每一個 `__row` 都讀它
- `.sce__head` — 表頭；`--muted` 底、`--column-head-ink` 字，不畫下框線（Q41）
- `.sce__col` ＞ `.sce__col-label`（固定欄，如「尺碼」）或 `.sce__col-input`（可改名的量測欄）＋ `.sce__col-remove`
- `.sce__row` ＞ `.sce__cell`（`.sce__cell--size` 為首欄的識別格，字重較重）＋ `.sce__row-remove`
- `.sce__foot` ＞ `.sce__add` — 底部虛線新增鈕（加列／加欄各一顆）

**為什麼欄定義只放一個 CSS 變數** — `__head` 與每個 `__row` 是各自獨立的 grid container，欄寬要一致就只能吃同一份 `grid-template-columns`。宣告在 `.sce__table` 上、下面都用 `var(--sce-cols)`，JS 增減欄時只要改這一個變數＋每列補一格 DOM，不必動 CSS。做法取自 `.bmx` 的 `--bmx-cols`。

**首欄一定要用固定寬，不能用 `max-content`** — 表頭與資料列是不同的 grid，`max-content` 會在各自的 grid 裡分別解析：表頭那格只有一行文字（算出 72px），資料列那格是輸入框（算出 152px），兩邊就錯開了。實測踩過，改成固定 `112px`。

**為什麼不擴充 `variant-builder` 的 `.variant-table`** — 那支的欄寬是三套寫死的 `grid-template-columns` 字面值，服務「規格組合＋價格＋庫存＋SKU＋成本」這組已知固定欄位。要讓欄數變成使用者可控，等於把它的 grid 模型整個換掉，那已經不是擴充。視覺語彙（外框、`--muted` 表頭、格子用 `.input`、列尾刪除鈕）仍然照抄，兩張表在站上讀起來是同一族。

**刪除鈕預設不顯示** — 欄與列的刪除鈕都是 `opacity:0`，hover 該欄／該列或 focus 才浮現（同 `.bmx__remove`、`.variant-row__remove`）。理由是兩個維度都可能長，常駐一整排刪除圖示會蓋過資料本身、也容易誤點。表頭的量測欄名輸入框同理：平常收起邊界（`.input` 的邊界是 `box-shadow` 環，所以是清 `box-shadow` 不是改 `border-color`），hover 或聚焦才顯形。

**`.sce-block__tabs`（2026-08-21 · D214）** — 尺碼制（國際／US／EU／JP）是同一張尺寸表的四個分頁，不是四張表：一列＝一個實體尺碼，四種標示法只是它的四個名字，所以每一制各存一份**尺碼欄**、量測值四制共用。分頁沿用 `.tabs`（`--count-plain`），計數欄位借來標「這一制還有幾格沒填」；`.tabs` 預設的 20px 下外距在這裡歸零，間距改由下方那句說明承接。切換與逐制資料在 `partials/size-guide-modal.js`。

**`.sce-block__head`（2026-08-20 · D212）** — 子塊抬頭：左邊標題＋說明，右邊放屬於這張表的控制項。目前唯一的用例是尺寸表右上的量測單位（公分／英吋）——那兩個值是絕對換算，切換是「換一種看法」而不是另外填一份資料，所以它跟著表走、不是一條獨立設定列。換算以公分為真值（`cell.dataset.cm`），畫面依單位算出來顯示到小數一位；不拿畫面數字反覆相乘，來回切兩次就會四捨五入漂掉。尺碼制（國際／US／EU／JP）不適用這個做法——各國尺碼是慣例對照、不是換算公式，它留在上面當設定列。

**`.sce-block`（2026-08-20 由 store-settings.css 搬來）** — 編輯器裡各子塊之間的呼吸（尺寸表／身高體重／量測方式／版型建議／免責）：上下 20px 內距＋一條 `--border-soft` 上分隔線，不各自畫框（Q32）。彈窗裡第一個子塊不畫上線（head 已經有一條）。原名 `.ss-spec-block`、住在 `store-settings.css`；編輯器抽成共用 partial 之後建立商品也會用到它，只住在商店設定那一支就不成立了。

**指南切換（2026-08-21 · D216）** — 從建立商品的「點擊查看」開進來時，彈窗頂端多一列「看哪一份」（下拉 `.select`＋`.sg-picker__select`，`opts.guides` 有幾份就列幾份——份數會長，segmented 撐不住），每一份的整份表單各自快照、換回來原封不動；該模式下名稱欄不出現（切換列已經是識別）。從商店設定點單一份進來時不帶 `guides`，行為不變。

**編輯器是共用 partial（2026-08-20 · D211）** — `partials/size-guide-modal.js` 持有整個彈窗的 markup 與互動（`window.ztorSizeGuide.open()`／`.close()`），兩個地方在編同一張表：商店設定的商店尺寸指南、建立商品的商品專屬指南。差別只有一個參數 `showName`——商品專屬那份沒有名字（它只屬於那一件商品）。彈窗殼沿用 `.payout-modal`／`.payout-dialog--wide`。

**Dependencies** — `.input`（格子與欄名）、`.ztor-icon`、`.payout-modal`／`.payout-dialog--wide`（彈窗殼）、`.spec-row`（量測方式逐列）。增刪列／欄、`--sce-cols` 同步與欄名改動時的 aria-label 同步由 `partials/size-guide-modal.js` 處理（2026-08-20 起，此前是 `store-settings.html` 的行內控制器）。消費頁：`store-settings.html`（spec 5.1.5.5 F7.2）、`create-product.html`（spec 5.1.5.2 §4.1 F2 · D211）。

**Consumers** — `store-settings.html`（spec 5.1.5.5 F7.2 尺寸表與身高體重參考，同一支元件兩個實例；身高體重那張欄固定、不給欄刪除鈕）。
