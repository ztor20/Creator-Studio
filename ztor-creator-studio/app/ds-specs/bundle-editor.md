**分段版型 `layout: 'sections'`（2026-08-13 活動專用建立 → 2026-09-01 通用化，現為所有消費頁的版型）** — 清單列＋兩步彈窗、彈窗內一段一張分卡；票種／場次相關分卡仍是活動變體獨有：

  1. 內容（適用票種／商店商品／額外權益）
  2. 販售設定（原價合計 → 折扣 → 粉絲實付，一列算完；販售上限）
  3. 呈現方式（名稱＊／簡短說明／封面圖同一列）

- **為什麼倒過來**：預設版型是名稱＊ → 說明 → 封面圖 → 內容 → 數量 → 權益 → 定價，等於要創作者先替一個還沒有內容的盒子取名字、上傳封面。活動套組腦中的句子是「VIP 票 ＋ 巡演 T 恤，賣 4,800」——先有內容才有名字與價格。名稱移到最後並自動擬建議名（票種名 ＋ 第一件商品），必填欄從空白格變成確認。
- **票種挑選器**：票項可多帶 `group`（哪一場）／`kind`（哪個票種）／`qty` 三個選配欄位，帶了才啟用對應能力——依場次分組（組頭可整場全選）、一排跨場次的票種捷徑、選完收合成 chip（`.bd-chosen`）。實測三場 × 兩票種時預設版型一張空卡 1,464px、視窗只有 944px；分段版型收合挑選器後降到約 1,065px，且不再隨場次數膨脹。
- **`scope`（多場才問）**：`shared`＝一組通用所有場次；`per`＝每場各一組——只挑票種，送出時在每一場各展開成一組（`commit()`），省掉手動複製 N 次。
- **三步彈窗（2026-08-13 使用者指示「把 1,2,3 分成步驟」）**：三段改成真的三步，用站上既有的分步彈窗契約 `.payout-view`（請款彈窗就是三步）。一次只渲染當前那一步、不留 `[hidden]` 的兄弟——同一個 `data-bd-f` 出現三份會讓焦點還原與就地同步抓錯節點；`.payout-view` 這一層仍要留著，dialog 的 head／body／foot 釘住是靠 `.payout-dialog > .payout-view` 那條規則傳下去的。步驟指示器用建立流程頂部同一支 `.progress-stepper--segmented`（`.bd-steps` 只負責它在 dialog 裡的位置與間距），不另做小圓點；步驟標題因此由進度條承擔，body 不再重複段標題。**第 1 步要挑到票才走得下去**——「一組至少含一張票」本來就是 `isValid()` 的條件，把它前移到步驟閘門比讓人填完三步才在最後被擋下誠實。走過的步驟可以點進度條跳回去，還沒到的不給點。
- **六張分卡、每一段一個決定（2026-08-13 第二輪，使用者指示「參考建立商品」）**：場次對應／組合內容／販售設定／販售數量／基本資料／封面圖。三處對齊建立商品的既有做法——
  - **折扣改成開關**（`.control-group` ＋ `.switch`，同「折扣設定」）：多數組合包不打折，把折扣欄永遠攤在算式裡等於預設每一組都要回答一個多數人不需要回答的問題。關著時算式只有兩段（原價合計＝粉絲實付），開了才長出中段。關掉會一併清值，避免「看不見卻仍在算」。
  - **販售數量改成不限量／限量二選一**（`.segmented.radio-cards`，同「庫存」的 Edition）：原本是一個「留空＝不限」的數字欄，留空是安靜的預設、讀不出「我選了不限量」，而且空欄與 0 在畫面上長得一樣。限量才出現上限欄且為必填。
  - **「呈現方式」拆成「基本資料」與「封面圖」兩張**（同「商品資訊」與「展示它」）：名稱／說明與圖片是兩件事，混在一張卡裡右邊那格圖看起來像名稱欄的附屬。原標題也太白話，改用站上既有的欄目命名。
- **「每場次各一組」列出實際會建立哪幾組（2026-08-13）**：選了模式卡只說「會長出 3 組」，沒說是哪 3 組。`secPerHTML()` 照 `commit()` 的展開邏輯算出真正的清單、逐場列出。還沒挑票種時分卡照樣出現、只把說明句換成引導，整塊消失會接不上剛剛那一下點擊。同輪修掉 `commit()` 的一個漏洞：原本展開時對每一個場次都生一顆組合包，某一場沒賣到那個票種時會生出空的一顆；改成先濾掉沒有票可放的場次，展開結果因此與這張分卡逐列相同。
- **兩塊表格化（`.bd-tbl`，2026-08-13 使用者指示「第二個要和第一個一樣是一個 section，並且兩個都要表格化」）**：「會建立的組合包」從票種分卡裡的一段欄位升格成自己的 `.bd-sec`（它回答的是「按下完成之後會多出哪幾組」，與「這一組賣哪一種票」是兩個決定）；它與「適用場次」的內容一起從引用列（`.fc-ref`：縮圖＋名稱＋一行次要資訊）改成表格。原本一列的事實全串在同一行字裡——「$3800 · 共 150 張」要讀句子才分得出哪個數字是價格、哪個是張數，多列之間也對不齊；表格把每一種事實各給一欄，同欄數字上下對齊（`tabular-nums` 右對齊）就能直接比大小。每列一律一個票券圖示是純裝飾（分卡標題已經說了這裡列的是票），一併拿掉。<br>欄位：適用場次＝勾選框／票種／售價／張數，依場次分組（`.bd-tbl__group`，組頭帶「全選本場次」）；會建立的組合包＝組合包名稱／內含票種／票券原價，名稱寫的是展開後的完整名字（`stem · 場次名`），也就是按下完成後清單上真的會出現的字。<br>表頭沿用 2026-07-31 使用者裁示的全站列表慣例（不畫底色帶、不畫下框線，只有 `--column-head-ink` 的欄名）——`.restock-table__head` 那種 `--muted` 底色帶不能照抄，L2 分卡裡再壓一條暗底會變成往下沉一階，與 Q66 的疊層方向相反。列與列之間的分隔用相鄰選擇器（`.bd-tbl__row + .bd-tbl__row`），所以組頭底下的第一列不會被劃線、組頭也就不會被讀成某一列的底線。墓碑：`.bd-grp`／`__head`／`__name`／`__all` 併入 `.bd-tbl__group`。
