### 4.51b Progress timeline

**Purpose** — 把一段交付故事畫成同一張圖：答應做什麼、做到哪、一路上跟支持者說了什麼。為項目詳情的「進度」分頁而建（spec [5.1.2.2-專案詳情.md](../../../documents/5.1.2.2-專案詳情.md) §2.2.10 v3.0、D193、D194）。2026-08-17 由「可手動排序的里程碑清單」改寫成**由真實日期驅動的單軸時間流**：未來在上、今天在中、過去在下（D194 使用者裁決）。日期放進左側日期欄（gutter），是為了讓軸線保持一條直線，也讓「哪一天發生什麼」在掃視時對得起來。

**Anatomy**
- `.ptl` — 容器；定義 `--ptl-dot`（軸點直徑 20px，窄螢幕 24px；2026-08-18 前是 28px）、`--ptl-date`（日期欄寬 64px）與 `--ptl-gap`；這幾個變數一次定義軸點欄寬、日期欄寬與軸線左邊界，所有列都靠它們對齊
- `.ptl__node` — 軸上一列；grid 三欄＝日期欄／軸點／內容。`::before` 是連到下一列的軸線
- `.ptl__date` — 日期欄（gutter）。必須 `align-self: start`，否則日期會置中到整列的中線。**跨年的日期年自己一行**——**這一條是規格約束、不是本層的選擇**（spec [5.1.2.2](../../../documents/5.1.2.2-專案詳情.md) §2.2.10「日期與時間的型別」，2026-08-20 D209）：日期欄的日期不得在數字中間被折斷（欄寬只有 64px，「2025/12/16」會斷成「2025/12/1」＋「6」，被折斷的數字要讀兩次才知道是幾號），跨年時年獨立成行、哪一行是年跟隨該語言的日期寫法。本層只決定行高、字級與對齊。呼叫端輸出兩個 `.ptl__date-part`，順序照該語言的日期寫法（中文年在上、英文年在下）；第一行沿用 `--ptl-line` 行高維持與軸點、標題同線，第二行收到 `--lh-comfy`，兩行才讀成一個日期
- `.ptl` — 整條軸。`max-width: 760px`（2026-08-18）：每一列都是「日期＋一行標題」，滿版之後標題與右端動作之間會留下一大片空白
- 生命週期事件節點（2026-08-19，D202）：開始收單／達標成功／送審／審核結果等系統事實，與「項目建立」同款——`.ptl__node--start` ＋ `pmark--ghost` 空心小點，只有名字與日期，無動作無內容
- `.ptl__dot` — 軸點。長相整組交給 [Progress mark](./progress-mark.md)（呼叫端掛 `.pmark.pmark--{state}` ＋ 對應字符），本檔只留「這顆點坐在軸上的哪裡」：對齊與 `z-index`（不壓過軸線的話，線會從點的正中間穿過去）。垂直位置由 `calc((--ptl-line - --pmark-size) / 2)` 算出，圓心對到標題中線；今天那顆放大時對齊自動成立。2026-08-18 撤除（墓碑）：`.ptl__node--{done,doing,alert,today,day,start} .ptl__dot` 的顏色／尺寸規則，以及那支只服務軸點的 `ptl-mark` 尺寸變數（改讀 progress-mark 自己的 `--pmark-size`）
- `.ptl__body` — **不裝卡**（2026-08-18 A2：卡的邊界比軸線還搶眼，而時間軸要說的是「這些事是連著的」）；分行交給一條極淡線（`--border` 的 40%）。＞ `.ptl__head`（`.ptl__late` ＋ `.ptl__name` ＋ `.ptl__vis` ＋ `.ptl__acts`；`.ptl__toggle` 只用在按天收合的 `--day` 列，里程碑不折疊——逾期與名稱同級且排在名稱之前、可見度 12px、動作收成一顆 kebab（`⋯`，`.dropdown` 原生 `<details>`）靠右常駐 55% 不透明度，展開後才是「編輯／刪除」兩個帶文字的選項——2026-08-18 使用者裁決：兩顆圖示鈕常駐時，一條軸掃下來是一整排鉛筆與垃圾桶，它們卻是這條軸上最少用的東西；選單開著時觸發鈕維持全亮，面板 `min-width` 收到 148px）／`.ptl__lede`（`__lede-num`）／`.ptl__meta`（`.ptl__meta-item`）／`.ptl__note`（`.ptl__note-body`）／`.ptl__acts`／`.composer`（見 Composer 元件）／`.ptl__updates`
- `.ptl__fold` — 被收合鈕收起的那一段；父層帶 `--collapsed` 時整段不顯示
- 夾帶區已隨發文框 promote 至 [Post composer](./post-composer.md)（`.post-composer__media`［`--image`／`--video`／`--audio`］），本元件不再定義；軸上只留發文框的落點
- `.post-composer`（2026-08-18 promote 至 [post-composer.css](../ds-components/post-composer.css)） ＞ `__composer-head`／`__composer-fields`／`__composer-foot`（`__composer-who`、`__composer-avatar`、`__composer-tools`）— 內嵌發文框
- `.ptl__update`［`--release`］＞ `__update-title`／`__update-body`（`__update-head` 排標題與可見度）— 一則更新的內容區塊，兩種擺法：掛在某顆里程碑底下（`--nested`，只留一段文字；沒有軸點——它不是藍圖的一步，是掛上去的內容），或**自己站在軸上**（`.ptl__node--post` 裡，2026-08-20 D209——日期搬到日期欄、標題列改用 `.ptl__head` 讓標題落在軸點中線上）

**Variants** — `--todo`／`--doing`／`--done`／`--alert`（里程碑狀態）；`--system`（釘頂的完成作品）／`--today`（今天）／`--start`（系統事實：項目建立與生命週期事件，只有名字與日期）／`--foot`（軸的終點，不留下方間距、不畫分隔線、軸線在此停）／`--day`（按天收合的更新列）；`--collapsed`（收起 `.ptl__fold`）。**`--start` 與 `--foot` 是兩件事**（2026-08-20 拆開，D209）：兩條規則原本都掛在 `--start`，而 `--start` 當時只有一個成員「項目建立」、它永遠是最後一列；D202 之後生命週期事件沿用同一個修飾子長相，於是軸中間每出現一個事件，它與下一列就黏在一起、中間沒有分隔線、軸線也斷一截。**這條分工是規格約束**（spec [5.1.2.2](../../../documents/5.1.2.2-專案詳情.md) §2.2.10「組成」）：生命週期事件在軸上與其他列同等份量，「軸到這裡結束」與「這一列比較不重要」不得共用同一套處理。`.ptl__update--release` 標出「完成作品」那則貼文。

**軸向與排序** — 單一排序軸是真實日期，沒有手動調整順序這個動作；要換位置就改預計日期。未來段由遠而近往下排、沒有預計日期的排在未來段最上方；今天在中間；過去段由近而遠往下排。里程碑落位的日期：已完成的用完成日（提前／延後完成都落在真的做完那一天，原定日期以 `.ptl__meta` 附註），其餘用預計日期。逾期的節點不留在原本的日期位置，排在今天正下方。

**今天那一格** — `--today` 是軸上一個真實節點，也是整條軸上唯一會換說法的位置。`.ptl__lede` 依情境改寫（倒數、逾期、里程碑日、當天完成、全部完成、沒有日期、已取消…），`__lede-num` 把天數拉成品牌墨、`--alert` 下轉紅。發文框內嵌在它身上，**是活的 DOM**：消費頁每次重繪都要先把它從舊軸上摘下、重繪後掛回插槽，否則使用者打到一半的字與 zselect 的接線會被洗掉。

**兩列不隨日期移動** — `--system`（完成作品）釘在軸的最上方且不帶日期（它的日期是上映日，可能還沒定）；`--start`（項目建立）釘在最下方，也是軸線的終點。軸線關在 `--start` 而不是 `:last-child`，因為渲染時它之後還可能被追加節點。

**收合** — `--day` 列預設收合、里程碑預設展開。收合狀態存在消費頁的 JS 裡，不存在 DOM——每次重繪都會把 DOM 洗掉。

**收合的單位是「兩顆里程碑之間」，展開後一則一列**（2026-08-20，D209）。收合時 `--day` 那一列說出這一段有幾則；展開時那一列留下來當控制項，**每一則各自成為 `--post`：自己的日期欄、自己的一顆 `--ghost` 點**。改法的理由是這條軸的承諾是「一顆點＝一件事」，三則發生在不同日子的貼文擠在同一顆點底下，軸上會讀成「這裡發生了一件事」。連帶影響：展開與收合**必須重繪**（那幾列是兄弟節點，不是收在 `.ptl__fold` 裡的一塊，切 class 藏不掉也長不出來）。

**軸上哪些東西點得開** — 軸是掃視用的，一列只放讀得下去的份量；其餘進詳情彈窗。兩種可點的目標，同一套 hover／focus 處理（負的左右 margin 讓底色比文字往兩側各長 8px，不然亮起來像文字被框住；鍵盤走 `:focus-visible`，兩種操作看到同一個狀態）：
- `.ptl__update[data-up-open]`（2026-08-19，D205）— 每一則更新，含掛在里程碑底下的完成宣告。
- `.ptl__head[data-ms-open]`（2026-08-20，D208）— **已完成**的里程碑，整條標題列。更新貼文只有兩種（D206），兩種都要點得開，而里程碑貼文在軸上的樣子就是那一列里程碑——只讓底下那一小段內文可點，等於這一類貼文有一半的呈現點不開。**未完成的不可點**：紀錄回答的是「這顆發生過什麼」，還沒完成的那一顆能寫的只有軸上已經寫著的預計日期。消費頁的處理器負責分流（有完成宣告就開那則貼文的紀錄、沒有就開里程碑自己的），並排除 `.ptl__acts`（右端的 ⋯）——按選單不該同時開彈窗。

**狀態色只上在軸點與軸線** — 用 `color-mix` 由 `--status-success`／`--status-info`／`--status-error` 推導；內容區不染色，因為退件理由常常很長，整塊染紅會把一段可讀的文字變成一張警告圖。紅色墨走 `--destructive-ink`（站上唯一的「小字可讀紅」，見 `_tokens.css` 的推導註記）。

**Surface** — 節點本身不填色，白底與灰底都成立。`.ptl__update` 不填底（2026-08-17 起，歸屬靠它在軸上的位置表示）；`.post-composer`（2026-08-18 promote 至 [post-composer.css](../ds-components/post-composer.css)）用 L1 表面 `--layer-1-surface`（Q64），放在卡內使用。發文框內的 `.select--bare` hover 改用 `--accent`——它預設的 `--muted` hover 跟發文框同色會整顆消失（Surface-Layer Contrast）。

**Dependencies** — `.badge`／`.btn`（`--ghost`／`--icon`／`--primary`／`--outline`，皆 `--sm`）／`.input`／`.textarea`／`.select`（`--bare`）／`.ztor-icon`。內容由 `js/project-progress-store.js`（里程碑與更新，日期是真實 `Date`）＋ `js/work-review-store.js`（送審件）產生，完成作品那一顆**不另存狀態**、直接讀送審件，所以總覽、進度與作品三處講的一定是同一件事。

**Consumers** — `project-detail.html`（進度分頁）。

**沿革** — 2026-08-17 上午照元件檔頭先行補寫（當時消費頁尚未接上），同日消費頁落地後回頭對齊；同日下午依 D194 改寫成日期驅動的時間流。原寫在 4.22h0 Section nav 規格檔裡，2026-11-09 併入本檔。
- （舊，2026-08-18 A2 改版前：軸點是圓框＋圖示。A2 當下先改成里程碑 10px 實心、更新與收合列 8px 空心、今天 12px 品牌色＋光暈，並在元件層以 `.ptl__dot .ztor-icon { display:none }` 收掉 JS 輸出的圖示；之後長相整組交給 Progress mark，現況見 Anatomy `.ptl__dot`。）
- （舊，2026-08-17 前：掛在里程碑下的 `.ptl__update` 用 `--muted` 淺灰填、靠內縮與左側細線表示歸屬，因此要放進 `.card`；2026-08-17 使用者反饋後改成不填底、不加左側色條，見 `progress-timeline.css` 註記。）

**✝ 2026-08-17 墓碑（D194）** — `.ptl__loose` / `__loose-head` / `__loose-title` / `__loose-sub`（軸尾的公告盒）退場：未掛里程碑的更新改依發布時間排進同一條軸，不再有第二個盒子。同輪撤除里程碑的上移／下移鈕（順序由預計日期決定），對應的 i18n key `pd-prog.ms.up`／`pd-prog.ms.down`／`pd-prog.loose.*` 一併移除。
