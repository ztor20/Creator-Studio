### 4.104 Sortable

**Purpose** — 全站表格唯一的排序互動：把欄位標題包成按鈕，靜止時與純文字標題完全一樣，只有 hover/聚焦或正在排序時才出現方向指示——表頭不該長得像工具列。

**狀態：`tier-benefits.html` 為死引用（待清）** — 該頁 `<link>` 引入 `sortable.css?v=r2.2`，但頁面內無 `.sort-th`/`.table-head`，也未載入 `js/table-sort.js`。

**Anatomy**
- `.sort-th` — 根層；`.sort-th--end` — 數字欄（右對齊，caret 在前）
- `.sort-th__ind` — 固定尺寸的指示井，caret 淡入淡出零位移
- `[data-sort-state]` × `[data-sort-first]` — 決定顯示 ▼ 或 ▲：看的是「這一欄第一次點是遞增還是遞減」，不是單純的排序方向——文字欄第一次點是遞增、數字欄第一次點是遞減，兩者卻都顯示 ▼
- `.table-head` — grid 表格家族的表頭列（與資料列共用同一組 `grid-template-columns`）
- `.product-list__head` — 2026-10-27 起 `js/table-sort.js` 也認它當表頭（`.table-head, .product-list__head` 擇一）：資料列用 `.product-list__row`、列容器標 `[data-sort-rows]`，即可在 `.product-list` 清單上點欄名排序（首個消費頁：fans-crm.html 排行榜／名人堂）
- `.table-scroll` — 寬表格在窄螢幕橫向捲動而非重排成卡片

**Dependencies** — `js/table-sort.js`（執行期把 `<th data-sort>` 或 `<span data-sort>` 包裝成 `<button class="sort-th">`，也負責實際排序邏輯）；兩種表格家族 `.ztor-table`（真 `<table>`）與 `.data-list`/`.msg-history`（grid 列）。

**對外 API** — 兩支：
- `window.ztorTableSort.scan(scope)`：之後才注入的表格補掛排序（彈窗打開、整張表含表頭重畫）。
- `window.ztorTableSort.refresh(scope)`（2026-11-10）：已掛好的表格，表身列被頁面重畫（篩選、切分頁籤、資料更新）——新的列當成預設順序（第三次點回到的就是它），所有欄回到「未排序」。範圍內還沒掛的表格順便掛上，所以重畫後呼叫一次就夠。
- 只在表尾加列（新增、複製）不必呼叫：沒有預設位置的列，排序時自動排在既有列之後。

2026-11-02 D497 曾加 `set(root, key, state)` 給粉絲名冊工具列的「排序」選單用；D506 撤除該選單（表頭即可排序），`set` 已無呼叫者，一併移除。

**列標記（2026-11-10）**
- `data-sort-pin`（掛在 `<tr>`）：合計列，不參與排序、固定留在最後一列。首例：pickup-detail 領取統計彈窗。
- 值的解析：金額的印刷體減號（U+2212「−$84.60」）視同負號。顯示文字不能直接比的格（「42 / 100」「EUR 1,326 → $1,410」「$500 → 10%」「3 小時／2 天」），一律給 `data-sort-value`。

**Consumers** — `earnings-sony.html`、`brand-campaigns.html`、`fans-crm.html`；2026-11-10 補接：`admin-ip-bank`、`admin-video-review`、`admin-creator-events`、`admin-platform-fees`（版本歷史、費率例外）、`admin-platform-promotions`、`admin-platform-loyalty`、`audience-report`（完整清單彈窗的兩張貼文表）、`ip-bank-reporting`、`fan-analytics`（轉換漏斗）、`store-settings`、`order-detail`、`earnings-ztor`、`earnings`、`pickup-detail`、`project-detail`（含 `js/project-earnings-chart.js` 的收益明細彈窗）、`event-detail`。`tier-benefits.html` 見上方狀態。

**刻意不接的表格**（固定列的設定或輸入表、順序本身有意義的列表）：`admin-platform-fees` 的六張費率輸入表（換匯手續費＋五個維度）、`fan-analytics` 的影響力四面向（四列單位各不相同，數值互比沒有意義）、`project-detail` 的兩張時程表（里程碑依時間固定排列，其中一張只有兩列）、`js/publish-stage.js` 的翻譯表（逐欄位輸入、有分組列）、`js/components.js` 儀表板的 `table:true` 輸出（目前只有 `docs/` 的儀表板探索稿在用）。

**Code example**（`.ztor-table` 家族擷取自 `earnings-sony.html` 第 333 行；`data-sort` 屬性經 JS 於執行期轉為 `<button class="sort-th">`）

```html
<tr>
  <th data-sort="text">Item</th>
  <th data-sort="text">Category</th>
  <th class="sort-th--end" data-sort="num">Amount</th>
</tr>
```

grid 家族範例（擷取自 `fans-crm.html` 第 200–210 行）：

```html
<div class="table-head fan-row">
  <span data-sort-key="name">Fan</span>
  <span class="table-head__end" data-sort="num" data-sort-key="rep">Loyalty points</span>
</div>
```
