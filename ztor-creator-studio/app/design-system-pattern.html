5.1.6 Form assembly

Workflow

Trigger

觸發

Any create / edit form

任何建立／編輯表單

Must

必須

every field is a Field (label + hint + one atom control); group into Form sections (title + grey sub; sibling sections auto-divide, base gap 6 / field spacing 16); side-by-side via Form grid; save on a sticky action bar. Sectioned create sheets use --surface-page; visible outlined sections use --card / dark --muted fill (no border edge, Q14) and a --sp-24 gap across hidden conditional sections. Adopted by product, auction, bundle, event, project, IP registration, and Admin IP Entry flows. Field order: identity → content → settings → risk disclosures. One section = one decision (extracted from create-product, 2026-09-01): split sections by the decision a creator makes, not by field type — price and discount are two decisions, so two sections; the test is whether the section title answers "what is being decided here" in one line. Branches toggle visibility, never reorder: physical / digital / multi-variant branches show or hide whole sections via data-*-show; section order stays fixed and no second form is ever built. Four fixed levels inside a section: __head → __subhead (only when one decision holds two field groups) → form-grid / field → nest; skip unused levels, never invent a fifth. Route-changing actions (e.g. type switch) live at the right end of the first section's __head--actions

每個欄位都是 Field（label＋hint＋單一 atom 控件）；用 Form section 成組（標題＋灰副標；區段相接自動分隔線、基礎 gap 6／欄距 16）；並排用 Form grid；儲存放固定動作列。區塊式建立 sheet 使用 --surface-page；可見外框區塊以 --card／黑夜 --muted 填色（無邊框線，Q14）與跨越隱藏條件區塊的 --sp-24 間距組成。商品／拍賣／組合／活動／項目／IP 登錄／Admin IP Entry 均已採用。欄位順序：識別 → 內容 → 設定 → 風險揭露。一個 section＝一個決定（2026-09-01 自 create-product 抽取）：切區依創作者要做的決定、不依欄位型別——價格與折扣是兩個決定就是兩個 section；判別句：section 標題能不能一句話回答「這區在決定什麼」。條件分支控顯隱、不重排：實體／數位／多規格分支用 data-*-show 控整個 section 顯隱，順序恆定、絕不為分支建第二份表單。Section 內分層階梯固定四級：__head → __subhead（僅當同一決定下有兩群欄位）→ form-grid／field → nest；用不到就跳過，不得自創第五級。改變路由的動作（類型切換）放第一個 section 的 __head--actions 右端

5.1.10 Detail + persistent rail

Layout

Trigger

觸發

An entity page where editing is split across tabs but a few read-only facts must never leave view (product detail: stock, delivery, linked project)

編輯分散在多個分頁、但有幾項唯讀事實必須永遠看得到的實體頁（商品細節：庫存、交付、關聯項目）

Must

必須

wrap the page in .page.page--narrow (1056px — the default 1280px plus a 300px rail leaves the main column too wide), then the Detail rail shell: editable Tabs in .detail-main, sticky .detail-rail on the right holding read-only Form section cards built from KV list / Stock bar / KPI. The rail answers "what do I need to know before I change something", so it holds constraints and consequences (stock on hand, delivery method, what this item is attached to), never the fields being edited and never a primary action. Cap it at 3–4 cards — a rail that scrolls has stopped being persistent. Below 1100px it falls in under the main column, so nothing in it may be the only route to a task.

5.1.11 Destructive confirm

Interaction

Trigger

觸發

An action that can't be taken back — voiding an order item, deleting a product / draft / event, disabling an account. Reversible actions (save draft, unlist, toggle visibility) just do it and show a toast.

一個按下去就收不回來的動作——作廢訂單明細、刪除商品／草稿／活動、停用帳號。可逆的動作（存草稿、下架、切換顯示）不走這張卡，做完給 toast 就好。

Must

必須

No new modal CSS — this is Modal shell plus .btn--destructive, which is why the rule lives here and not in Pillar 4. The entry point is a quiet .btn--ghost.btn--destructive (red text, never the loudest thing in the row); only the commit button in the dialog foot is a full .btn--destructive. Body order is fixed, four blocks: what is being acted on (name it and quantify it — never "this item") → prerequisite (what must already be done elsewhere, e.g. "refund the buyer in Stripe first") → what happens (one line per consequence: codes voided, stock restocked, who gets emailed) → no undo. Afterwards the toast says what actually happened, not "success".

沒有新的 modal CSS——它是 Modal shell 加上 .btn--destructive，所以規則寫在 Pattern、不寫成元件。入口是安靜的 .btn--ghost.btn--destructive（紅字，絕不是那一列裡最響的東西）；只有彈窗頁尾真正執行的那顆才是完整的 .btn--destructive。內容順序固定四段：動到哪一項（講出名稱與數量，不要只說「這個項目」）→ 前置條件（要先在別的地方做完什麼，例如「請先在 Stripe 完成人工退款」）→ 會發生什麼（一條後果一行：憑證失效、庫存回補、誰會收到信）→ 不可逆。事後的 toast 要說出實際發生了什麼，不是只說「成功」。

2026-10-15 (visual check C1, STYLE-DECISIONS Q134): the confirm button may never look weaker than the entry. When the entry is already the tinted .btn--soft.btn--destructive (one per list row, the order header’s “Void whole order”), the confirm uses the same tinted button. The prerequisite and the no-undo note are Alert --row (warning / error) above the reason field, not grey hints; a prerequisite that doesn’t apply is removed (a free order — zero amount, no payment — shows no Stripe refund note).

2026-10-15（目視檢查 C1，STYLE-DECISIONS Q134）：確認鈕不得比入口弱。入口已是淡紅底 .btn--soft.btn--destructive（清單列每列一顆、訂單頁首的「撤銷整張訂單」）時，確認鈕用同一款淡紅底。前置條件與不可逆改用 Alert --row（warning／error）放在原因欄上方，不再是灰色 hint；前置條件不適用時整條收起（免費訂單——金額 0、不經金流——不出現 Stripe 退款提醒）。

2026-10-15, applied site-wide: event detail’s shared confirm dialog (openConfirm() in event-detail.html) now gives every destructive confirm the tinted .btn--soft.btn--destructive — Void all remaining tickets, Void ticket, Unlist event, Remove date, Discard changes (Cancel event was retired on 2026-10-20, D457). One dialog serves several entries; the confirm takes the strongest entry’s level, so no entry ever outweighs it. Pages with their own dialog whose entry is a red outline, ghost button, menu item or icon button (delete product, delete draft, delete IP) keep the red-outline confirm: same level as the entry, which Q134 allows.

2026-10-15 全站套用：活動詳情的共用確認視窗（event-detail.html 的 openConfirm()）所有破壞性動作的確認鈕一律改淡紅底 .btn--soft.btn--destructive——撤銷全部剩餘票券、撤銷單張票、下架活動、移除場次、捨棄變更（取消活動於 2026-10-20 D457 退場）。同一個視窗服務多個入口，確認鈕取最強入口那一級，任何入口都不會比它重。自帶視窗、入口是紅框、ghost、選單項或圖示鈕的頁面（刪除商品、刪除草稿、刪除 IP）維持紅框確認鈕：與入口同級，符合 Q134。

Should / must-not

建議／禁止

Keep a blocked entry point visible and disabled with a title saying why (already picked up, needs the Admin role) — a hidden button reads as "this feature doesn't exist". Never use the native confirm(); never replace the consequence list with a single vague "this cannot be undone"; never change the screen before the user confirms.

不能按的入口留在畫面上、停用並用 title 說明為什麼（已取貨、需要 Admin 角色）——藏起來的按鈕會被讀成「沒有這個功能」。不可用原生 confirm()；不可把後果縮成一句籠統的「此操作無法復原」；不可在使用者確認之前就先改畫面。

5.1.12 Export confirm

Interaction

Trigger

觸發

A list the creator filtered and now wants as a file — Orders, and the ticket transactions inside one event. The file follows the current filters, so the dialog says how many rows it will hold before anything downloads.

創作者已經篩好一份清單、現在要拿它成檔——訂單管理，以及某場活動裡的交易明細。檔案照目前的篩選結果，所以下載前先在視窗裡講清楚會有幾筆。

Must

必須

No new modal CSS — this is Modal shell (.payout-modal / .payout-dialog--narrow) plus .zcheck, built once by js/csv-export.js (ztorCsv.confirm()) and shared by every export. Body order: the row count first, then the optional personal-data checkbox with one hint line, then the footer (Cancel left-aligned ghost, Export primary). The checkbox is unchecked every time the dialog opens — personal data never leaves by default. With zero rows the Export button is disabled and the sentence says why.

沒有新的 modal CSS——它是 Modal shell（.payout-modal／.payout-dialog--narrow）加上 .zcheck，由 js/csv-export.js（ztorCsv.confirm()）建一次、每個匯出共用。內容順序：先講筆數，再放選填的個資核取框與一行說明，最後是腳（取消＝ghost、匯出＝primary）。核取框每次開窗都回到不勾——個資預設不外流。零筆時匯出鈕停用、句子講明原因。

Should / must-not

建議／禁止

The file itself is built in the browser (ztorCsv.build(): UTF-8 BOM, comma-separated, quotes doubled, CRLF) and named {what}_{event?}_{date range | all}.csv in the interface language, headers included. Amounts are plain numbers — no currency symbol, no thousands separator; empty means "no value", never 0 standing in for "not applicable". When an export has no personal-data option, say that in one hint line instead of showing a disabled checkbox. Never download straight from the toolbar button, and never pre-check the personal-data box.

檔案在瀏覽器端產生（ztorCsv.build()：UTF-8 加 BOM、逗號分隔、雙引號重複、CRLF 換行），檔名依介面語言寫成 {內容}_{活動?}_{起訖日期｜全部}.csv，表頭一樣走在地化。金額一律是純數字、不帶貨幣符號與千分位；空白代表沒有值，不用 0 代替「不適用」。這份匯出沒有個資選項時，用一行說明講明，不要放一個停用的核取框。禁止從工具列按鈕直接下載，也禁止預設勾選個資核取框。
