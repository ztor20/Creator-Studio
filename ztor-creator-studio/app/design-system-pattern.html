How components assemble.元件如何組合

Best-practice assembly recipes — how components combine to meet a creator's goal. Twelve cards across four categories (page-level and mid-level); each has trigger / must / should / must-not / edge-cases. Component sections demo the unit only — assembly rules live here.

最佳實務的組合配方 — 元件如何組合起來達成創作者的目標。四個類別共十二張卡（頁面級＋中間層），每張都列出 trigger / must / should / must-not / edge-cases。元件段只展示單元本身——組合規則一律寫在這裡（判準見 §4.0）。

What counts as a pattern

什麼是 pattern

PatternPatternA fixed way of putting several components together to finish one kind of user task — when to use it, which components, how they are arranged, how they behave, and what happens at the edges. It has no stylesheet of its own; anything that needs styling is a component.為了完成某一類使用者任務，把幾個元件組在一起的固定做法——什麼情況用、用哪些元件、怎麼排、怎麼互動、邊界狀況怎麼處理。它本身沒有樣式檔；需要樣式的部分屬於元件。
Variant變體A fixed branch of the same recipe for a different situation, written on the same card (e.g. the wizard as a full page, a full page with a preview, or laid over the page).同一套做法在不同情境下的固定分支，寫在同一張卡（例：多步驟精靈的整頁、整頁＋右側預覽、蓋在頁面上）。
Instance實例A real page built by following the pattern, listed at the bottom of its card; the page's own details live in that page and the product spec.照這個做法做出來的具體頁面，列在卡片底部；頁面細節屬於該頁與產品規格。
Not a pattern不是 patternA single component (Pillar 4); page skeletons, grids and templates (Pillar 6); product rules (the product spec decides what must be shown — a pattern only says where and how).單一元件（Pillar 4）；頁面骨架、網格與模板（Pillar 6）；產品規則（要顯示什麼由產品規格決定，pattern 只說放哪裡、怎麼呈現）。

Pillar 5 has two areas: assembly recipes (the 5.1 cards below) and site-wide conventions (5.2 voice, 5.3 states, 5.4 data viz). The old 5.5 list of workflows is now the instance list of 5.1.5.

Pillar 5 分兩區：組裝做法（下方 5.1 的 pattern 卡）與全站通則（5.2 文案語氣、5.3 狀態與互動、5.4 資料視覺化）。原本的 5.5 流程清單已併進 5.1.5 的實例。

How to use it when designing a page

設計頁面時怎麼用

Read the product spec first → find a pattern: use it as is; if it mostly fits but needs a different branch, add a variant instead of changing the base (change the base only if every instance should change); if none fits, create a new pattern only when the arrangement will be reused, otherwise note the one-off layout in BUILD-SPEC.md → then find components (use / add a variant / keep a one-page style on the page / only then a new component) → list the page as an instance on the card.

先看產品規格 → 找 pattern：適用就照做；大致適用但要不同分支，就加成變體、不改原 pattern（只有所有實例都該跟著改才改原 pattern）；沒有的話，會重複用才建新 pattern，只有這一頁就記進 BUILD-SPEC.md → 再找元件（用現成／加變體／只有一頁用就留在頁面／都沒有才建新元件）→ 把這頁記成卡片的實例。

5.1.6 Form assembly

Workflow

Trigger

觸發

Any create / edit form

任何建立／編輯表單

Must

必須

every field is a Field (label + hint + one atom control); group into Form sections (title + grey sub; sibling sections auto-divide, base gap 6 / field spacing 16); side-by-side via Form grid; save on a sticky action bar. Sectioned create sheets use --surface-page; visible outlined sections use --card / dark --muted fill (no border edge, Q14) and a --sp-24 gap across hidden conditional sections. Adopted by product, auction, bundle, event, project, IP registration, and Admin IP Entry flows. Field order: identity → content → settings → risk disclosures. One section = one decision (extracted from create-product, 2026-09-01): split sections by the decision a creator makes, not by field type — price and discount are two decisions, so two sections; the test is whether the section title answers "what is being decided here" in one line. Branches toggle visibility, never reorder: physical / digital / multi-variant branches show or hide whole sections via data-*-show; section order stays fixed and no second form is ever built. Four fixed levels inside a section: __head → __subhead (only when one decision holds two field groups) → form-grid / field → nest; skip unused levels, never invent a fifth. Route-changing actions (e.g. type switch) live at the right end of the first section's __head--actions

每個欄位都是 Field（label＋hint＋單一 atom 控件）；用 Form section 成組（標題＋灰副標；區段相接自動分隔線、基礎 gap 6／欄距 16）；並排用 Form grid；儲存放固定動作列。區塊式建立 sheet 使用 --surface-page；可見外框區塊以 --card／黑夜 --muted 填色（無邊框線，Q14）與跨越隱藏條件區塊的 --sp-24 間距組成。商品／拍賣／組合／活動／項目／IP 登錄／Admin IP Entry 均已採用。欄位順序：識別 → 內容 → 設定 → 風險揭露。一個 section＝一個決定（2026-09-01 自 create-product 抽取）：切區依創作者要做的決定、不依欄位型別——價格與折扣是兩個決定就是兩個 section；判別句：section 標題能不能一句話回答「這區在決定什麼」。條件分支控顯隱、不重排：實體／數位／多規格分支用 data-*-show 控整個 section 顯隱，順序恆定、絕不為分支建第二份表單。Section 內分層階梯固定四級：__head → __subhead（僅當同一決定下有兩群欄位）→ form-grid／field → nest；用不到就跳過，不得自創第五級。改變路由的動作（類型切換）放第一個 section 的 __head--actions 右端

Interaction

Trigger

觸發

An action that can't be taken back — voiding an order item, deleting a product / draft / event, disabling an account. Reversible actions (save draft, unlist, toggle visibility) just do it and show a toast.

Must

必須

No new modal CSS — this is 5.1.8 彈窗類型的共用外殼 plus .btn--destructive, which is why the rule lives here and not in Pillar 4. 5.1.13 Pre-publish preview

Workflow

Trigger

觸發

Something fans will see — an event, product, bundle, project or work — is built or edited and about to go out. The creator looks once at what fans will see and checks every language; the same screen comes back after publishing to adjust languages or content.

要對粉絲公開的東西（活動、商品、組合包、專案、作品）建立或改完、送出之前，讓創作者看一次粉絲端長什麼樣，順便檢查各語系；發布後回頭改語系或內容也用同一個畫面。

Must

必須

A full page, not an overlay (D310). Frame: Publish stage — left, the Fan page mirror (a 1:1 copy of the fan page, filled from the create flow); right, a sticky control rail: languages (status per language, restore auto-translation, field-by-field table) plus the pre-publish checklist (each item jumps back to its step) or the unsaved-changes summary. The main button sits at the bottom of the rail and publishes on the first press. Hovering a block of the preview offers “Edit”, which jumps to the step that owns it.

全頁畫面，不用浮層（D310）。骨架是 Publish stage：左邊 前台鏡像（粉絲端頁面的 1:1 鏡像，資料來自建立流程），右邊 sticky 控制側欄——語言（每個語系標狀態、可還原自動翻譯、可開逐欄位對照）＋發布前檢核（每項可點回該步驟）或未儲存的變更摘要；主鈕在側欄底部，按一次就發布。滑到預覽某一塊會浮出「編輯」，跳回擁有那塊內容的步驟。

Preview prices in the creator currency only (D514); purchase buttons in the preview do nothing. Never bring back the old overlay (Publish preview is retired); fan-shop.css serves the mirror only and no other page links it; never redraw the fan page in a different layout.
