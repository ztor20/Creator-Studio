# ztor Creator Studio 輸入與表單欄位普查（2026-11-09）

範圍：`site/app` 根目錄產品頁 65 頁（排除 `design-*`、`lab-*`、`demo-*`）＋ `js/*.js`、`partials/*.js`（排除 `js/devtools.js`、`js/lab-media-vault.js`）。只讀，未改任何專案檔。勾選類（checkbox／radio／switch／segmented／selection-card）只在跟輸入混用時提到。

讀法：

- 「檔:行」是代表位置；同一種寫法出現在多頁時寫「代表頁＋共 N 檔」。
- 次數是 grep 命中數（含 JS 字串與註解），只當量級參考。
- 兩支腳本會在執行期改寫 markup，判讀時要算進去：
  - `js/zselect.js:416` 把所有 `select.select` 升級成自繪下拉（zselect）；沒有 `.select` class 或頁面沒載這支的，展開清單仍是作業系統畫的。
  - `partials/date-input.js:23` 把所有 `type=date／datetime-local／time` 包上 `.date-input`（日曆或時鐘圖示＋「選擇日期」佔位字）；頁面沒載這支的，空值會露出瀏覽器的「年/月/日」。

## 2. 建議的類型（7 類）

共通規則先講：每一格都是一個 `.field`（`__label` → 控件 → `__hint` → `__error`，順序固定）；必填用標籤後的 `.field__req`「*」；選填交給 placeholder（Q123），不在標籤寫「（選填）」；驗證錯誤一律 `.field__error`＋控件 `aria-invalid="true"`，位置在 hint 下方、不另開 class；鎖定與唯讀一律用 `.input` 的 disabled 樣子（Q128／Q133，`--disabled-field-bg`＋`--view-field-ink`），原因寫在 `.field__hint`。

| 類型 | 要輸入什麼 | 用哪支控件 | 標籤／說明／單位／錯誤怎麼放 | 唯讀或鎖定 |
|---|---|---|---|---|
| 1 文字 | 名稱、說明、備註、退回原因；長篇內文 | 單行 `.input`；多行 `.textarea`；需要段落與粗體的長篇才用 `.rich-body` | 字數上限用 `.field__counter` 放在標籤列右側（`field__label--split`）；最低字數寫進 hint 一次 | disabled 框；檢視態 textarea 去拖拉把手 |
| 2 數字（金額、比例、數量） | 錢、%、倍數、點數、張數、上限 | 一律 `.amount-field`：錢＝前綴單位（幣別符號或代碼擇一，見 3.1 第 8 點，要使用者裁決）；其他＝`--suffix` 後綴單位；整數且常微調的加 `.zstep`；大額主角用 `--hero` | 單位放在框內的 `__unit`，不寫在標籤也不寫在框外；上限、換算結果寫 hint（超過時 `.field__error`，不是換色的 hint） | disabled 框（單位保留）；算出來的值用 `.field-readout` 加 `.field__hint--fact` |
| 3 日期與時間 | 單一日期、單一時間、日期時間、區間 | 單一：`date`／`time`／`datetime-local`（皆由 date-input.js 加佔位）；區間：`.date-range`；「跟著某個時間或另設」：`.follow-field` | 「日期時間」只用一種寫法（`datetime-local` 一格或 date＋time 兩格，見 3.1 第 3 點，要使用者裁決）；區間的先後錯誤放在迄日那格的 `.field__error` | disabled 框 |
| 4 從固定清單挑 | 分類、幣別、國家、語言、時區 | `select.select`（zselect）；多選加 `data-zselect-multi`；選項 ≤ 4 且要一眼看完時才改用 segmented／radio-cards（勾選類） | 選單裡的「新增一個」用 `data-zselect-action`，不在旁邊另放按鈕 | 觸發鈕 disabled；bookyay 帶入另掛 `.field-source`＋`.is-source-locked` |
| 5 搜尋後挑 | 人（使用者、粉絲、創作者）、電影、優惠碼、商品 | 挑人：`.owner-lookup`；挑多個並留在欄位成 chip：`.combobox`；固定物件類型有專用件（Film picker、Code picker）；要邊篩邊勾很多個：開彈窗（5.1.8 第 5 類，Picker／Member picker） | 已選成 chip 留在欄位內；沒結果的空狀態放在下拉裡 | chip 去 ×、輸入格停用（archived-gate 已處理） |
| 6 多個自由標籤 | 商品標籤、粉絲標籤 | `.tag-input` | 建議標籤放欄位下方 chip-group | chip 就是值，零個時顯示「—」 |
| 7 檔案 | 主圖、縮圖、影片、附件、資料檔 | `.upload-tile`（含 `--file`、`--slim`、`--video`）；整批匯入走 Source upload modal | 尺寸與格式限制寫在格子內或 hint；上傳失敗放 `.field__error` | 封存時整格不可點（archived-gate） |
| 附：系統值（只讀、可帶走） | 分享連結、掃碼網址、付款編號 | `.linkf`（複製＋重置都在行尾）；不是要整條帶走的只讀值用 `.field-readout` | 說明一行在下方 | 本來就唯讀，不套 disabled 灰底（`.linkf__input` 已是例外） |

「附」不算一類輸入，但要寫進總卡，因為現在有三種做法（見 3.6）。

## 3. 不一致清單

### 3.1 同一種值用了不同控件

1. **數量（整數）三種寫法**：`.zstep`（create-bundle.html:214、create-project.html:553）／`.amount-field--suffix` 帶單位但沒增減鈕（create-bundle.html:322）／裸 `.input type="number"` 沒單位（create-event.html:3473、js/bundle-editor.js:1753、event-detail.html:2094，約 40 處）／裸 `inputmode="numeric"` 文字框（create-product.html:530）。同是「張數／組數」，建立組合包有增減鈕，建立活動沒有。
2. **百分比三種寫法**：`.amount-field--suffix`「%」（21 檔）／手刻 `.input`＋`<span class="text-sub">%</span>`＋行內寬度（create-project.html:600–612）／單位只寫在標籤（project-detail.html:1644、create-campaign.html:216）。
3. **日期時間兩種寫法**：商品、組合包、拍賣、專案、媒體庫用 `datetime-local` 一格（create-product.html:974）；活動用 `date`＋`time` 兩格（create-event.html:1101、event-detail.html:1176）。同一件事（上架、開賣時間）。
4. **日期區間三種寫法**：`.date-range` 元件（orders.html:82、event-detail.html:1623）／手刻兩格＋「–」（tier-settings.html:310、store-settings.html:731、admin-platform-promotions.html:267）／起迄拆成兩個 `.field`（js/ticket-bundle.js:424）。前兩種是同一種呈現，應該收成元件。
5. **從清單挑一個，有兩處沒升級成 zselect**：admin-platform-fees.html:411 寫成 `<select class="input">`（不是 `.select`，展開是作業系統清單）；earnings-sony.html:725 用了 `.select`，但這頁沒載 `js/zselect.js`。
6. **工具列篩選下拉兩種**：`.select--bare`（orders.html:90、fans-crm、demand-board、ip-market、login）／`.field-pill__select`（projects.html、project-detail.html）。同在清單上方篩選列。
7. **搜尋 Ztor 使用者兩種**：`.owner-lookup`（creators、admin-creator-events、media-vault:130、create-event:273）／`.combobox`（create-event.html:504 表演陣容，placeholder「Search Ztor users or type a name」）。另有 admin-creator-events.html:193、creators.html:181 的裸 `type="search"` 輸入。
8. **金額的幣別前綴兩種**：「$」符號（多數）／幣別代碼 TWD（`amount-field--code`：create-event.html:3410、event-detail.html:2067、earnings-sony.html:738）。create-event 的註解寫明是使用者要求「顯示實際幣別」，其他頁沒跟上。
9. **字數提示三種**：`.field__counter`（fans-crm.html:681、product-post-modal.js:61）／`.field__hint--count`（create-product.html:215）／一般 `.field__hint` 自寫（create-auction.html:138、register-ip.html:154）；計數邏輯也各頁一份（`data-cp-counter`、`data-ca-counter`、`data-ri-counter`）。
10. **長篇描述兩種**：活動用 `.rich-body`（contenteditable），商品、組合包、專案用一般 `.textarea`。可能是產品差異，要上游確認。

### 3.2 欄位沒有 `.field` 包裝（自帶另一套標籤）

1. **partials/manual-entry-modal.js:19–48（手動補登收入）用 `.payout-form-grid`／`.payout-field`，這兩個 class 的 CSS 已於 2026-07-11 刪除**（ds-components/payout-modal.css:286 的註解寫「No remaining callers」），所以這張彈窗的標籤與欄位目前沒有任何版面樣式。最該先修。
2. **`.msg-field` 一整套平行的欄位系統**：fans-crm.html:660–716（群發訊息）、partials/product-post-modal.js:57–70（建立商品後發文）；有自己的 `__label`、`__label-text`、`__req`，排程區另有 `.msg-schedule`。

### 3.5 唯讀與鎖定的呈現

1. 規則已統一（Q128：檢視態＝disabled 框；readonly＝disabled 樣子，`.linkf__input` 例外），但「為什麼鎖住」的說明有三種：`.field__hint`（pickup-detail.html:773）／`.lctl__lock-note`（auction-detail.html:312–372、bundle-detail.html:597）／`.field-source`＋`.is-source-locked`（bookyay 帶入，create-event、event-detail、js/purchase-conds.js）。
2. 算出來的值有兩種：readonly `.input`（auction-detail.html:407／411、create-auction.html:490 結束時間、partials/restock-modal.js:117 `restock-table__ro`）／`.field-readout`（order-detail.html、event-detail.html，9 檔）。依 field-system 規格，「只顯示、不可填」該用 `.field-readout`。
3. 命名混淆：`.amount-field--readonly` 指的是「單位是靜態字、不能點」，不是欄位唯讀；117 處 suffix 欄位幾乎都掛它，容易被誤讀成唯讀欄位。
