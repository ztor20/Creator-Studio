# Dashboard 重設計（r2.2 第二輪）· 2026-08-19

依 2026-08-07 的旅程研究（`dashboard-佈局重思-2026-08-07.md`）重新設計整頁 UX/UI。
本輪產出兩個 demo，**正式站台 `index.html` 未動**：

- **V1 旅程版**：`docs/dashboard-v1-旅程版.html` — 完全依研究結論設計，版面份量跟著使用頻率走
- **V2 粉絲優先版**：`docs/dashboard-v2-粉絲優先.html` — 加一條硬約束「ztor 粉絲組成第一眼就要看到」
- **V3 全資料版**：`docs/dashboard-v3-全資料版.html` — 追加需求（同日）：現況九區塊的資料一筆不少，照旅程重新組織，必要處拆分資料

## 研究回顧（沿用 08-07 的分析，結論不變）

五種後續登入旅程與頻率：A 日常巡檢（每天、30–90 秒）＞ B 處理待辦（每週數次）＞
C 檔期推進（有檔期時每天）＞ D 成效複盤（每週/每月）＞ E 拓展機會（被動）。
第一次登入者要的是能力地圖與第一步，不是一份自己缺席的報表。

現況（2026-08-11 版 index.html）已把粉絲組成＋粉絲關係疊進第一屏，但整頁仍是
「九區塊全數常駐」：D 旅程（平台表現三卡＋外部資料）每天被捲過，總長 3,734px。

## 兩版共用的設計決定

1. **首屏答兩個問題**：今天有沒有事（F2 計數）＋是哪件事（F4 前 3 筆滿寬、每筆自帶 CTA）。
2. **E 旅程**＝一條可關閉的官方訊息帶（`info-banner--dismissible`），不用全幅輪播。
3. **C 旅程**＝「進行中」一張大卡（span-8），F5 最近動態收成卡內第二分頁；
   F3 近期收入降為側欄精簡清單（span-4）——總額在 F2 已看過，明細是確認型資訊。
4. **D 旅程收成入口**：表現與受眾一張摘要卡（三欄一句話＋「查看完整分析」CTA），
   完整圖表留在粉絲分析頁與項目 Performance 分頁。
5. **F8 外部資料**不再常駐：異常以告警形式進 F4（demo 中 Spotify 那筆就是）、
   新鮮度一句話進摘要卡。
6. **空狀態獨立設計**：能力四卡＋「建立之後這頁會變成什麼」，不用同骨架填空字（V1 示範）。

## 兩版的差異（唯一變因＝第一眼給誰）

| | V1 旅程版 | V2 粉絲優先版 |
|---|---|---|
| 第一眼 | 橘色總收入 KPI（錢） | ztor 粉絲組成 hero（人） |
| Row 1 | F2 三塊 KPI 橫排 | 粉絲組成 hero（span-8、220px 圓餅）｜右欄疊 KPI（span-4：總收入 hero＋待處理/進行中並排） |
| Row 2 | 今日待處理 滿寬前 3 | 同 V1 |
| 粉絲組成位置 | 表現摘要卡的中欄一句話 | 頁面主角 |
| 粉絲關係 F7 | 摘要卡不另列（入口進 Fans） | 摘要卡中欄補一句（承接 hero 的敘事） |

V2 的取捨：粉絲組成佔掉 Row 1 之後，三塊 KPI 被壓進右欄直向疊（總收入仍是橘色 hero、
但尺寸變小；待處理/進行中縮成半寬 mini）。「錢」的第一眼讓位給「人」——這是這條硬約束
的真實代價，做進 demo 讓使用者看著實物裁決。

## 佈局總表

**V1**：問候＋訊息帶 → F2 KPI×3 → F4 滿寬前3 → 進行中(tabs) span-8｜近期收入 span-4 → 表現與受眾摘要卡（本週受眾｜站上粉絲組成一句話｜資料新鮮度）
**V2**：問候＋訊息帶 → 粉絲組成 hero span-8｜KPI 疊 span-4 → F4 滿寬前3 → 進行中(tabs) span-8｜近期收入 span-4 → 表現與受眾摘要卡（本週受眾｜粉絲關係一句話｜資料新鮮度）

兩版皆為 demo（`docs/`，不進正式站台）；採用後需要的 promote：`.band-label`（若保留分帶標）、`.sum3`、V2 的右欄 KPI 疊法。

## V3 全資料版（追加，同日）

約束：現況所有資料都要在頁面上；自由度：呈現方式照旅程重排，必要時可拆分資料。

四帶結構與資料去向：

| 帶 | 內容 | 呈現手法 |
|---|---|---|
| 現在 | F2 三塊 KPI＋F4 全部 5 筆 | F4 滿寬卡改**兩欄網格**——「全部都在」與「一屏掃完」同時成立 |
| 進行中 | F6 全 6 列＋F5 全 6 列＋F3 全 8 筆 | F6 主位 span-8、F5 拆進同卡第二分頁；F3 降側欄精簡列（名稱／來源·日期／金額全保留，只拿掉表格框與縮圖） |
| 粉絲與受眾 | F9 全部＋F7 全部＋F8 全部 | **拆分 F7 一卡雙欄**：粉絲關係欄（站內分母：1,283／184、流失風險 toast、開啟粉絲頁）併進 F9 組成卡——同一份名冊，分級列表不再出現兩次；受眾趨勢欄（外部分母：+847 與各平台新增追蹤）併進 F8 狀態卡——同一組平台的兩面 |

實測 3,622px（現況 3,734px）：資料一筆不少、長度略短，代價是沒有 V1 那種砍半的縮幅——全資料就是這個長度的下限附近。
