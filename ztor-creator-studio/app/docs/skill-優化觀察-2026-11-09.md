# project-ui-creator 優化觀察（2026-11-09，邊做邊記）

這份記「照 skill 做 ztor 時，skill 沒寫到、寫得不夠或容易走錯」的地方，做完一輪再整理成 skill 修改。

## 已觀察到

1. **類型總卡的建立流程沒寫進 skill**：彈窗、抽屜都走了同一套——全站普查 → 依任務分類 → 草案（類型表＋要裁決的事）→ 使用者裁決 → 寫總卡＋裁決記 STYLE-DECISIONS → 收斂產品頁 → 驗收。skill 只說「先看類型總卡」，沒說總卡怎麼生出來、普查表長什麼樣。建議：Governance Mode 加一節「建立類型總卡」，附普查表欄位範本。
2. **改規則後，舊說法殘留在別處**：每輪驗收幾乎都抓到「規格檔、展示卡、元件 CSS 檔頭還寫舊說法」（例：窄版首例寫規格圖片、Modal shell 舊名、第 8 步）。建議：Close-out 加一步「改了規則或改名，全庫 grep 舊說法」，或在 check_ds_sync 加一個「已退場名稱」清單比對。
3. **「合併」在 skill 裡沒有區分兩種**：只改文件層（變體段併卡、class 沿用）與真合併（class 改寫、樣式統一、畫面會變）。真合併是設計決定，要先問。建議：lifecycle 的合併規則分成兩種並寫明哪種要裁決。
4. **重複實作的收斂缺做法**：同一段 markup 在多頁複製時，可以抽成 partial 並用 `document.currentScript` 插在原位置（DOM 順序、時機不變）。skill 的 frontend-architecture 只講 partial 何時用，沒講「把既有重複收成 partial」的安全做法與驗證方式（逐字比對 HEAD）。
5. **「不收」也要記**：有些看似重複的東西其實是不同情境（優惠碼三份、示範資料不同的頁）。建議：巡檢報告與 pattern 卡都要有「刻意不收」欄位，避免下一輪又被當成待辦。

## 6. 元件退場後，沒有檢查擋「還在用但已沒有樣式」的 class

- 現象：`.payout-field`／`.payout-form-grid`／`.payout-inline-control` 在 2026-07 退場、CSS 刪除，退場註解寫「已無消費者」，但 `partials/manual-entry-modal.js`（補登收入彈窗）一直在用，畫面欄位沒有排版長達四個月；普查才發現。同類：`js/brand-start-event.js` 用了不存在的 `info-banner--warning`。
- 原因：check_ds_sync 只查「CSS 有、沒人用」（零消費），不查「有人用、CSS 沒有」；退場時的消費者 grep 只掃 `*.html`，漏了 `partials/`、`js/` 裡的 template 字串。
- 建議：
  - 新增一項檢查：頁面、partials、js template 裡出現、帶元件前綴（`ds-components/*.css` 檔名或 BEM 根）的 class，在所有 CSS 都找不到定義時 FAIL（墓碑檔列出的退場 class 直接點名）。
  - 退場步驟的「先 grep 消費者」明寫範圍含 `partials/`、`js/`。

## 7. 使用者裁示過的全站規則沒有檢查守著

- 現象：「所有表格都要能排序」（2026-07-27）寫在 `js/table-sort.js` 檔頭，但 16 頁的表格沒接；「錯誤不能只靠 toast」（5.1.4）有 6 處違反；「清單要有空狀態」十幾處缺。都是普查才發現。
- 建議：check_ds_sync 加「全站規則」類檢查（可在 ds-baseline.json 的 project 區塊設定）：例如有 `table.ztor-table` 的頁必須載 `table-sort.js` 且 `th` 至少一欄 `data-sort`。規則能機器判斷的就寫成檢查，不能的寫進 Close-out 清單。

## 8. 元件預設值讓「不能點」看起來能點

- 現象：`.ztor-table__row` 預設 `cursor:pointer`、`.product-list__row` 預設 hover 浮起，於是二十幾張唯讀表格看起來能點。
- 建議：skill 的元件規則加一條「互動外觀（手指游標、hover 浮起）一律是修飾類、不放元件預設」；check_ds_sync 可抓「元件基底 class 帶 cursor:pointer」。

## 9. 平行收斂代理的派工與並行改檔（五批收斂的回報彙整）

- 並行改同一個檔：Edit 工具提示「檔案已變」是預期狀況，共用規則要直接寫明照樣精準替換即可；大量改名（e-shop 70 多處）需要一支「只替換指定字串、不整檔覆寫」的安全改名腳本，寫成 skill 認可的做法。
- 共用派工規則（`scratchpad/converge-brief.md` 那份）值得收進 skill 的 references 當範本：位置、鐵律、禁碰名單、變更紀錄寫草稿不直接寫、回報格式。

## 10. 元件合併缺 checklist

- 退場有墓碑流程，合併沒有。這次 tier-overview → `.bmx--readonly`、stock-tip → `.tip--card` 要動：消費頁與 JS 字串改名、新變體寫進規格、展示卡錨點保留舊 id、`ds-head.js` 移除、總表 ✝、其他展示頁連結、規格文字。建議 Governance Mode 加一份合併 checklist。
- 「同一種任務只留一種元件」遇到資料欄位對不上（`.source-list` 有金額欄、`split-bar` 沒有）時，規則要寫：先回報待決，不硬換。

## 11. 改元件預設行為前，要能列出所有消費者的互動

- Q166 改「列預設不可點」時，最花時間的是逐頁確認每份清單到底點不點得動；普查也會過時（e-shop 其實點得動）。建議提供工具列出各頁的 `data-go`、`closest('.x__row')`、row click handler。
- JS 用外觀 class 判斷選中狀態（`.tabs__item--active`、`.selection-card--active`），換元件時 JS 要跟著改。建議鐵律：選中狀態用 `aria-selected`／`aria-checked`／`data-*` 判斷。

## 12. 會在載入後改寫畫面的元件，規格要寫「保證不變的行為」

- `date-input.js` 把一格 `datetime-local` 換成兩格，規格該列出保證：值格式、事件來源、停用、`aria-invalid`、聚焦。
- 錯誤一律 `aria-invalid` 的鐵律需要配套：紅框原本只認 `.input`，`.textarea`、`.select`、zselect 標了沒反應。規格的完成檢查要列涵蓋哪些控件。
- 共用彈窗（partial）改了 markup，要檢查每個載入它的頁都有載對應 CSS（pickup-session-modal 被 7 頁載入，有頁漏 control-row.css）。建議 check_ds_sync 加一項。

## 13. 其他小項

- 圖示：registry 只服務 `<i data-lucide>`；被 `data-i18n` 改字或 JS 動態產生的元素改用 CSS mask，何時可用 mask 要寫清楚。
- 缺「抽出 HTML 內嵌 script 再語法檢查」的工具（要跳過註解裡的 `<script` 字樣）。
- 「同步展示卡」要區分：新增一種排法只要加說明，改外觀才換示範。
- `.nest` 只用在貼齊母卡底緣的第 3 層，卡中段的第 3 層用 `.card--muted`（派工指示寫「改 .nest」差點走錯）。
- 容器查詢（`@container`）寫在同權重基底規則之前會被蓋掉；第一次引入 `container-type` 的元件要在規格寫明。

## 14. 退場的展示卡與共用 CSS 檔、批次替換黏字

- 退場要「從目錄拿掉」，但檢查 6 要求「每張卡都在目錄」：實際做法是刪掉那張卡、在上層卡尾寫一段 ✝ 說明。skill 要寫明。
- 元件和別的元件共用一支 CSS 檔（rank-bars 在 chart.css）時：不動 `ds-head.js`，墓碑寫在共用檔那一段。
- 批次替換把兩個屬性黏在一起（`hiddendata-i18n=`，20 處），錯誤訊息一開頁就顯示、檢查抓不到。建議 check_ds_sync 加一項：布林屬性後面直接黏 `data-`／`aria-`／`class=`。
