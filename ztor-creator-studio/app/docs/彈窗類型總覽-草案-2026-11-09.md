# 彈窗類型總覽（草案，2026-11-09）

給使用者裁決用，還沒寫進設計系統。證據是同日的全站普查 [彈窗普查-2026-11-09.md](彈窗普查-2026-11-09.md)：138 個浮層，依「使用者在裡面做什麼」初判任務類型。

## 這份草案要解決的事

彈窗分兩層：
- **元件層**：彈窗本身——外殼（`.payout-modal`／`.payout-dialog`）、頭身腳、遮罩、寬度。現在是 §4.61 Modal shell。
- **pattern 層**：彈窗有哪些類型——每一類是為了哪種任務、裡面放什麼、按鈕怎麼排、用哪個寬度。

做新彈窗時：先看需求是哪一類 → 都不像時先檢討分類要不要改 → 類型確定後，元件做不出來才改元件。

現況的問題：pattern 層只定義了 3 類（Modal shell 通用、5.1.11 破壞性確認、5.1.12 匯出確認），但站上實際有 11 類左右。沒定義的那幾類，各頁各寫各的。

## 要你裁決的事

1. **類型清單**：上面 11 類可以嗎？要合併或拆開的寫出來。（我的建議：照表；「選擇做法」也可以併進「確認後執行」，但它的版面是選擇卡，分開比較清楚。）
2. **確認類只用一種外殼**：現在「確認後執行／破壞性確認／提示告知」有兩套外殼並存——活動詳情與媒體庫用 `payout-dialog --narrow`，商品、組合包、拍賣、電子商店、系列活動用 `leave-dialog`。建議統一成 `payout-dialog --narrow`，Leave dialog 只留給「離開未存」。
3. **寬度跟類型走**：窄（確認、告知）、預設（表單、匯出、選擇做法）、寬（挑選、欄位多的表單）、全畫面（開另一頁、整頁工作區）。現在同樣是小表單有 `--narrow`、預設、行內寫死 520px 三種。
4. **看細節用彈窗還是抽屜**：26 個都是彈窗，另有 3 個抽屜。建議：要跟清單對照著看（逐筆點開）用抽屜，獨立看一筆用彈窗。
5. **可逆動作不用紅鈕**：活動「下架」現在是紅色確認鈕（event-detail.html:3310），照 5.1.11 應改成一般確認。

## 這份草案之外、裁決後要排的工作

- 原生 `confirm()` 6 處（4 處是破壞性動作）與 `alert()` 21 處，改成對應類型的彈窗。
- 3 個直接下載的按鈕改走匯出確認：受眾報告完整清單、收入項目明細、取貨核銷紀錄。
- 已沒有入口的兩個浮層退場：`partials/publish-preview.js`（四個建立頁還在載入）、`ztorCsv.openLog()`。
- 同類重複實作收成共用：優惠碼建立 3 份、規格圖片 2 份、收益明細 4 份、create-bundle 兩個同名「加入組合物」。

## 寫進設計系統的方式（裁決後）

- 5.1.8 改成「彈窗類型」總卡：開頭一張類型表（就是上表），每一類寫什麼時候用、外殼與寬度、內容順序、按鈕、實例。破壞性確認、匯出確認保留自己的卡，在總卡列為其中兩類。
- §4.61 Modal shell（元件）只管外殼與寬度修飾類，用途段改成「有哪些類型見 5.1.8」。
- 這個「元件 → 有哪些 pattern 類型」的寫法同步進 skill 的判斷流程，其他元件（抽屜、清單、卡片）之後比照。
