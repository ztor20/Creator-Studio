# ztor Creator Studio 清單與表格普查（2026-11-09）

範圍：`site/app` 根目錄產品頁（排除 `design-*`、`lab-*`、`demo-*`）＋ `js/*.js`、`partials/*.js`。只讀，未改任何專案檔。路徑皆相對 `site/app/`。

讀法：

- 編號「A／B／C／D n」是分組普查的原編號：A＝活動與取貨，B＝收入與專案，C＝商店、商品、組合包、訂單、媒體庫，D＝Admin、粉絲、IP、受眾分析、品牌合作、設定。
- 同一支 partial／JS 多頁共用只算一列，所在頁寫成 `partials/x.js:行（← 使用頁）`。兩頁各自寫一份的，各算一列，並記在第 3 節「重複實作」。
- 「初判類型」用分組時的 11 個暫定代號；第 2 節把它們收成 8 類。
- 不收：純設定開關列（`settings-row`、`control-row`、`lctl`）、單一計量條（`completeness`）、KPI 數字排（`stat-row`）、卡片格（媒體庫、IP 市集）。
- 總數：335 個用法（A 73、B 78、C 68（另 3 列與 A／D 重複已刪：C11＝A72、C17＝D115、C40＝A67）、D 116）。

### 3.2 各組原始不一致清單

下面四段是分組普查的原文。各段裡的「#n」指該組自己的編號，對應第 1 節表格的「A n／B n／C n／D n」。

#### A 活動與取貨

1. **`ztor-table__row` 被拿去做不可點的列**：table.css:146 定義 `.ztor-table__row { cursor: pointer; }`，用途是「整列可點」。event-detail 的售票紀錄（3608）、參加者名單（2670、7844）、撤銷紀錄（3796）、營收事件表（3755）都掛了這個 class，但沒有整列點擊，滑鼠變手指卻點不動。pickup-detail.html:1158 管理領取碼才是正確用法（有 tabindex 且整列可點）。
