4.2 Button

🟢 atom

Purpose

用途

Primary action control. Five emphasis levels — pick by how important the action is and how dense the surface is. One orange primary per block (card / dialog / toolbar); never use the orange primary for destructive actions.

主要動作控制項。五種強度——依「動作多重要」與「版面多密」挑。每一塊（卡片／彈窗／工具列）只留一個橘 primary;刪除類動作絕不用橘色 primary。

When to use which

什麼時候用哪個

“One block” = a self-contained area on screen (a card, a dialog / form, a toolbar, a list row) — not the whole page.

「一塊」＝畫面上各自獨立的一塊區域（一張卡片、一個彈窗／表單、工具列、列表的一列），不是整頁。

On which background (white vs grey)

Do & Don't

該做與別做

Do該做
  • Keep one orange primary per view as the clear CTA.
  • 每個畫面只保留一個橘色 primary 當明確的 CTA。
  • Use outline / ghost for secondary and inline actions.
  • 次要與行內動作用 outline／ghost。
Don't別做
  • Put more than one primary in a region, or use orange for destructive actions.
  • 同一區塊放多個 primary,或用橘色做破壞性動作。
  • Use a transparent-fill outline on the white canvas — it reads as "nothing there."
  • 在白底上用透明填色的 outline — 看起來像「什麼都沒有」。

In context — product & bundle status badges (spec §7.14 · D241; derived by js/listing-state.js, never a stored field)

Eight states, one badge slot. A listing has three independent switches (listed / shown in shop / on sale) plus a sellable count, and the badge is what falls out of them. The priority is fixed and pages must not reorder it: draft → unlisted → hidden → ended → soldout → coming → low → live. hidden sits above ended and soldout because a list row has one badge slot and "you cannot find it in the shop" is the more actionable fact; a detail page has room for two, so it calls deriveFlags() and shows e.g. Sold out + Hidden side by side.

八個狀態，一個徽章位置。一個上架品項有三個互相獨立的開關（上架／顯示於商店／開賣）再加一個可售量，徽章是它們算出來的結果。優先序固定，各頁不得自行調換：draft → unlisted → hidden → ended → soldout → coming → low → live。hidden 排在 ended 與 soldout 之前，因為清單列只有一個徽章位置，而「商店裡找不到」是比較該先講的事；細節頁擺得下兩顆，改叫 deriveFlags()，把「售罄」與「已隱藏」並排顯示。
