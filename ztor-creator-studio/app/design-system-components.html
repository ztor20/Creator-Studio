04 · Component

Concrete, importable UI units.

可直接匯入的具體 UI 單元。

Each component references Pillar 2 Roles (not raw Pillar 1) and ships either as a dedicated ds-components/ file or as a documented product-owned component in shared.css / feature CSS. Every unit carries a _layer tag (🟢 atom / 🟡 molecule / 🟠 organism), orthogonal to its variants.

每個元件都參照 Pillar 2 Role（不直接用 Pillar 1），並以獨立 ds-components/ 檔或已文件化的 product-owned component（shared.css／feature CSS）形式存在。每個單元都帶一個 _layer 標籤（🟢 atom／🟡 molecule／🟠 organism），與其變體相互獨立。

Component card order元件卡閱讀順序Purpose用途
1 · PurposeWhat job the component owns; why it exists.這個元件負責什麼工作；為什麼存在。
2 · RelationshipsBuilt from ↓ means child components. Used by ↑ means parent components.由哪些元件組成 ↓ 是子元件；被哪些元件使用 ↑ 是父元件。
3 · Rendered previewWhat the component looks like in use. Variations and interactions are shown inside the preview, not as separate reading categories.直接看這個元件實際長什麼樣。樣式差異與互動變化放在預覽裡，不再拆成多個閱讀分類。
4 · SpecificationSource, anatomy, behavior, token usage, classes, and evidence / usage.來源、內部結構、行為、token 使用、class，以及實際頁面證據／用法。

4.0 Classification

Two orthogonal axes. Layer (atom → molecule → organism → template) tells you how big a unit is. Component vs Pattern tells you whether it's a thing you import (Pillar 4) or a recipe you follow (Pillar 5).

兩條互相獨立的軸。Layer（atom → molecule → organism → template）告訴你一個單元有多大。Component vs Pattern 告訴你它是可匯入的東西（Pillar 4）還是依循的配方（Pillar 5）。

Preview discipline (2026-07-08) — a component's Rendered preview shows one instance of the component itself (as a variant × state matrix where meaningful). Any demo that assembles multiple distinct components is labelled In context and links to the matching Pillar 5 pattern card; assembly rules (what sits above what, order, rhythm, triggers) live in Pillar 5 only, never duplicated in a component section. Litmus test: "would this rule still hold if this component's CSS were deleted?" — if yes, it's a pattern, not the component.

展示判準（2026-07-08）——元件段的視覺展示只展示該元件的單一實例（有意義時做成變體 × 狀態矩陣）。凡是把多個不同元件組起來的示範，一律標「實際情境 In context」並連到對應的 Pillar 5 pattern 卡；組合規則（誰在誰上、順序、節奏、觸發時機）只寫在 Pillar 5，元件段不重複。判斷句：「把這個元件的 CSS 刪掉，這條規則還成立嗎？」成立 → 它是 pattern，不是這個元件的。

4.1 Inventory

Rows are split by source ownership. ds-components/ rows are independently importable; shared.css rows are real product components that are reused today but have not yet been split into one-file CSS.

清單依來源權責拆分。ds-components/ 列是可獨立匯入的元件；shared.css 列是今天產品中真實復用、但尚未拆成單一 CSS 檔的元件。

JS components with no CSS of their own are listed and demoed here too (2026-08-11). They used to be registered in design-system.md only, on the grounds that they own no styles. But this page is where components are reviewed — a component that is missing here reads as a component that does not exist. Their CSS column names the JS file instead.

無自帶 CSS 的 JS 元件同樣列在這裡、也有 demo 卡（2026-08-11 起）。這類元件過去只登記在 design-system.md，理由是它們不擁有任何樣式；但元件是在這一頁被檢視的，這頁沒有就等於這個元件不存在。它們的 CSS 欄改放 JS 檔名。
