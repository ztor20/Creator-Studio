Selected / active state (Q8-A, 2026-07-27)

已選中／active 狀態（Q8-A，2026-07-27）

Orange text on a near-white surface fails contrast (--primary alone is only 1.92:1) — these five tokens are the readable, WCAG-AA answer for "this is selected" and "orange used as ink, not fill". --on-primary is the separate answer for text sitting on top of solid --primary (e.g. .kpi--hero).

橘字直接鋪在近白底上對比不過關（--primary 單獨只有 1.92:1）——這五支 token 是「已選中」與「橘色當文字用」的可讀答案。--on-primary 則是另一個問題的答案：文字鋪在實色 --primary 底上時用（例如 .kpi--hero）。

brand-ink#8F4E00
on-primary#171717
selected-surface14% --primary
selected-surface-hover20% --primary
selected-ink= --brand-ink

--brand-ink light #8F4E00 / dark #ffa33f — the readable version of brand orange for text/icons on a non-orange surface (contrast ≥5.7:1 on card/sidebar/tint). --selected-ink is a semantic alias of it. --on-primary is aligned to #171717 in both themes (9.02:1 on --primary). --selected-surface and --selected-surface-hover are color-mix(--primary 14%/20%, transparent) tints, so they inherit whatever surface sits underneath.

--brand-ink 亮色 #8F4E00／暗色 #ffa33f —— 品牌橘鋪在非橘底上當文字／icon 用的可讀版本（對 card／sidebar／tint 皆 ≥5.7:1）。--selected-ink 是它的語意別名。--on-primary 兩個主題都定在 #171717（對 --primary 9.02:1）。--selected-surface 與 --selected-surface-hover 是 color-mix(--primary 14%/20%, transparent) 的淡染，會自動貼合底下任何底色。

Faint ink (2026-08-09)

最低階墨色（2026-08-09）

--faint-ink = color-mix(in srgb, var(--muted-foreground) 72%, transparent) — one step quieter than the floor text token. --muted-foreground is already the site's quietest ink, so anything softer has to step it down in opacity. Mixing with transparent rather than a surface color means it keeps the same step of dimness on any background — and it therefore goes darker in the dark theme and lighter in the light theme on its own, with no per-theme override. Consumers: --column-head-ink (table headers, below) and the value of a source-locked field (field-source-tag.css).

--faint-ink ＝ color-mix(in srgb, var(--muted-foreground) 72%, transparent) —— 比最低階文字 token 再輕一階。站上最安靜的墨色就是 --muted-foreground，比它更輕的角色只能以它為基底調降不透明度。混 transparent 而不是某個面色，所以它坐在任何底上都是同一階暗度——也因此**在黑夜版自動更深、在白天版自動更淡**，不需要逐主題各寫一次。消費者：--column-head-ink（表頭，見下）與來源鎖定欄位的值（field-source-tag.css）。

--locked-field-ink = color-mix(in srgb, var(--muted-foreground) 55%, transparent) — one step below --faint-ink, reserved for the value of a source-locked field (since 2026-10-12, Q128, input boxes use --view-field-ink instead; this one only inks unpicked locked option cards and a void link). It is a separate token rather than a dimmer --faint-ink because that one also inks 10 table-header components, which are not meant to fade. Its contrast is deliberately below AA (measured: dark #606061 on #1C1D1E = 2.69:1, light #AFAFAC on white = 2.20:1). That holds only because it carries a disabled read-only value, not information the page is asking you to read — the field label and the "From bookyay" source tag keep normal contrast and are what answer "what is this, and why can't I edit it". Do not use it for text meant to be read.

--locked-field-ink ＝ color-mix(in srgb, var(--muted-foreground) 55%, transparent) —— 比 --faint-ink 再輕一階，專給來源鎖定欄位的值（2026-10-12 Q128 起輸入框改吃 --view-field-ink，這支只剩未選的鎖定選項卡與作廢連結）。之所以另立一個 token 而不是把 --faint-ink 調更淡：那一支同時是 10 支表頭元件的墨色，表頭並沒有要跟著變淡。對比刻意低於 AA（實測：深色 #606061 對 #1C1D1E ＝ 2.69:1、亮色 #AFAFAC 對白 ＝ 2.20:1）。成立的前提是它只承載 disabled 的唯讀值、不是本頁要讀的資訊——欄位標籤與「bookyay 帶入」來源標記都維持正常對比，「這格是什麼、為什麼不能改」由那兩個回答。不要拿它去寫需要閱讀的文字。

--view-field-ink = var(--faint-ink) (2026-10-27 STYLE-DECISIONS Q137: two steps down from --foreground-muted so locked values no longer read as editable; 2026-10-12; widened the same day by STYLE-DECISIONS Q128) — the value ink of every disabled input box: .input／.textarea／.select :disabled (input.css), view-mode boxes in a two-step panel and readonly-locked boxes in edit mode (shared.css), and a locked description editor. Locked values are still content to read, so this passes AA (dark ≈ white 70%, about 9:1 on #1C1D1E; light #4D4D4D, about 8.6:1 on white). "Can't edit" is carried by the transparent fill, the not-allowed cursor and the lock hint. --locked-field-ink now only inks unpicked locked option cards and a void link.

--view-field-ink ＝ var(--faint-ink)（2026-10-27 STYLE-DECISIONS Q137 由 --foreground-muted 降兩階，鎖住的值不再像可以改；2026-10-12 新增；同日 STYLE-DECISIONS Q128 擴大）—— 所有 disabled 輸入框的值墨色：.input／.textarea／.select 的 :disabled（input.css）、兩段式面板檢視態的框與編輯態 readonly 鎖住的框（shared.css），以及鎖定的描述編輯器。鎖住的值仍是要讀的資訊，所以過 AA（深色 ≈ 白 70%，對 #1C1D1E 約 9:1；亮色 #4D4D4D，對白約 8.6:1）。「不能改」由透明底、not-allowed 游標與鎖定提示說。--locked-field-ink 只剩未選的鎖定選項卡與作廢連結在用。

--disabled-field-bg = color-mix(in srgb, var(--layer-0-surface) 20%, transparent) (2026-10-12; STYLE-DECISIONS Q133, replaces the transparent fill of Q58/Q128) — the fill of every disabled input box: one step darker than the card it sits on, still translucent. Shared by .input／.textarea／.select :disabled (input.css), view-mode and readonly-locked boxes (shared.css) and a locked description editor (rich-body.css).

--disabled-field-bg ＝ color-mix(in srgb, var(--layer-0-surface) 20%, transparent)（2026-10-12；STYLE-DECISIONS Q133，取代 Q58／Q128 的透明底）—— 所有 disabled 輸入框的底：坐在卡上比卡面暗一階、仍半透明。.input／.textarea／.select 的 :disabled（input.css）、檢視態與 readonly 鎖住的框（shared.css）、鎖定的描述編輯器（rich-body.css）共用。

--chip-surface = color-mix(in srgb, var(--foreground) 6%, var(--card)), dark var(--ztu-film) (2026-10-15; STYLE-DECISIONS Q76 ruling B) — the unselected Chip fill. In light mode both --input-surface and the white film equal --card, so chips melted into the card; this role gives them their own one-step-darker fill. Dark mode is unchanged. Light mode is off for now (Q135).

--chip-surface ＝ color-mix(in srgb, var(--foreground) 6%, var(--card))，暗色 var(--ztu-film)（2026-10-15；STYLE-DECISIONS Q76 裁決 B）—— 未選 Chip 的底。淺色模式的 --input-surface 與白薄膜都等於 --card，chip 會融進卡面；給它一個比卡深一階的專用值。暗色不變。淺色模式目前關閉（Q135）。

Column header ink (Q41, 2026-07-31)

欄位表頭墨色（Q41，2026-07-31）

--column-head-ink = var(--faint-ink) (2026-08-09; the recipe itself moved up to --faint-ink when a second consumer appeared — value and behaviour unchanged) — the label ink for every list/table column header. There is no text token darker than --muted-foreground (light #6E6E68 / dark #979797 are already the floor), so it steps that down in opacity instead. It exists as a token because the same role had been running three recipes (bare --muted-foreground, color-mix(…68%, --card), color-mix(…72%, transparent)) — exactly the ad-hoc greys Q9 set out to collapse. Mixing with transparent rather than --card keeps the same step of dimness on any surface, including the four headers that carry a --muted fill. Consumed by 10 header components.

--column-head-ink ＝ var(--faint-ink)（2026-08-09 起；出現第二個消費者時把配方上收成 --faint-ink，值與行為不變）—— 所有列表／表格欄位表頭的標籤墨色。站上沒有比 --muted-foreground 更暗的文字 token（亮 #6E6E68／暗 #979797 已是最低階），所以以它為基底調降不透明度。收成 token 是因為同一個角色原本跑了三種配方（裸 --muted-foreground、color-mix(…68%, --card)、color-mix(…72%, transparent)），正是 Q9 要收斂的「散落的即席灰」。混 transparent 而非 --card，表頭坐在任何底色上（含四支帶 --muted 底的）都是同一階暗度。消費者＝ 10 支表頭元件。

Status ink pairs

狀態墨色配對

Saturated status fills often fail AA as text (--status-warning alone is 1.42:1 on white). Each status color gets a same-hue "-ink" variant reserved for text/icon use — fill stays fill, ink stays ink.

飽和的狀態填色當文字用時常不過 AA（--status-warning 單獨對白只有 1.42:1）。每個狀態色都配一支同色相的「-ink」版本，專供文字／icon 使用——填色歸填色、墨色歸墨色。

status-warning-ink#8A6D00
status-accent-ink#6D28D9

--status-warning-ink — light #8A6D00 (4.92:1 on white) / dark var(--status-warning). --status-accent-ink — light #6D28D9 / dark var(--status-accent); used by .badge--accent.

--status-warning-ink —— 亮色 #8A6D00（對白 4.92:1）／暗色 var(--status-warning)。--status-accent-ink —— 亮色 #6D28D9／暗色 var(--status-accent)；用於 .badge--accent。

Scrollbar · --scrollbar-* (2026-07-27)

捲軸 · --scrollbar-*（2026-07-27）

Site-wide custom scrollbar, defined once (not per-theme) — color derives from color-mix(var(--foreground) …%, transparent), which already flips with theme on its own. Mixing into transparent rather than a surface token is deliberate: the same scrollbar sits on the sidebar rail, white modals, dark cards, and the solid-orange hero card, and baking in one surface's color would leave a stain on the others.

全站自訂捲軸，只定義一次（不分主題）——顏色由 color-mix(var(--foreground) …%, transparent) 推導，本來就會跟著主題翻。混 transparent 而非某個 surface token是刻意的：同一支捲軸會出現在側欄軌、白色 modal、深色卡、甚至實色橘的 hero 卡上，混死某個面就會在其他面上烤出色斑。

1.1b ztorUI skin · Glass & Glow raw layer (2026-08-28, Wave 1–2b)

1.1b ztorUI 換裝 · Glass & Glow 原料層（2026-08-28 熔接，Wave 1–2b）

A new visual language merged in from the reskin sandbox demo/ztorui-skin: white low-opacity glass and warm orange bloom on a near-black canvas, plus glowing selected states. Raw values live in ds-components/_tokens.css:608–674 (the --ztu-* family, 28 tokens) plus the unprefixed --bloom-surface named by the spec's §3.8, and --font-dot in fonts.css. See docs/wave1-熔接紀錄.md and docs/wave2-熔接紀錄.md for the full merge log.

從換皮沙盒 demo/ztorui-skin 熔接進來的新視覺語言：深色近黑檯面上的白色低透明玻璃、暖橘霧光，加上發光選中態。原料值集中在 ds-components/_tokens.css:608–674（--ztu-* 家族，28 支）＋不加前綴的 --bloom-surface（規格書 §3.8 指名的字面）、以及定義在 fonts.css 的 --font-dot。完整熔接對照見 docs/wave1-熔接紀錄.md 與 docs/wave2-熔接紀錄.md。

Light mode is switched off (2026-10-15, STYLE-DECISIONS Q135): the prototype always renders dark. LIGHT_MODE_OFF = true in js/theme.js ignores the saved preference and ?theme= and hides every toggle; the light tokens stay in _tokens.css :root for the later full light-mode pass — turning it back on means setting the constant to false and un-hiding the toggles.

淺色模式暫時關閉（2026-10-15，STYLE-DECISIONS Q135）：原型一律深色展示。js/theme.js 的 LIGHT_MODE_OFF = true 讓已存偏好與 ?theme= 都失效、切換入口全部收起；淺色 token 保留在 _tokens.css 的 :root，之後整站重做淺色時把常數改回 false、拿掉入口的 hidden 即可。

⚠ Dark-only vocabulary, light mode not yet tuned — this whole raw layer was tuned for [data-theme="dark"]'s near-black canvas. Most consuming rules (.card, .btn--primary, .chip…) are written unscoped on the base selector, so light mode inherits the same values today — e.g. a 5% white glass overlay on a white canvas is nearly invisible. This is a known, recorded state from Wave 1 (light-mode tuning is a later wave), documented as-is.

⚠ 這整組是深色語彙、light 模式尚未調校 —— 原料值是為 [data-theme="dark"] 的近黑畫布調的。多數消費規則（.card、.btn--primary、.chip…）不分主題寫在基礎選擇器上，所以 light 模式目前也吃到同一批值——例如白底上疊 5% 白玻璃幾乎不可見。這是 Wave 1 就記錄在案的現況（light 模式調校排在後續波次），文件如實記載。

Surface rule (2026-08-28, STYLE-DECISIONS Q77): every surface is neutral glass; colour shows only in light and text, never in the fill. The card family (.card, .kpi, .alert--bar, .readiness, .preview-card, .form-section--outlined, .list-toolbar, .app-topbar…) uses --ztu-glass-bg + blur(var(--ztu-blur-glass)) + 1px --border + --shadow-card/--shadow-edge-top; nested layers (card-in-card, control wells, thumbnail frames, neutral badges) use --ztu-film without blur. Named exceptions live in each component spec, e.g. the solid orange .kpi--hero (Q83).

表面材質原則（2026-08-28，STYLE-DECISIONS Q77）：表面一律中性玻璃，顏色只出現在光與文字，不出現在面。卡片家族（.card、.kpi、.alert--bar、.readiness、.preview-card、.form-section--outlined、.list-toolbar、.app-topbar…）統一用 --ztu-glass-bg＋blur(var(--ztu-blur-glass))＋1px --border＋--shadow-card／--shadow-edge-top；巢狀層（卡中卡、控件凹槽、縮圖框、中性徽章）統一用 --ztu-film、不上模糊。具名例外寫在各元件規格，例如 .kpi--hero 的實色橘（Q83）。

1.5 Shadow · Elevation ladder (E0–E4)

工具：.edge-shadow — 把 --shadow-header 變成「只露下緣」的邊緣陰影：內容寬（內縮）、兩端漸淡收尾、上緣與兩側都不外漏。作法是一個與元素等高、內縮、下方圓角的圖層（::before）投陰影，再用 clip-path 只露出元素下方那段——不需另做不透明上層遮蓋。可調 --edge-shadow-inset（28px）／--edge-shadow-radius（64px）。忠實照 Figma 720:1763 的兩層結構。電子商店貼頂庫存條使用（wizard header 用到 2026-09-23，之後改成浮起膠囊）；其他元素加 class="edge-shadow" 即可覆用（host 需為已定位元素：sticky／relative）。
