02 · Role

From raw values to design decisions.從原始數值到設計決策

Semantic roles assign each Foundation value a job. Components reference these, so a token swap re-themes the whole system.

語意角色替每個 Foundation 數值指派一份工作。元件引用的是角色，所以換一組 token 就能替整個系統重新換膚。

This layer is organised as six categories — 2.1 Color · 2.2 Typography · 2.3 Spacing · 2.4 Control sizes · 2.5 Elevation · 2.6 Cross-component rules. Every renderable role is shown live. Light values live here (the role default); dark overrides live in Pillar 3.

本層分六類 —— 2.1 顏色 · 2.2 字體 · 2.3 間距 · 2.4 控件尺寸 · 2.5 陰影 · 2.6 跨元件規則。可渲染的角色都即時畫出來。這裡放亮色（角色預設）；深色覆寫在 Pillar 3。

圖表 · Charts

Two palettes, two kinds of data. --chart-1..8 is categorical: independent categories with no order (revenue sources). --tier-1..4 (new, 2026-09-01) is a sequential ramp for ordered, nested data — the fan tiers, where Fan ⊇ Ranked Fans ⊇ Super Fans ⊇ Inner Circle. Painting nested tiers with categorical colours reads as four unrelated groups; the ramp lets lightness carry the depth. A warm re-cut of the dark chart palette was tried and reverted the same day at the user's call — the ramp fixes "nested data drawn in categorical colours"; the categorical set never had that problem. The reverted swatches live on in the tuner (docs/chart-palette-tuner.html).

2.3 Spacing

2.3 間距

Spacing runs on the Pillar 1 --sp-* px-named scale — component gap / padding / margin reference the primitive directly, the same pattern as font sizes using --fs-*. No semantic spacing-role layer yet (component/layout-level names): that is the honest status — roles get named when real, consistent usage groups emerge, never invented up-front (the fictional --gap-* set was removed 2026-06-30). Literal exceptions: odd optical tweaks, off-scale 22/26px, negatives, calc(); fan-store.css pending (parallel edit).

間距走 Pillar 1 的 --sp-* px 直命名刻度——元件 gap／padding／margin 直接引用 primitive，與字級用 --fs-* 同一模式。語意間距 role 層（component/layout 級命名）仍未建立：這是誠實現況——等真實一致的用途分群出現才命名，不預先杜撰（虛構的 --gap-* 已於 2026-06-30 移除）。保留字面值的例外：奇數微調、刻度外 22/26px、負值、calc()；fan-store.css 因並行編輯待補。

Vertical rhythm law (2026-09-01, Q103) — the space between stacked siblings belongs to the container, not to the siblings. Create rhythm with container gap (flex column / grid); never with .x + .x { margin-top } sibling combinators or "every member carries its own margin-bottom". Both fail the same way: the distance is tied to what the member is, so the first sibling of a different kind lands glued at 0px — it happened three times (media-vault's upload tile before the first group, form-section's radio-cards that are not .field, and .form-grid in the same sections). Sibling combinators are only for tightening (margin-top 0 / negative / semantic pairs like label+hint). The test: swap either neighbour for a different component — should the space still exist? If yes, it's the container's job. Existing same-class sibling rules are inventoried by check_ds_sync check 13 (WARN).

垂直節奏法（2026-09-01 立法，Q103）——直排兄弟之間的距離由「容器」持有，不由兄弟自己想辦法。建立節奏用容器 gap（flex column／grid），不用 .x + .x { margin-top } 相鄰選擇器、也不用「每個成員自帶 margin-bottom」。兩種寫法的病一樣：距離綁在「成員是誰」上，排進來一個異類鄰居就貼成 0px——實例三發（media-vault 的上傳格排在第一個分區前、form-section 裡不是 .field 的 radio-cards、同區段裡的 .form-grid）。相鄰選擇器只准用來收緊（margin-top 0／負值／label＋hint 這種語意配對）。判別法：把兩個鄰居中的任何一個換成別種元件，距離還該存在嗎？該存在→那是容器的事。既有的同類相鄰規則由 check_ds_sync 檢查 13 以 WARN 盤點。

2.4 控件尺寸

Buttons + form controls share one height scale (all multiples of 4) so an input and a button at the same size line up. Drive heights from --control-h-*; never hard-code.

按鈕與表單控件共用一套高度級（全部 4 的倍數），同尺寸的 input 與 button 對齊。高度一律走 --control-h-*，不寫死。

--control-h-md · 44
--control-h-lg · 52 （待採用）

2026-07-21 (Q25): the real default for single-line controls is --control-h-sm (36) — md is only labelled "default" at the scale level. Before Q25 .input was padding-driven (39px) while .btn was 36px, so "equal-size controls align" was aspirational; per-component padding tweaks had also grown three mismatched search boxes (41.5 / 37.5 / 35.5). Single-line controls now all take height: var(--control-h-sm); never size a new control with padding — padding×2 + font-size×line-height almost always lands on a fraction. .textarea stays padding-driven with min-height.

2026-07-21（Q25）：單行控件的實際預設是 --control-h-sm（36），md 只是刻度層被標為 default。Q25 之前 .input 靠 padding 撐開＝39px、.btn 是 36px，「同尺寸等高」只是文件宣稱；各元件自行調 padding 還長出 41.5／37.5／35.5 三種對不齊的搜尋框。現在單行控件一律 height: var(--control-h-sm)；新增控件不要用 padding 湊高度——padding×2 ＋ font-size×line-height 幾乎必然算出小數。.textarea 例外，維持 padding ＋ min-height。

2.5 Elevation

2.5 陰影

Elevation roles follow the Pillar 1 E0–E4 ladder: one component, one rung; interaction borrows the rung above (card hover → float); shadows never separate same-level elements. Content surfaces top out at E2 Card — E3/E4 are reserved for transient layers (dropdowns, dialogs). The hero is the only deeply-lit surface and it does that with a gradient veil, not box-shadow.

層級角色依 Pillar 1 的 E0–E4 海拔階梯：一元件一階；互動借上一階（card hover → float）；同層元素之間永遠不用陰影分隔。內容表面最高到 E2 卡片——E3／E4 保留給暫時性浮層（下拉、對話框）。只有 hero 是重打光的表面，且靠漸層遮罩、不是 box-shadow。

Text on photography: --scrim-media / --on-media / --on-media-muted are constants and do not flip with the theme — they sit on a photograph, and a photograph does not get lighter because someone switched to the light theme. Wiring the caption to --foreground would turn it into pale grey on a white image. The scrim’s job is to keep that one line readable however bright the picture is. Consumed by the canvas wall’s tiles.

壓在圖片上的字：--scrim-media／--on-media／--on-media-muted 是常數，不隨主題翻轉——它們貼在照片上，而照片不會因為使用者切成亮色主題就變亮。文字色若接上 --foreground，亮色主題下就會變成白圖上的淺灰字。壓底的工作是保證圖片再亮也讀得到上面那行字。消費端是海報牆的磚。

Frosted-overlay recipe: modal backdrops pair --overlay-tint (darkening wash) with --overlay-blur (backdrop blur) — e.g. .payout-modal. The scrim itself is one token, --overlay-scrim (2026-09-01): the mix of canvas colour and tint used to be copied into three components (payout-modal / embed-modal / explainer), and three copies of one recipe eventually disagree. The canvas share dropped 68% → 40% at the same time — that share, not the tint, is what was flattening the page behind into pure black (composited alpha 0.85 → 0.68). Element-level overlays (drawer, scanner, upload tile, media vault) keep using --overlay-tint on its own.

毛玻璃浮層配方：modal 背景以 --overlay-tint（壓暗）搭 --overlay-blur（背景模糊），如 .payout-modal。遮罩本身收成一支 --overlay-scrim（2026-09-01 使用者裁示「統一將所有 popup 後的黑色遮罩都改」）：畫布色與遮罩色的混合配方原本在三支元件裡各抄一份（payout-modal／embed-modal／explainer），三份一樣的字串遲早有一份沒跟上。同一次把畫布色的比重由 68% 降到 40%——真正把後面那一頁壓成一片黑的是這一項，不是 --overlay-tint（合成後 alpha 0.85 → 0.68）。元件層的局部遮罩（抽屜、掃描器、上傳格、媒體庫）維持單獨吃 --overlay-tint。

2.5a Surface layers (--layer-*)

2.5a 表面階層（--layer-*）

E0–E4 answers "how high" (shadow); --layer-* answers "how bright the stacked surface is" (fill + line). Two orthogonal axes — a component takes one rung from each. The level is in the token name. All are Role aliases onto existing Foundation values (no new colours, no separate dark override). Q61 A / Q63 B, 2026-09-15; migration of existing consumers tracked under Q64.

E0–E4 管「抬多高」（陰影），--layer-* 管「疊上去的面該多亮」（填色與線）——兩條正交的軸，同一元件各取一階。級數寫在名字裡。全部是 Role 別名、指向既有 Foundation，不帶新顏色、不另設暗色覆寫。Q61 A／Q63 B，2026-09-15；既有消費者的遷移進度記在 Q64。

2.6 Cross-component rules

2.6 跨元件規則

These are principles every component obeys, not a token scale — rendered as live mini-demos.

這些是每個元件都要遵守的原則，不是 token 刻度——用小型 live 示例呈現。

① Focus 環

One recipe across every control + both modes — outline: 2px solid var(--ring); outline-offset: 2px (list rows use -2px inset). No per-component outline vs box-shadow drift.

全控件、兩模式單一配方 —— outline: 2px solid var(--ring); outline-offset: 2px（清單列用 -2px 內嵌）。不再各元件各寫各的。

② Surface 分層對比

A component is seen by the contrast of its fill / border / shadow against the layer it sits on; a fill the same colour as the background disappears. White fills need a 1px border to form on white; for cross-layer safety use a real border, not fill-as-edge. Build any filled component against its layers and verify on the darkest one. (Button white/grey example: §4.2.)
