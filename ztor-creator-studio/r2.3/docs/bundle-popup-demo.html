這一組還缺什麼？

    版面參考了建立商品的哪幾件事

    • 一路捲、用分卡而不是分步——建立商品是一連串分卡（PRODUCT INFO／SHOW IT OFF／VARIATIONS／PRICE…），每張卡一個主題、卡頭一行說明。結構讀得出來，但不必按三次「下一步」才看得到全貌。這一版把先前的三步改回三張卡。
    • 底部就緒 chip 取代步驟閘門——建立商品底部是「6 items needed」＋停用的主要動作，hover 展開缺什麼的清單。組合包同一套：「還缺 N 項」，補齊才解鎖「完成」。三步版用「第 1 步沒選票就不給下一步」擋，是同一件事的較笨版本——就緒 chip 一次講完全部缺項，而不是走到那一步才發現。

    分層照 Figma 的疊層模型：每疊一層變亮一階

    規則來自 demo-layer-system.html（Figma 856:27798，STYLE-DECISIONS Q61–Q64 待裁決）：L0 畫布實色 → L1 卡片實色 → L2 半透明薄膜（疊在誰身上就跟著誰亮）→ L3 不再疊填色、只留框。這一版對上去是：

    • L1 彈窗面板 --card #212223
    • L2 三張分卡（組合內容／定價／呈現）rgba(222,223,233,.04) 疊上去 ≈ #292A2B，比面板亮一階
    • L3 票種挑選器與算式列：不再疊填色，只留 rgba(222,223,233,.08) 的線框

    為什麼不能直接用 .form-section--outlined：它吃 --surface-shell（深色 #1C1D1E），比彈窗面板的 --card 更暗——放進彈窗就是往下沉一階，方向與這個模型相反，正是先前那版看起來不對的原因。

    站上目前有兩套相反的巢狀答案：--muted #161718／--surface-shell #1C1D1E 是「嵌套襯底比卡更暗」，--nest-surface（Q24）與這份 layer 模型是「疊上去比卡更亮」。這一版依本次裁示採後者，衝突已記進 STYLE-DECISIONS Q66 待裁決。
