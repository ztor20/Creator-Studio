# 活動詳情頁顯示矩陣

`event-detail.html` 在不同狀態、類型與場地結構下，實際看得到哪些分頁與哪些區塊。

盤點日期 2026-08-20，對象是 `site/r2.2/event-detail.html`。內容取自實跑——每個組合各取一筆代表活動用瀏覽器開起來，讀套用完顯隱規則後的 DOM，不是讀 markup 猜的；程式碼規則另從 `applyTabs()`、`syncSalesView()`、`syncStage()`、`syncNavSections()`、`renderSessions()` 交叉核對。

## 三個維度怎麼分

**狀態**共六種：草稿、已排程、售票中、進行中、已結束、已取消。

**類型**共五種，但頁面只在三個群組之間分岔——演唱會、音樂節、粉絲見面會三者行為完全相同，故合併成一列：

- 實體（演唱會／音樂節／粉絲見面會）
- 線上活動
- 共看派對

**場地結構**共三種，這一層與類型正交：

- 單場地・單時段：最單純的一場
- 單場地・多時段：同一個場地連開幾場，收在同一筆活動的 `sessions` 陣列裡，場地只填一份
- 多站活動（系列）：每站場地不同，拆成系列母子頁——一站就是一筆活動，共用一個 `series.id`

多時段與多站的分界是「場地換不換」：場地不換就是同一筆活動的多個時段，場地換了就是多站。這條規則寫在 `js/events-store.js` 場次陣列那段的註解裡。

## 讀這張表的規則

分頁的可見性只由四條規則決定：

- 草稿一律不渲染詳情頁，直接轉回建立流程
- 已排程還沒開賣，所以沒有「售票與名單」分頁
- 共看派對只有一張單一入場券，所以沒有「票務」分頁，「售票與名單」裡也沒有退款那一節
- 線上活動與共看派對都沒有實體場地，所以「設定」少一節地點、「總覽」多一張線上房間卡

場地結構只動三個地方：

- 設定分頁的「場次」那一節，多時段是 N 個可摺疊的場次盒加一顆新增日期，其餘是 1 盒
- 總覽的「場次與票務概況」，多時段的日期格顯示場次數而不是單一日期
- 多站活動的總覽多一張「多站場次卡」，列出同系列各站與各自狀態，可直接點進別站；麵包屑也多一層系列名

另外「取消活動」只在已排程與售票中出現，已結束與已取消連編輯入口都收起。

## 已知缺口

**已取消的活動仍顯示活動名單與通知**（表中標 ⚠ 的格）。程式碼的意圖是收起來——活動不會發生，名單與通知沒有對象，`syncSalesView()` 明確把這兩節設為不顯示。但 2026-08-19 修「線上活動不該有地點」時改寫了 `syncNavSections()`，讓它只認 `data-hide-type` 與 `data-stage-show` 兩個屬性來判斷，而這兩節的「已取消要收起」規則只寫在 JS 裡、沒寫成屬性，於是後跑的那一步又把它們打開了。補上 `data-stage-show="on-sale live ended"` 即可，讓規則回到單一決策點。

**多時段活動的名單、交易與報到統計都不分場次**。`buildRoster()` 與 `buildTx()` 都以整筆活動為單位，三個時段的持票人混在同一份名單裡，也看不出誰是哪一場的。同一個場地連開三天的簽名會，現場要按場次核對時會缺這一刀。是否要切，屬產品層決定。

**售票中的多時段活動，總覽只顯示第 1 場**。這個階段的總覽用的是「場次脈絡」卡而不是「場次與票務概況」，而場次脈絡讀的是單值的 `date`／`start`／`doors`（設計上等於第 1 場的鏡像），所以看不出後面還有幾場。

**多站與多時段的組合目前沒有假資料**。資料模型上兩者可以並存（某一站自己連開兩場），但 44 筆 mock 裡沒有這種活動，這個組合的畫面未經實測。
