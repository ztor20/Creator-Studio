# ztorUI 換裝稽核 — r2.3 全元件表面盤點（2026-09-11）

## 結論

全庫盤點 `ds-components/*.css`＋`shared.css`（不含 `_tokens.css` 的純 token 定義行）共找到 246 處現行（非註解）的實色背景宣告，分類如下：

- **A 確定漏換：115 處，分布 44 支檔案**——控件底／chip 底／列 hover／縮圖框／工具列坐在玻璃面上卻仍用 `--muted`／`--card`／`--accent`／`--input-surface` 等舊實色 token。
- **B 刻意保留：106 處，分布 33 支檔案**——彈出層（dropdown／popover／dialog／modal／tooltip）、亮色主題區塊、圖表資料視覺化、精靈流程（wizard）獨立配色系統、以及少數有明文「刻意例外」註解的裝飾性表面。
- **C 待裁決：23 處，分布 17 支檔案**——多數是 2026-08-28 玻璃化之前就存在、且有明確理由的舊決策（如「可互動填色面比卡亮一階」「輸入框維持實色」），與新的玻璃語彙是否要收斂需要使用者裁決；另有少數是容器背景與角色不明確（如 `.hero`、`.vault-gate__panel`）。

A 類最值得先修的五處（依影響範圍排序）：

1. **`ds-components/button.css:276` `.btn--icon:hover`**——全站 67 個頁面／partial 消費，是今天已修好的姊妹元件 `.btn--icon-circle:hover` 的漏改對照，同一支檔案內。
2. **`ds-components/button.css:156` `.btn--ghost:hover`**——全站 46 個頁面消費，緊鄰已修好的 `.btn--outline:hover`。
3. **`ds-components/table.css`（96／204／208／235／250／356 共 6 處）**——`.ztor-table` 本體已於 Wave 2a 改透明巢狀於玻璃卡，但列 hover、展開列、交易明細徽章與縮圖仍各自殘留舊實色，影響全站幾乎每一張資料表。
4. **`ds-components/header.css`（82／324／373／450 共 4 處）**——頂欄高亮條、搜尋框、漢堡鈕、側欄收合鈕，直接坐在玻璃頂欄／側欄上，能見度最高。
5. **`ds-components/data-list.css:80` `.data-list__icon`（＋121／133 兩個變體）**——全站清單縮圖標準元件，21 個頁面消費。

另外 `ds-components/notification-matrix.css:55`、`ds-components/store-settings.css:200`、`ds-components/review-status.css:94`、`ds-components/vault-share.css:209` 都是「容器本體已修好玻璃／薄膜，但巢狀子層（表頭、圖示、備註、chip）未同步」的同一種漏改模式，值得一次性檢查所有「8/28 之後改過的容器」是否留有這類巢狀殘漏。

## 搜索範圍與方法

- **搜尋目錄**：`site/r2.3/ds-components/*.css`（164 支，含 `_tokens.css`）與 `site/r2.3/shared.css`。
- **搜尋 pattern**：`background:`／`background-color:` 後接
  `var(--muted)`／`var(--card)`／`var(--accent)`／`var(--secondary)`（全站 0 處）、
  `var(--surface-shell)`、`var(--input-surface)`、`var(--surface-page)`、其餘 `var(--surface-*)`，
  以及 `background`／`background-color` 後直接寫 hex 或 `rgba?(` 的宣告。
- **排除註解**：先用括號配對去除所有 `/* … */` 區塊再套 pattern，避免把「舊值：background: var(--card)」這類記錄歷史的說明文字誤判成現行宣告——這類註解代表**已經修好**，同一輪掃出 70 處，均未列入下表（多數集中在 2026-08-28～09-01 各次「ztorUI 換裝補漏」；detail-sheet／tag-input／variant-builder／dropdown-menu／header／payout-modal／segmented／selection-card／zselect／vault-share／media-vault／store-settings／event-preview-card／fans-guide／funding-panel／notification-matrix／preview-panel／restock-modal／size-chart-editor／tabs／upload-tile 等檔都有這種「已修好」痕跡）。
- **`_tokens.css` 的處理**：檔內 2 處 `--background:` 是 token 定義本身（不是元件消費），不計入三表；檔內另有 1 條真實 CSS 規則（`.theme-toggle`，開發用主題切換鈕）計入 B。
- **判準**：
  - 彈出層（`.dropdown__menu`／`.zselect__panel`／`.combobox__menu`／`.owner-lookup__results`／`.payout-dialog`／`.payout-modal`／`.message-modal`／`.product-post-modal`／`.embed-modal`／`.leave-dialog`／`.explain__dialog`／`.drawer__panel`／`.app-topbar__dropdown`／`.app-notif` 通知面板等）內部一律歸 B，即使用的是 `--card` 而非規範的 `--popover`——那是 token 命名一致性的小問題，不是本題要抓的「該玻璃卻沒玻璃」。
  - `html[data-theme="light"]` 區塊、圖表／資料視覺化元件（`chart.css`／`waterfall.css`／`.vault-door__seg` 涵蓋率條）、品牌橘家族、狀態徽章 tint 一律歸 B，不在本題範圍。
  - `scanner.css` 全檔（16 處）歸 B：檔頭明載「A separate URL with NO Creator Studio nav」，是獨立行動裝置掃碼頁，不掛接 ztorUI 玻璃殼／星空系統。
  - `fans-guide.css` 全檔（5 處）歸 B：STYLE-DECISIONS Q87 已明確裁決「維持現狀，不熔接」。
  - `.wizard`／`.wizard__sheet` 一系（shared.css 約 9 處）歸 B：精靈流程是獨立維護的另一套配色系統（Q81 提及的靜態點陣背景），只有 `.wizard__top` 頂列已於 Wave 2b 改玻璃，sheet 本身刻意維持既定材質。
  - `.vip-card` 歸 B：註解明載「全像色塊＝固定藝術，刻意例外」。
  - 凡選擇器或前後文出現「刻意」「例外」字樣才採信——逐一讀了上下文後刷掉一個假陽性（`ds-components/table.css:356` `.ztor-table__thumb`，附近註解的「刻意」其實是在講另一件事「列高」，與表面色無關，改判 A）。
  - 「容器本身已修好玻璃，但巢狀子層未同步」的情形（如 `.ss-status__icon`／`.review-status__note`／`.vault-door__keychip`）歸 A，視為同一輪換裝的漏網之魚。
  - 舊有「輸入框／可互動填色面用 --input-surface 比卡亮一階」（Q19／Q67 系列，多在 2026-07 中旬裁決、早於 2026-08-28 玻璃化）與新玻璃語彙有明顯張力、且找不到 ztorUI 期重新確認的，一律歸 C，不代 AI 選邊。
- **消費頁查法**：對 A／C 類的主要 class 名稱，在 `site/r2.3/*.html`、`partials/*.js`、`js/*.js` 三處 grep，最多列 5 個檔名＋總數；B 類不列消費頁（依規格書要求）。
