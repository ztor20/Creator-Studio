面板內的列 Hover（設計探索）

母子列展開已裁定用 L3 整組換層：展開時母列與子項一起包進一塊 --ztu-film 薄膜面板。面板裡的列目前繼承站上通用的列 hover（浮起成一張玻璃卡），但那組樣式是為「列坐在實色卡面上」設計的，疊到薄膜面板上會打架。這是一張比較用的探索頁，不是產品頁，沒有任何既有頁面被改動。

現況的三個矛盾

  1. 方向反了：hover 的填色（5% 白）比它坐的面板底（8.6% 白）還暗，讀起來是往下沉，不是浮起。
  2. 模糊沒有意義：backdrop-filter 在面板內只會取樣到面板自己，讀不出層次，還多耗 GPU。
  3. 語意打架：一列「浮出」面板，跟「這一組是同一個平面」互相矛盾。
基準

現況 · 浮玻璃卡

站上目前的通用列 hover，供對照——上面三個矛盾就是從這組樣式來的。

  • 已經在用，眼熟，零學習成本

H1

提亮一階

hover 只把該列底色在面板之上再提亮一階（--ztu-glass-strong），不浮起、不模糊、不加陰影——同一平面上的暫時強調。

母列 / 子列強度：母列與子列用同一階提亮。提亮的效果本身很輕，若要強調母列「可點開整組」，可以考慮母列再提亮半階、子列維持這一階，但本候選示範刻意先給同一種力度，看基本語彙成不成立。

優點

  • 一步解掉三個矛盾：不模糊、不浮起、方向對（比 8.6% 的面板底亮，讀起來對）
  • 母列子列吃同一條規則，維護成本低

代價

  • 面板外的一般列若也套同一招，會跟 e-shop 玻璃卡的既有語彙不一致，得決定這招只用在面板內、還是全站換
  • 亮度差是唯一線索，字多、掃得快的現場（取貨台）可能不夠抓眼
H2

左緣光條

底色不變，列的左緣出現一條 2px 指示條（--primary）——平面感完全不動，只加一個位置固定的線索。

母列 / 子列強度：光條的粗細與顏色在母列子列上完全一致。若要分強度，比較合理的做法是母列用實心 --primary、子列降不透明度，但本候選示範刻意先給同一種力度看基本語彙成不成立。

優點

  • 完全不動底色與陰影，零回歸風險，跟面板語彙零衝突
  • 視覺重量最輕，不會搶過內容本身

代價

  • 光條顏色用 --primary（橘），跟「待核銷」badge--warning 的橘系相近，可能被誤讀成「這一列有狀態變化」
  • 面板外單獨出現時，一條橘色豎線的意圖不夠直覺，沒有上下文不容易猜到是 hover
H3

母列 / 子列強度：內框粗細一致。母列因為整列可點，理論上可以疊加更亮的 --primary 邊而不是中性 --border，但那樣會跟「待核銷／已核銷」badge 的橘色系混淆，所以本候選先給中性、同強度的版本。

優點

  • 跟面板自己的邊同語彙（都是 inset 1px 框），層級感一致、最不違和
  • 面板外單獨出現也讀得通，是常見的「這一列被選中了」語言

代價

  • 面板內已經有一圈外框，列內再來一圈內框，兩圈框疊在一起可能分不清哪個是哪個的邊界
  • 對比強度偏弱，光線暗的環境下可能要湊近看才發現

母列 / 子列強度：母列的標題本來就是全墨色 --foreground（不是 muted），提字這招在母列上幾乎沒有視覺效果；子列才會有明顯的「變亮」。這正好對應母列可點、子列只讓動作選單浮現的差異——是本候選裡強度天生就不同的一個，不是刻意設計。

  • 變化幅度小，滑鼠移動快的情況可能感知不到「這一列被選中了」
  • 母列幾乎沒有效果，跟子列的 hover 觀感不一致（見上方強度說明）

只有可操作的東西有 hover

整列不反應，只有列內可點的元素（來源連結、動作選單按鈕）各自 hover——最保守的一種。領取碼目前不是可點元素，維持純文字。

母列 / 子列強度：母列（可點開整組）與子列（不可點）在這個候選下都不給整行 hover。理論上母列該有一個「可以點開」的暗示，但本候選刻意保持「只有明確可操作的元素才有 hover」這條規則不打折——兩者視覺上沒有差異，只靠游標變成手指這一個信號分辨。

優點

  • 最誠實：不可點的列不給「看起來能點」的錯誤暗示
  • 幾乎不需要新增列級樣式，維護成本最低

代價

  • 母列整列其實可點開整組，卻沒有整列 hover 提示，容易讓人以為只有連結和按鈕能點
  • 視覺上跟其他候選相比幾乎沒有「探索性」新意，改動最小也最不顯眼

怎麼挑

  1. 面板內外是否都成立：面板裡好看的招，擺到面板外的一般列會不會變醜、變得不知所云？六個候選都各擺了一份對照。
  2. 可點與不可點的列要不要不同強度：母列整列可點、子列不可點只有選單可點——這個語意差異，hover 強度該不該跟著分？每張候選卡下面都有一段話講這件事在該候選下的結果。
  3. 與站上其他清單的一致性成本：挑定的招如果只用在展開面板內，其餘所有列表（e-shop、orders 等）維持現況玻璃卡，会不会讓站上同時存在兩套 hover 語言？如果要全站統一換，換血範圍多大？

三個判準會互相牽制——面板內外都成立的招通常最安靜，能分強度的招通常要多寫一條規則。挑的時候先決定哪一項優先。
